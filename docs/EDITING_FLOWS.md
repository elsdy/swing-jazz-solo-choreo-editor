# 편집 흐름 — 사람이 실제로 채우는 순서

이 도구로 안무표를 채우는 길이 몇 가지인지 전부 적고, 그중 무엇이 지금 막혀 있는지, 어떻게 열 것인지를 적는다.
[기능 설명서](FEATURES.md)가 "그 버튼이 무슨 일을 하나"라면 이 문서는 **"무엇부터 어떻게 하나"** 다.
계획 부분은 아직 만들지 않은 것이므로, 지금 되는 것과 섞이지 않게 표마다 표시해 두었다.

## 방향은 둘뿐이다

```
   표를 먼저 적는다                      영상을 먼저 본다
   ┌───────────┐                        ┌───────────┐
   │  동작 목록 │                        │    영상    │
   └─────┬─────┘                        └─────┬─────┘
         │ 끌어다 놓기                         │ 보면서 적는다
         ▼                                    ▼
   ┌───────────┐     박자 맞추기         ┌───────────┐
   │   안무표   │ ◀──────────────────▶   │   안무표   │
   └───────────┘                         └───────────┘

     A1~A5 · E1~E3                        B · C · D
      지금 잘 된다                         지금 막힌다
```

아래 스무 개 시나리오는 전부 이 둘 중 하나다. 도구는 왼쪽 길만 제대로 되어 있다.

## 시나리오 전부

### A. 영상 없이 시작 (머리·메모)

| | 무엇을 하나 | 지금 |
| --- | --- | --- |
| A1 | 내가 짠 안무를 적어 둔다 | 된다 |
| A2 | 수업에서 배운 것을 기억나는 대로 적는다 | 된다 |
| A3 | 말로 불러 초안을 만들고 손으로 고친다 | 된다 |
| A4 | 남의 안무표 파일을 받아 내 것과 합친다 | 된다 |
| A5 | 기존 안무를 변형해 새 판본을 만든다 | 파일을 따로 저장하는 수밖에 없다 |

### B. 남의 영상에서 시작 (유튜브 강습·공연)

| | 무엇을 하나 | 지금 |
| --- | --- | --- |
| B1 | 강습 영상을 보며 받아 적는다 | **막힌다** — 영상에서 표로 가는 길이 없다 |
| B2 | 공연에서 마음에 드는 대목만 뽑는다 | 마커로 표시만 된다. 블록이 안 생긴다 |
| B3 | 곡 구조부터 훑고 안을 채운다 | **막힌다** — 마디 위의 묶음이 없다 |
| B4 | 배속을 낮춰 한 마디씩 뜯는다 | 배속은 되는데 받아 적는 길이 없다 |

### C. 내 촬영본에서 시작

| | 무엇을 하나 | 지금 |
| --- | --- | --- |
| C1 | 연습 녹화에서 안무 구간만 잘라 보관한다 | 된다 |
| C2 | 내가 춘 것을 보며 받아 적는다 | B1 과 같이 막힌다 |
| C3 | 같은 안무를 여러 번 찍어 나아짐을 본다 | **없다** — 테이크 개념이 없다 |
| C4 | 관절 가동 범위를 재서 남긴다 | 계산은 되는데 화면에 안 나온다 |

### D. 가르치기·나누기

| | 무엇을 하나 | 지금 |
| --- | --- | --- |
| D1 | 구간별 클립과 이름으로 수업 순서를 만든다 | 자르기와 마커로 반쯤 된다 |
| D2 | 학생에게 줄 안무표를 만든다 | 된다 |
| D3 | 리드와 팔로우를 따로 기록한다 | **없다** — 한 사람 기준의 표 하나뿐이다 |

### E. 오래 쓰기

| | 무엇을 하나 | 지금 |
| --- | --- | --- |
| E1 | 곡 하나를 여러 판본으로 관리한다 | 파일을 나누는 수밖에 없다 |
| E2 | 자주 쓰는 묶음을 루틴으로 쌓는다 | 된다 |
| E3 | 동작 이름과 카테고리 체계를 정돈한다 | 된다 |

## 순서가 뒤집혀 있다

영상을 보며 적을 때 사람이 밟는 순서와, 도구가 요구하는 순서가 반대다.

```
   사람이 하는 순서                   도구가 요구하는 순서
   ─────────────────                 ───────────────────
   ① 여기가 어디인가  (파트)            ① 동작 이름을 정한다
   ② 무슨 일이 일어나나 (구간)          ② 동작 목록에 등록한다
   ③ 그게 뭐지        (이름)           ③ 카드를 끌어다 놓는다
   ④ 무슨 갈래지      (카테고리)        ④ 길이를 맞춘다
   ⑤ 얼마나 잘하나    (자세)

     이름이 맨 나중이다                 이름이 맨 처음이다
                    └──── 여기가 어긋난다 ────┘
```

영상을 보다가 "어 지금 뭔가 했다"를 적으려면, 지금은 그것이 **무엇인지 먼저 정해야** 한다.
블록을 놓는 유일한 길인 `placeMoveAt` 이 동작 목록에 이미 있는 id 를 요구하기 때문이다.
그래서 받아 적기가 "보다 → 멈추다 → 이름 짓다 → 등록하다 → 놓다 → 다시 보다"가 되고, 흐름이 매번 끊긴다.

## 막히는 곳 다섯

```
   영상 ──▶ 재생 위치 ──╳──▶ 카운트에 블록        ① 놓을 길이 없다
                        1

   (자리) ──╳──▶ 이름 없는 블록                   ② 이름이 있어야만 놓인다
            2

   마커 ──╳──▶ 블록                              ③ 다리가 없다
          3

   (없음) ──╳──▶ 파트                            ④ 마디 위가 비어 있다
            4

   자세 ──▶ 가동 범위 ──╳──▶ 화면                 ⑤ 계산만 있고 출구가 없다
                        5
```

1. **재생 위치에서 바로 블록을 놓을 수 없다.** 세로선 위치를 눈으로 보고 격자를 손으로 쓸어야 한다.
2. **이름 없이 자리를 잡을 수 없다.** 배치는 언제나 동작 목록의 한 항목을 가리킨다.
3. **마커가 블록이 되지 않는다.** 영상 구간과 카운트 구간을 이어 두었는데 표에는 아무것도 안 생긴다.
4. **마디 위의 묶음이 없다.** A파트·브레이크 같은 곡 구조를 담을 자리가 저장 포맷에 없다.
5. **잰 가동 범위가 화면에 안 나온다.** `domain/rom.js` 가 다 계산해 두는데 그리는 곳이 없다.

## 계획 — 네 단계

앞이 뒤의 전제라 순서를 바꾸기 어렵다. 단계마다 **어느 시나리오가 열리는지**로 값을 잰다.

| 단계 | 하는 일 | 여는 시나리오 | 막는 곳 |
| --- | --- | --- | --- |
| 1 | 영상에서 표로 가는 다리 | B1 · B2 · C2 | 1 · 2 · 3 |
| 2 | 나중에 이름 붙이기 | B1 · B4 를 빠르게 | 2 |
| 3 | 파트 | B3 · D1 | 4 |
| 4 | 기록과 비교 | C3 · C4 · D1 | 5 |

### 1단계 — 받아 적기

영상을 보면서 동작이 시작될 때 한 번, 끝날 때 한 번 누르면 그 구간이 **이름 없는 블록**으로 표에 바로 놓인다.
초를 카운트로 바꾸는 것은 이미 있는 박자 설정이 한다.

```
   영상 재생 ──────────────────────────────────▶ 시간
              │        │       │        │
              ●        ●       ●        ●        ← 같은 키를 번갈아
             시작      끝     시작      끝
              └────────┘       └────────┘
                   │                │
                   ▼                ▼
   안무표   8x1 ┌──────────┐ ┌──────────┐
               │    ?     │ │    ?     │         ← 이름 없는 블록
               └──────────┘ └──────────┘
```

- 도메인이 이름 없는 배치를 허용하게 넓힌다. 지금은 `name` 이 필수다.
- 이미 찍어 둔 마커를 블록으로 바꾸는 버튼을 단다. 그동안 모은 것이 살아난다.
- 키 하나로 되게 한다. 영상에서 눈을 떼면 흐름이 끊긴다.

### 2단계 — 나중에 이름 붙이기

이름 없는 블록만 모아 한 곳에서 채운다. 같은 모양이 되풀이되면 "아까 그것"으로 묶어 한 번에 단다.
이때 동작 목록에 없던 이름은 그 자리에서 동작과 카테고리로 등록된다 — 3번과 4번이 2번 **뒤로** 간다.

```
   이름 없는 블록 4개          →     한 곳에서 이름 붙이기
   ┌───┐ ┌───┐ ┌───┐ ┌───┐          8x1·1  [        ] 갈래 [▾]
   │ ? │ │ ? │ │ ? │ │ ? │          8x2·1  [        ] 갈래 [▾]
   └───┘ └───┘ └───┘ └───┘          8x3·1  ↑ 와 같음
                                     8x4·5  [        ] 갈래 [▾]
```

### 3단계 — 파트

마디 위에 묶음을 하나 둔다. 영상에서 큰 덩어리를 먼저 긋고 이름을 붙인 뒤 그 안을 1·2단계로 채운다.
이것이 탑다운의 맨 윗단이다.

```
   곡
   ├─ A파트      8x1 ~ 8x8
   │    ├─ 8x1   [ 찰스턴 8                    ]
   │    └─ 8x2   [ 킥볼체인지 2 ][ 스텝 6       ]
   ├─ 브레이크    8x9
   └─ B파트      8x10 ~ 8x17
        └─ …
```

파트는 접히고, 통째로 옮기거나 되풀이할 수 있어야 한다.

### 4단계 — 기록과 비교

테이크를 도입해 같은 동작의 여러 촬영본을 시간순으로 세우고, 이미 계산되는 가동 범위를 거기에 붙인다.
지난주와 오늘을 나란히 놓는 것이 목적이다.

```
   찰스턴
   ├─ 9/01 테이크  무릎 가동 범위 42°  ●●●○○
   ├─ 9/08 테이크  무릎 가동 범위 51°  ●●●●○   +9°
   └─ 9/12 테이크  무릎 가동 범위 58°  ●●●●●   +7°
```

## 시작하기 전에 정할 것

1. **이름 없는 블록을 화면에서 어떻게 보일까.** 점선 테두리에 `?` 를 생각하고 있다. 저장 파일에도 그대로 들어가야 하므로 스키마가 한 번 늘어난다.
2. **파트를 어디에 저장할까.** 지금 포맷에 없는 개념이다. 마커와 합칠지 따로 둘지가 갈림길이다 — 마커는 영상 구간에 붙고 파트는 카운트 구간에 붙는다는 점이 다르다.
3. **받아 적기의 조작.** 시작과 끝을 번갈아 누를지, 누르고 있는 동안을 한 블록으로 볼지. 실제로 영상을 보며 해 봐야 안다.

1단계만 해도 막혀 있던 시나리오 셋이 열린다. 거기부터 시작하는 것을 권한다.

전체 일정과 다른 갈래의 작업은 [로드맵](ROADMAP.md)에 있다.
