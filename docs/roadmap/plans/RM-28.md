# RM-28 설치형 앱으로 포장

## 풀어 본 설명 — 2026-09-29

지금은 터미널에서 python3 server.py 를 켜고 브라우저로 localhost 를 열어야 쓸 수 있다. 이 과정을 맥·윈도우에서 두 번 눌러 켜는 앱 하나로 싸서, 파이썬이나 ffmpeg 를 따로 깔 줄 모르는 사람도 영상 보관·자르기·자세 분석까지 그대로 쓰게 한다. 방향은 「설치형·로컬 우선」으로 이미 정했다(Q1). 다만 처음 켠 사람이 10분 안에 쓸 수 있게 하는 일(RM-26)이 먼저라서 차례를 기다린다.

### 무엇

맥에서는 .app(.dmg), 윈도우에서는 설치 파일 하나를 받아 두 번 누르면 켜지는 앱이다. 앱 안에는 지금의 앱 파일(index.html 과 src/ 의 ES 모듈)과 server.py, 파이썬 실행 환경, ffmpeg 가 모두 들어 있다. 켜면 뒤에서 서버가 빈 포트를 잡아 뜨고, 안무표 화면이 창으로 열린다. 포트가 이미 쓰이고 있으면 조용히 죽지 않고 알린다. 영상·안무표·설정·모델은 지금처럼 앱 밖의 데이터·설정·캐시 폴더에 쌓이므로, 앱을 지우거나 새 판으로 바꿔도 사용자의 것은 남는다. 자르기(ffmpeg)가 처음부터 켜져 있어 「자르기: 꺼짐」이 사라진다. 앱 코드 자체는 바뀌지 않는다. 포장은 그 둘레에 두르는 껍데기다.

### 왜

지금 이 도구의 좋은 점(영상 보관, 구간 자르기, LLM 중계, 자세 모델 보관)은 전부 server.py 에 기대는데, 그것을 쓰려면 터미널을 열고 파이썬 명령을 치고 ffmpeg 를 따로 깔아야 한다. 댄서나 강사에게는 이 단계가 곧 문 앞에서 멈추는 자리다. 서버 없이 정적 파일로 열면 앱은 뜨지만 반쪽이 된다. 호스팅 웹앱으로 가면 영상이 컴퓨터 밖으로 나가고 계정·결제·저장 서버를 새로 지어야 한다. 그래서 「내 컴퓨터에서 도는 앱 하나」가 로컬 우선이라는 정체성을 지키면서 문턱을 없애는 길이라고 정했다(Q1, 계정 없는 1회 구매가 기본). 로드맵 이정표 M3(남에게 준다)의 「설치형 앱 첫 판」이 이 항목이다.

### 어떻게

- 먼저 결정 기록과 CLAUDE.md 의 「빌드 도구·의존성 없음」을 「저장소의 앱 코드에만」으로 좁혀 다시 적는다. 포장 단계에서만 도구를 허용하고, 앱은 지금처럼 브라우저가 그대로 읽는 ES 모듈로 둔다.
- 포장에 쓰는 스크립트와 설정은 저장소 안의 따로 떨어진 폴더(예: packaging/)에 둔다. src/ 와 server.py 는 그 폴더를 모르게 한다.
- 파이썬은 사용자 기계에 있다고 가정하지 않는다. server.py 를 PyInstaller 같은 도구로 얼린 실행 파일로 싣거나, 독립형 파이썬 런타임을 함께 싣는다. 표준 라이브러리만 쓰므로 얼리기가 쉽다.
- server.py 에 포장된 채로 돌 때 필요한 것만 더한다. 빈 포트 고르기(포트 0), 켜지면 창이나 브라우저 열기(--open), 포트가 쓰이면 물러나며 알리기, 정적 파일 뿌리를 저장소 자리 대신 앱 묶음 안의 자리로 받기.
- ffmpeg 는 앱 안에 함께 싣고 --ffmpeg 로 그 경로를 넘긴다. 지금 찾는 차례(--ffmpeg → CHOREO_FFMPEG → PATH)는 이미 이것을 받게 되어 있다.
- 윈도우의 보관 자리를 고친다. 지금은 윈도우가 리눅스 쪽(홈 아래 점폴더)으로 떨어지므로 %APPDATA% · %LOCALAPPDATA% 관례로 맞춘다. 저장소 안의 옛 자리를 살피는 코드는 포장된 앱에서는 돌지 않게 한다.
- 맥은 서명과 공증, 윈도우는 서명(또는 첫 실행 경고 안내)을 거쳐 .dmg 와 설치 파일을 만든다. 두 OS 에서 켜기 → 영상 넣기 → 자르기 → 저장·다시 열기를 손으로 한 바퀴 돌린다.
- README · 튜토리얼의 「실행」 절을 「앱 받기」 중심으로 고쳐 쓰고, RM-27 의 지원 표에 「설치형」 열을 더한다.

### 갈리는 대목

- 앱 화면을 어디에 띄울까
  - 앱 안의 창(Tauri 같은 내장 웹뷰) — 진짜 앱처럼 보이고 독(Dock)·작업 표시줄에 제 이름으로 선다. 대신 맥은 사파리 엔진, 윈도우는 엣지 엔진이라 크롬에서만 시험한 동작(자세 분석 WASM, 영상 재생, 파일 끌어 넣기)이 달라질 수 있어 RM-27 의 표가 한 줄 늘고, 포장 도구(Rust 등)가 무거워진다.
  - 작은 런처 + 사용자의 기본 브라우저 — 메뉴 막대나 트레이에 아이콘만 두고 서버를 켠 뒤 평소 쓰는 브라우저를 연다. 지금 쓰는 모습과 같아 시험한 그대로 돌고 포장이 가볍다. 대신 탭을 닫아도 서버가 남아 있어 「앱을 껐다」는 감각이 흐리고, 사용자가 쓰는 브라우저마다 결과가 갈린다.
- 함께 싣는 ffmpeg 의 라이선스
  - GPL 빌드를 싣고 앱도 GPL 로 맞춘다 — 지금의 자르기 설정(libx264)을 그대로 쓴다. 대신 1회 구매로 파는 앱의 소스를 공개해야 하는 조건이 따라오고, 라이선스 결정(Q2)과 LICENSE 와 README 가 서로 다른 말을 하는 문제를 먼저 풀어야 한다.
  - LGPL 빌드를 싣고 인코더를 바꾼다 — 앱의 라이선스를 자유롭게 둘 수 있다. 대신 자르기 인코더를 OS 하드웨어 인코더(맥 VideoToolbox, 윈도우 Media Foundation)나 openh264 로 바꿔야 해서, 화질·속도와 서버 시험의 기대값이 달라진다.
- 첫 판에 서명·공증을 할까
  - 서명한다(맥 개발자 등록 + 윈도우 코드 서명 인증서) — 받아서 두 번 누르면 그냥 켜진다. 대신 해마다 비용이 들고, 공증을 기다리는 단계가 빌드에 붙는다.
  - 첫 판은 서명 없이, 경고 넘기는 법을 안내한다 — 돈 없이 빨리 몇 사람에게 줄 수 있다. 대신 「확인되지 않은 개발자」 경고에서 멈추는 사람이 생긴다. 문턱을 없애려는 이 항목의 목적과 반대라서, 다섯 명 10분 검증(M3) 전에는 결국 서명해야 한다.

### 조심할 것

- 포트가 바뀌면 브라우저가 다른 출처로 본다. localStorage 에 둔 최근 목록·초안이 켤 때마다 사라진 것처럼 보일 수 있다. 빈 포트를 고르더라도 한 번 잡은 포트를 기억해 다시 쓰거나, 그런 상태가 서버 쪽에 있게 해야 한다(RM-33 과 닿는다).
- 보관 자리는 앱 묶음 밖이어야 한다. 앱을 업데이트하거나 지울 때 안무표와 영상이 함께 날아가면 안 된다. 옛 저장소 자리를 살피는 코드가 앱 묶음 안을 「옛 자리」로 잘못 읽지 않게 한다.
- LLM 키는 설정 폴더에만 두고 앱 묶음이나 데이터 폴더에 섞이지 않게 한다. 지금 데이터와 설정을 가른 까닭이 포장에서 무너지지 않게 한다.
- 폰 접속(같은 와이파이, QR)은 서버를 127.0.0.1 밖으로 여는 일이고 지금 서버에는 인증이 없다. 이 항목에 끼워 넣지 말고, 인증을 정한 뒤 따로 다룬다.
- server.py 와 앱의 계약(경로 규칙, 안무표 스키마)이 두 곳에 적혀 있는 것은 포장해도 그대로다. 포장 스크립트가 어느 한쪽의 사본을 따로 만들지 않게 한다.
- 자세 분석 모델은 지금처럼 처음 쓸 때 받게 둘지, 앱에 넣을지에 따라 설치본 크기가 수십 MB 달라진다. 예제 영상(RM-26 의 갈림)도 마찬가지다.
