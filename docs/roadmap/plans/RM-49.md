# RM-49 판이 더한 from-factoriel 트랙에 plan 이 없어 로드맵 시험이 TypeError 로 붉음

보드는 출처 트랙 from-factoriel 을 plan 없이 설명(what)만 달아 판에 더한다(factoriel SCHEMA 가 정한 꼴, B899). 그런데 roadmapFile 시험의 앵커 대조는 모든 트랙에 plan 이 있다고 보고 t.plan.split 을 불러 TypeError 로 던진다. 그래서 판 변경 올리기가 푸시 훅에 막힌다. 그러니 RM-40 의 described 규칙처럼 「원본이 실제로 남기는 꼴」을 받도록 고친다 — plan 이 있는 트랙은 앵커를 재고, plan 이 없으면 설명이 있을 때만 통과시킨다.

크기 S · 2026-11-03 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 보드가 본 트리 로드맵 파일에 트랙 from-factoriel(🏭 factoriel 에서 올라온 버그, B899)을 plan 없이 더했고, tests/unit/roadmapFile.test.mjs:191 「트랙이 가리키는 문서 앵커가 문서 뷰어에서 실제로 걸린다」가 t.plan.split 에서 TypeError 로 붉다(단위 607 중 1). HEAD 의 판으로는 초록, 보드가 쓴 판으로 바꾸면 붉음을 사본에서 재현했다(2026-11-03, RM-14 마무리 중). 이대로면 판 변경 올리기가 푸시 훅에 막힌다. RM-40 과 같은 부류 — 원본(판)이 남기는 꼴(plan 없는 출처 트랙)을 시험이 받아 주거나, 엔진이 출처 트랙에 plan 을 달거나.

## 요구

- plan 이 없는 트랙이라도 비지 않은 설명(what)이 있으면, 앵커 시험이 던지지 않고 그 트랙의 앵커는 재지 않는다. plan 도 설명도 없는 트랙은 「plan 도 설명도 없다」는 글로 붉다
- plan 이 있는 트랙의 앵커가 문서 뷰어에 없으면 지금처럼 붉다. 앵커 대조는 순수 함수(트랙 목록과 앵커 집합 → 어긋남 글 목록)로 떼어 견본으로 잰다
- 지금 판(from-factoriel 트랙이 plan 없이 RM-43~RM-52 를 담은 상태)으로 roadmapFile 시험 파일 전체가 초록이다
- 문서 세 곳에 새 조건과 이번 버그를 적는다: ROADMAP.md 「판 파일이 원본이다」 문단, PRINCIPLES.md 의 RM-40 원칙 근거, BUG_REPORTS.md 버그 기록. 개발 지침의 단위 시험 수도 맞춘다

## 순서

- 작업 사본의 판(from-factoriel 트랙 포함)으로 node --test tests/unit/roadmapFile.test.mjs 를 돌린다. 붉은 것이 앵커 시험의 TypeError(reading 'split') 하나뿐인지 재현으로 확인하고, HEAD 의 판으로는 초록인지도 함께 잰다
- described 옆에 trackAnchorMismatches({ tracks, anchors }) 를 둔다. plan 이 있으면 앵커를 재고, 없으면 what 이 비지 않을 때만 통과시키며, 어긋남 글 목록을 돌려준다. 복잡도 표지도 단다
- 실제 앵커 시험은 이 함수의 결과가 빈 배열인지로 assert 하게 바꾸고 [RM-49 요구 2] 표지를 단다
- 견본 시험 [RM-49 요구 0] 을 새로 쓴다(what 만 · 빈 what · 공백 what · plan 앵커 없음 · plan 앵커 있음)
- node --test tests/unit/roadmapFile.test.mjs 로 같은 재현이 이제 초록인지 다시 잰다
- ROADMAP.md 「판 파일이 원본이다」 문단, PRINCIPLES.md 의 RM-40 원칙 근거, BUG_REPORTS.md 에 이번 일을 적는다. CLAUDE.md 의 단위 시험 수(614 → 615)를 고치고 node tools/check-docs.mjs 로 링크를 확인한다
- 작업 사본의 ROADMAP.json 판 변경(from-factoriel 트랙)이 origin/main 에 아직 없으면 이 브랜치에 함께 싣는다. 시험 고침 없이는 그 판 커밋이 main 에 못 들어간다

## 조심할 것

- plan 없는 트랙을 아무 조건 없이 건너뛰면, 이름만 있는 빈 트랙이나 plan 을 빠뜨린 사람 손 트랙도 조용히 통과한다. 그래서 what 을 요구해 RM-40 의 described 와 같은 문턱으로 맞춘다
- LANE 표는 다음 · 그다음 · 나중 셋뿐이다. from-factoriel 항목을 문서 추적 표에 옮겨 적으면 칸이 undefined 로 읽혀 「칸」 어긋남으로 붉을 수 있다. 이번 일은 판에만 두는 지금 꼴을 유지하고, 문서로 옮기는 일은 사람이 고를 때 따로 한다
- 작업 사본의 ROADMAP.json · BUG_REPORTS.md · PRINCIPLES.md 가 이미 고쳐진 상태다. 그 변경이 누구의 것인지 보고 이 브랜치에 실을지 가린다 — 다른 항목의 변경을 덮지 않는다
- 엔진 판에 올릴 일: 보드가 출처 트랙을 더할 때 plan(문서 앵커)을 함께 다는 길은 factoriel SCHEMA 를 바꾸는 엔진 쪽 일이다. 이 항목에서는 시험이 판의 꼴을 받는 쪽으로만 고친다
