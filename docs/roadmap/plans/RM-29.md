# RM-29 ★ 판본과 연습 기록 — 이름 붙인 판본·테이크별 기록

한 안무 파일 안에 이름 붙인 판본(A안·공연본)을 떠 두고, 날짜·구간·속도·시도·별점·걸린 자리·메모를 적는 연습 기록을 쌓아 영상 목록 곁에서 시간 순으로 보게 한다. 스키마와 계약에 자리만 적혀 있고 아무도 쓰지 않는 판본과 기록을 실제로 배선하는 일이다. 겹치는 항목: RM-22(구간·배속 표기와 「이번 연습 기록하기」 이음매), RM-25(서버 안전망 판, 판본을 열기 전 지금 본문을 지키는 일), RM-30(기록 줄에 잰 값 한 칸), RM-33(정적 경로 저장 쿼터), RM-35(스냅샷 크기).

크기 L · 2026-10-01 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 한 안무를 A안·B안·공연본처럼 이름 붙인 판본으로 갈라 두고, 연습할 때마다 날짜·속도·메모·잘 된 정도를 한 줄씩 적는 기록을 붙인다. 지금은 변형을 만들려면 파일을 따로 저장해야 하고, 영상 목록의 날짜·메모 말고는 연습을 남길 자리가 없다. 「이 안무가 어떻게 바뀌었고 내가 얼마나 나아졌나」를 한 파일 안에서 시간 순으로 보려는 항목이다.

## 요구

- 지금 안무표를 이름·메모를 붙인 판본으로 떠 둔다. 어느 판에서 갈라져 나왔는지(부모)를 함께 적고, 사람이 지우기 전에는 밀려나거나 사라지지 않는다
- 판본 목록에는 본문을 펼치지 않고 요약(이름·뜬 날·마디 수·부모·메모)만 보인다. 요약은 본문에서 언제든 다시 만들 수 있다
- 판본을 열면 그 판의 안무표가 지금 안무표가 된다. 선택과 되돌리기는 전체 불러오기처럼 비고, 다른 판본과 기록은 그대로 남는다. 지금 본문이 어느 판본과도 같지 않으면 그냥 버리지 않는다
- 판본 이름을 바꾸고 지울 수 있다(지우기는 confirmOnce). 지워도 자식 판본의 부모와 기록의 판본 표시가 남아 있을 뿐 화면이 깨지지 않는다
- 연습 기록 한 줄을 적고·고치고·지운다. 칸은 날짜, 판본, 구간(마디·카운트 좌표, 표기는 연습기·마커와 같은 「8x3~8x4」), BPM 또는 배속, 시도 수/깨끗한 수, 별점, 걸린 자리, 메모다. 영상은 없어도 되고, 있으면 영상 목록의 항목 id 로 가리킨다
- 영상 목록 줄에서 「이 테이크 기록」으로 들어가면 그 영상과 찍은 날이 채워진 기록이 열린다
- 판본과 기록이 파일 저장→다시 열기, 최근 목록 열기, 작업 문서(초안) 되살리기에서 모두 살아남는다
- 판본과 기록을 안 쓴 사람의 저장 파일은 바이트가 한 글자도 늘지 않는다(비면 키째 뺀다)
- 판본과 기록은 되돌리기 스냅샷에 들지 않는다
- 파일 최상위 media(빈 참조 목록)와 안무 안 media(영상 목록)의 이름 겹침을 정리하고, v1→v2 마이그레이션이 파일에 든 판본·기록을 빈 배열로 덮어쓰지 않게 한다
- 판본이 든 파일을 옛 앱이 열었다가 다시 저장해서 판본이 조용히 사라지는 일이 없다
- 새 라벨을 기능 설명서·튜토리얼·포트 문서의 프로젝트·영상 목록 대목에 반영한다

## 결정 사항

- 판본을 어디에 두나
  - 안무 파일 안에 함께 둔다(추천) — 파일 하나만 옮기면 판본과 기록이 다 따라가고 서버 없이도 된다. 서버 쪽 손댈 것이 없어 RM-25 를 기다리지 않는다. 대신 판본 수만큼 파일이 커지고, 정적 경로의 최근 목록(localStorage)은 쿼터가 금방 차므로 RM-33 이 먼저면 낫다
  - 서버 보관 폴더에 따로 둔다 — 안무 파일은 가볍게 남고 .history API 를 이어 쓴다. 대신 서버 없이는 판본이 없고, 남에게 준 파일에는 판본이 따라가지 않는다. server.py·projectServer·서버 시험이 늘고 RM-25 가 선행이 된다
  - **고른 답**: 안무 파일 안에 함께 둔다(추천)
- 판본마다 영상을 따로 두나
  - 영상은 안무 공통, 판본은 안무표만 뜬다(추천) — 가장 작다. 영상 목록·박자·마커가 그대로이고, 기록이 판본과 테이크를 둘 다 가리켜 잇는다. B안 영상이 A안 목록에도 보인다
  - 판본마다 기준 영상을 가진다 — 판본을 고르면 영상도 갈아탄다. 영상 블록의 주인이 바뀌어 저장 포맷과 되돌리기 범위가 크게 움직이고, 크기가 L 을 넘는다
  - 고른 답: 아직 — 판의 결정 사항으로 남아 이 항목을 막는다
- 판본이 든 파일의 쓰기 버전
  - 판본·기록이 있을 때만 version 2 로 쓴다(추천) — 판본을 안 쓴 사람의 파일 바이트는 그대로다. 폰에 캐시된 옛 앱은 미래 스키마로 보고 거절해 판본을 지우지 않는다. 대신 쓰는 모양이 둘(v1 평평 · v2 doc 묶음)이 된다
  - 늘 version 1 로 쓰고 최상위 키만 더한다 — 쓰는 모양이 하나로 남는다. 다만 옛 앱이 열고 저장하면 마이그레이션이 판본을 빈 배열로 덮어 조용히 사라진다
  - **고른 답**: 판본·기록이 있을 때만 version 2 로 쓴다(추천)

## 조심할 것

- 지금 v1→v2 마이그레이션은 versions·practiceLogs 를 늘 빈 배열로 덮고, saveProject·draftSnapshot 은 passthrough 없이 쓴다. 두 길을 다 고치지 않으면 판본이 저장에서 조용히 샌다. 필드 등록표 밖이라 docFields 왕복 시험이 잡아 주지 않는다
- 판본 열기는 전체 불러오기라, 자동 담기가 1.2초 뒤 지금 파일 본문을 그 판으로 덮는다. 열기 전 확인과 서버 .history 가 지금 본문을 지키는지 시험으로 잰다
- 판본을 되돌리기 스냅샷에 넣으면 동작 하나마다 판본 전부가 문자열화된다(RM-35 의 걱정). 판본 지우기처럼 되돌릴 수 없는 일은 confirmOnce 로 묻는다
- 최상위 media 이름을 바꾸는 구조 커밋과, 쓰기 포맷을 바꾸는 동작 커밋을 섞지 않는다
- 정적 경로에서는 최근 목록이 파일 10개를 통째로 localStorage 에 넣는다. 판본이 든 파일은 쿼터를 금방 채우니 실패를 RM-04 의 알림으로 드러낸다
- 구간·배속의 표기와 저장 자리가 RM-22(연습 구간 목록 저장 갈림)와 겹친다. 그쪽이 「저장하지 않는다」를 고르면 이 항목이 유일한 주인이 된다

## 다시 다듬기 전의 계획서

### RM-29 ★ 판본과 연습 기록 — 이름 붙인 판본·테이크별 기록

#### 풀어 본 설명 — 2026-09-29

한 안무를 A안·B안·공연본처럼 이름 붙인 판본으로 갈라 두고, 연습할 때마다 날짜·속도·메모·잘 된 정도를 한 줄씩 적는 기록을 붙인다. 지금은 변형을 만들려면 파일을 따로 저장해야 하고, 영상 목록의 날짜·메모 말고는 연습을 남길 자리가 없다. 「이 안무가 어떻게 바뀌었고 내가 얼마나 나아졌나」를 한 파일 안에서 시간 순으로 보려는 항목이다.

##### 무엇

화면에 두 가지가 생긴다. 하나는 판본 목록이다. 지금 안무표를 「A안」「공연본」처럼 이름 붙여 한 장 떠 둔다. 목록에서 판본을 고르면 그 판으로 열고, 어느 판에서 갈라져 나왔는지(부모)와 메모도 함께 보인다. 판은 서버가 저장할 때마다 알아서 남기는 안전망 판(RM-25)과 달리 사람이 일부러 남기는 것이라 지워지거나 밀려나지 않는다. 다른 하나는 연습 기록이다. 연습한 날마다 한 줄씩 쌓인다. 줄에는 날짜, 어느 판본을 연습했는지, 어느 구간을 했는지(마디 범위), 몇 배속 또는 몇 BPM으로 했는지, 몇 번 해서 몇 번 깨끗하게 됐는지, 별점, 걸린 자리, 메모가 들어가고, 그날 찍은 테이크 영상에 이어진다. 왼쪽 사이드바에는 이미 영상 목록(찍은 날 · 이름 · 메모, 영상마다 박자 · 마커)이 있다. 연습 기록은 그 목록의 짝이 되어 「9/01 테이크 · 0.75배 · 3/10 깨끗 · 8x3에서 늦음」처럼 읽힌다. 나중에 RM-30이 자세 분석으로 잰 값(무릎 가동 범위 등)을 이 줄에 한 칸 더 붙인다.

##### 왜

편집 흐름 표의 A5(기존 안무를 변형해 새 판본 만들기)와 E1(곡 하나를 여러 판본으로 관리)이 지금은 「파일을 따로 저장하는 수밖에 없다」. 그러면 영상 · 박자 · 마커가 파일마다 흩어지고, 어느 파일이 공연본인지는 파일 이름에 기대야 한다. 연습도 마찬가지다. 한 안무에 영상 여러 벌이 날짜를 달고 쌓이는 데까지는 2026-09-12 · 09-20에 됐지만, 그날 몇 배속으로 몇 번 했는지, 어디서 걸렸는지는 적을 칸이 없다. 그래서 「지난주보다 나아졌나」를 기억에 기대게 된다. 로드맵 M4 「기록이 쌓인다」가 겨냥하는 시간축의 위층이 이것이고, 옛 백로그 1번(연습 버전)의 남은 절반이다.

##### 어떻게

- 자리는 이미 잡혀 있다. 스키마에 판본(ChoreoVersion: 이름 · 메모 · 부모 · 안무 본문 통째 · 기준 영상)과 연습 기록(PracticeLog: 날짜 · 판본 · 구간 · BPM · 별점 · 시도 수 · 깨끗한 수 · 걸린 자리 · 영상 · 메모)의 모양이 적혀 있다. 저장소 계약에도 판본 목록/읽기/쓰기/지우기, 기록 목록/쓰기/지우기가 적혀 있다. 아직 아무도 만들거나 쓰지 않을 뿐이라 이 모양을 실제로 배선하는 일이 된다.
- 판본 뜨기는 지금 안무 본문(필드 등록표 RM-01이 정한 필드 전부)을 값으로 복제해 이름 · 메모 · 부모 id를 붙이는 순수 함수로 만든다. 열기는 전체 불러오기와 같은 길을 타서 되돌리기 스택과 선택을 비운다(RM-03과 같은 규칙).
- 목록에는 판본 본문을 펼치지 않는다. 20장 × 20KB를 파싱하지 않도록 이름 · 날짜 · 마디 수 같은 요약(meta)만 따로 두고, 이 요약은 본문에서 다시 만들 수 있게 한다(계약에 적힌 설계 그대로).
- 연습 기록 한 줄은 약 300바이트라 통째로 다룬다. 영상은 새 참조를 만들지 않고 이미 있는 영상 목록의 항목 id로 가리킨다. 영상마다 박자 · 마커가 사는 구조가 이미 섰기 때문이다.
- 구간은 마디 · 카운트 좌표(행 · 칸)로 적는다. 보드 칸 수가 바뀌어도 읽힌다. RM-22 연습기의 「8x3~8x4 0.75배」와 같은 문법을 쓰면 연습기에서 한 번에 「이번 연습 기록하기」로 이어진다.
- 쓰기 포맷이 바뀐다. 지금 파일은 여전히 version 1로 쓰이고 versions · practiceLogs는 늘 비어 있다. 비어 있으면 키째 빼서 판본을 안 쓰는 사람의 저장 바이트가 그대로이게 한다(media · phrasing과 같은 규칙).
- 시험: 판본 뜨기 → 저장 → 다시 열기 왕복, 판본을 열어도 다른 판본과 기록이 남는지, 기록이 지워진 판본을 가리켜도 깨지지 않는지(계약이 허용하는 dangling), 빈 판본 · 기록은 파일 바이트를 늘리지 않는지.
- 라벨이 새로 생기므로 튜토리얼 · 기능 설명서의 프로젝트 · 영상 목록 대목을 함께 고친다. 확인은 confirmOnce, 알림은 RM-04의 세 급을 따른다.

##### 갈리는 대목

- 판본을 어디에 두나
  - 한 안무 파일 안에 versions 배열로 함께 둔다 — 파일 하나만 옮기면 판본과 기록이 다 따라가고, 서버 없이도 된다. 다만 판본마다 안무 본문을 통째로 품어 파일이 판본 수만큼 커진다. 정적 경로에서는 최근 목록이 파일 10개를 localStorage에 통째로 넣고 있어서 쿼터가 금방 찬다. 그래서 RM-33(IndexedDB)이 사실상 먼저 서야 한다.
  - 서버 보관 폴더에 판본을 파일로 따로 둔다(안전망 .history 곁) — 안무 파일은 가볍게 남고, RM-25가 만든 「지난 판」 화면과 서버 API를 그대로 이어 쓴다. 「안전망 판에 이름을 붙이면 판본」이라는 한 줄로 두 층이 이어진다. 대신 서버 없이 열면 판본이 없다. 파일을 남에게 줄 때 판본이 따라가지 않는다.
- 판본마다 영상을 따로 두나(절반 정해진 것의 나머지 절반)
  - 영상은 지금처럼 안무 공통으로 두고 판본은 안무표만 떠 둔다 — 가장 작다. 영상 목록과 박자 · 마커는 그대로이고, 연습 기록이 「어느 판본 · 어느 테이크」를 둘 다 가리켜 이어 준다. 다만 B안 영상이 A안 목록에도 함께 보인다.
  - 판본마다 기준 영상을 가진다 — PORTS 문서가 미리 적어 둔 길이다. 영상 블록이 통째로 판본의 기준 영상 자리로 내려가고, 최상위에는 「기본 영상」만 남는다. 판본을 고르면 영상도 갈아탄다. 대신 영상 · 템포의 주인이 바뀌어 저장 포맷과 되돌리기 범위가 크게 움직인다.
- 연습 기록을 영상 목록의 줄에 붙이나, 따로 쌓나
  - 따로 쌓고, 영상은 있으면 가리킨다 — 스키마에 적힌 모양 그대로다. 영상 없이 거울 앞에서 한 연습도 한 줄이 된다. 그날 테이크가 있으면 그 줄을 가리킨다. 목록이 둘이 되니 화면에서 둘을 어떻게 겹쳐 보일지 정해야 한다.
  - 영상 목록의 줄에 속도 · 별점 · 걸린 자리 칸을 더한다 — 이미 있는 찍은 날 · 메모 옆에 칸 몇 개만 늘리면 되어 가장 싸고, 화면도 하나다. 다만 영상 없이 한 연습은 적을 수 없고, 판본과의 연결이 흐려진다.

##### 조심할 것

- 판본 · 기록은 되돌리기 스냅샷에 넣지 않는다. 판본 안에 안무 본문이 통째로 들어 있어, 스냅샷에 넣으면 동작 하나 옮길 때마다 판본 전부가 문자열화된다(RM-35의 걱정을 키운다). 대신 판본 지우기처럼 되돌릴 수 없는 일은 confirmOnce로 한 번 더 묻는다.
- 필드 등록표(RM-01)는 안무 본문(doc)의 필드를 다룬다. versions · practiceLogs는 본문 바깥의 파일 최상위라 그 표를 타지 않는다. 저장 · 불러오기 왕복 시험을 따로 더하지 않으면 phrasing처럼 조용히 새어 나갈 수 있다.
- 파일 최상위 `media`(연습 기록이 가리킬 영상 참조 목록, 늘 빈 배열)와 안무 안 `media`(영상 목록 블록)의 이름이 겹친다. 불러올 때 펼치면 doc 쪽이 이긴다. 기록이 영상을 가리키기 시작하는 이번에 한쪽 이름을 바꿔야 한다.
- 쓰기 버전을 1에서 2로 올리면 저장 파일 바이트가 달라지는 동작 변경이다. 구조 커밋과 섞지 않는다. 판본을 안 쓴 파일은 바이트가 그대로여야 한다.
- 판본을 여는 것은 전체 불러오기다. 자동 담기가 묶인 파일을 1.2초마다 덮어쓰므로, 판본을 열면 지금 파일 본문이 그 판으로 바뀐다는 점이 RM-25의 되살리기와 같은 함정이다. 열기 전 지금 내용이 안전망에 남는지 확인하고 시험으로 잰다.
- RM-22가 연습 구간 목록을 저장한다면 이 항목과 자리가 겹친다(RM-22 계획서가 이미 적었다). 구간 · 속도의 표기와 저장 자리를 한 번에 정한다.

##### 판의 옛 설명

> 이름 붙인 판본(A안·B안·공연본)과 테이크별 연습 기록을 둔다. 한 안무에 영상 여럿, 박자·마커는 영상마다로 절반 정해졌다.
