# RM-46 Safari 인쇄에서 행 중간에 쪽이 넘어간다

인쇄할 때 .board 를 격자(display:grid)가 아닌 블록으로 흘려서, WebKit 도 행(.board-row) 중간에서 쪽을 넘기지 않게 한다. RM-21 요구 1의 「행 중간에서 쪽이 넘어가지 않는다」가 Chrome 에서만 지켜지고 Safari 에서는 깨지기 때문이며, 같은 @media print 블록을 고치는 RM-44 · RM-45 · RM-47 과 손댈 자리가 겹친다(함수 호출 관계는 없다).

크기 S · 2026-11-03 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> RM-21 요구 1(행 중간에서 쪽이 넘어가지 않는다)이 WebKit 에서 깨진다 — 40마디 표에서 1쪽 끝에 8x13 행의 윗부분이 걸리고 2쪽이 그 행의 나머지로 시작한다(넓은 판 · 폰 폭 둘 다). Chrome 은 지킨다. .board 가 display:grid 라 WebKit 이 격자 안의 break-inside: avoid 를 따르지 않는 것으로 보인다(추론). 고침 후보: 인쇄에서 .board 를 display:block 으로 바꿔 행을 블록으로 흐르게 한다.

## 요구

- 인쇄에서 .board 가 display:block 으로 바뀌어 머리 줄과 행이 블록 차례대로 흐르고, 각 행은 break-inside: avoid 를 지킨다
- 격자 gap 이 사라진 대신 행 사이 간격(4px)을 margin 으로 되살려, 인쇄물의 행 간격이 지금과 같다
- Safari(WebKit) 인쇄 미리보기에서 40마디 표의 어느 쪽 끝에도 행이 반쪽만 걸리지 않고, Chrome 인쇄 결과도 지금과 같다

## 순서

- index.html 의 @media print 에서 .board 규칙에 display: block !important 를 더하고 gap 은 걷는다(width · min-width 는 그대로 둔다)
- 같은 블록의 .board-header, .board-row 에 margin-bottom: 4px !important 를 더해 행 간격을 되살린다. 각 행이 스스로 display:grid 인 것은 화면 규칙이 지키므로 건드리지 않는다

- 같은 재현을 다시 돌린다 — Safari 미리보기에서 행이 쪽 경계에서 통째로 다음 쪽으로 넘어가는지, Chrome printToPDF 결과가 전과 같은지 넓은 판 · 폰 폭에서 본다
- docs/BUG_REPORTS.md 에 증상 · 원인(WebKit 은 grid 항목의 break-inside 를 따르지 않음 — 재현으로 확인한 만큼만) · 수정 · 재발 방지를, docs/HISTORY.md 에 한 줄을 적는다

## 조심할 것

- 원인은 아직 추론이다(grid 안의 break-inside 를 WebKit 이 따르지 않음). display:block 으로 바꿔도 Safari 에서 그대로 잘리면, 행 안의 높이를 만드는 요소(.track 의 절대 배치 블록 · 인라인 높이)가 원인일 수 있다. 그때는 고치기 전에 다시 재현해 갈래를 좁힌다
- .board 가 grid 였을 때 열 폭(grid-template-columns)을 .board 가 정했으면, 블록으로 바꾸면 행마다 열이 어긋날 수 있다. 행마다 스스로 grid-template-columns 를 갖는지 고치기 전에 확인한다
- RM-44(말풍선 숨김) · RM-45(인쇄 칸 너비) · RM-47(비고 열)이 모두 index.html 의 같은 @media print 블록을 고친다. 따로 병합하면 줄이 충돌할 수 있고, 특히 RM-45 가 칸 너비를 바꾸면 행 높이와 쪽 나눔이 달라지므로 RM-45 뒤에 Safari 확인을 한 번 더 한다
- 기존 print: 시험의 정규식(@media print \{ … \n {4}\})이 블록 끝을 들여쓰기로 찾으므로, 블록 안의 들여쓰기를 바꾸지 않는다
