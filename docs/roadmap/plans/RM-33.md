# RM-33 정적 경로의 저장을 IndexedDB 로

서버 없이 연 앱에서는 최근 프로젝트 목록(안무표 10개를 통째로 담는다)과 1.2초마다 담는 작업 문서가 localStorage 한 칸에 들어간다. 이 둘을 IndexedDB 의 「목록」과 「내용」 두 칸으로 옮겨, 용량이 차서 조용히 실패하던 일을 없애고 실패하면 알린다. 선행 항목은 없다. RM-25 · RM-29 · RM-30 이 서버 없이 무엇을 남기려면 이 바닥 위에 서야 하므로, 이 항목이 그들보다 앞이다.

크기 M · 2026-10-13 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 서버 없이 정적 파일로 열었을 때 안무표를 브라우저 안에 담는 자리를 localStorage 에서 IndexedDB 로 옮긴다. 지금은 최근 목록이 안무표 10개의 내용을 localStorage 한 칸에 통째로 넣는다. 그래서 용량(보통 5MB 안팎)이 차면 목록에 오르지 않거나 자동 담기가 멈추는데, 사용자는 그 사실을 모른다.

## 요구

- 새 IndexedDB 어댑터가 ports/storage 의 SnapshotStore 계약(Promise 반환 · StorageError)을 채운다. 최근 프로젝트는 「목록(이름·저장 시각)」과 「내용」 두 칸으로 갈라 담고, 목록을 읽을 때 내용은 읽지 않는다
- 최근 목록의 한 줄을 열면 서버 폴더 경로처럼 이름으로 내용을 따로 읽어 온다. 저장 직후 보관 폴더에 쓰는 일도 지금처럼 이어진다
- 작업 문서 자동 담기의 브라우저 칸(choreo_draft)을 IndexedDB 로 옮긴다. 서버가 있으면 서버가 이기고 브라우저 칸은 읽기 폴백이라는 규칙은 그대로 둔다
- 처음 켤 때 localStorage 의 choreo_saved_files 와 choreo_draft 를 IndexedDB 로 한 번 옮긴다. 옮긴 뒤 다시 읽어 맞을 때만 옛 칸을 비운다
- 담기에 실패하면(쿼터 초과·열기 실패) 조용히 넘어가지 않는다. 「브라우저에 담지 못했다 — 파일은 받아졌다」처럼 알리고, 불러오기 경로도 「올바른 파일이 아닙니다」로 뭉개지 않는다
- IndexedDB 가 없거나 막힌 브라우저(사파리 프라이빗 등)에서는 지금의 localStorage 경로로 떨어진다
- 구조를 옮기는 커밋에서는 격자 골든이 그대로 통과한다. 실패를 알리는 동작 변경은 따로 커밋한다
- 테마·단축키·즐겨찾기·동작/카테고리 최근 목록 같은 작은 설정은 localStorage 에 둔다. 부팅 때 동기로 읽혀야 첫 화면이 깜빡이지 않는다

## 결정 사항

- 무엇까지 IndexedDB 로 옮기나
  - 최근 프로젝트 목록과 작업 문서 둘만 — 용량 문제는 이 둘에서만 난다. 테마·단축키·즐겨찾기·동작/카테고리 최근 목록(3개 상한)은 부팅 때 동기로 읽혀 첫 화면이 깜빡이지 않는다
  - 동작·카테고리 최근 목록까지 — 이것들도 payload 를 품지만 상한이 3이라 작다. 옮길 호출부가 둘 더 비동기가 된다
  - localStorage 키 전부 — 저장 자리가 하나로 모인다. 대신 부팅이 통째로 비동기가 되어 테마가 늦게 입혀지고, 고칠 호출부가 스무 곳 넘게 는다
  - **고른 답**: 최근 프로젝트 목록과 작업 문서 둘만
  - **근거**: 💰 절약 검토자 — 요구 8이 작은 설정은 localStorage 에 둔다고 정했고, 용량 문제는 두 가지에서만 난다. · 관점 범위
- 옛 localStorage 자료를 어떻게 넘기나
  - 옮기고, 다시 읽어 맞으면 옛 칸을 비운다 — 두 벌이 어긋나지 않고 localStorage 용량도 풀린다. 확인을 거쳐야 잃지 않는다
  - 옮기되 옛 칸은 한동안 남긴다 — 잃을 위험은 가장 적다. 다만 용량이 그대로라 localStorage 로 떨어지는 브라우저에서는 쿼터 문제가 남는다
  - **고른 답**: 옮기고, 다시 읽어 맞으면 옛 칸을 비운다
  - **근거**: 💰 절약 검토자 — 요구 4가 다시 읽어 맞을 때만 옛 칸을 비운다고 정했다. 확인을 거치므로 잃을 위험도 막힌다. · 관점 범위
- 브라우저에 영구 저장(지우지 말아 달라)을 청하나 — 설정에서 켜고 끌까
  - 청하지 않는다(기본 끔, 설정 칸 없음) — 지금과 같다. 서버·파일이 진짜 보관처라는 기존 설명을 따른다. 사파리는 오래 안 연 사이트의 저장소를 비울 수 있다
  - ⚙ 설정에 켜기 칸을 두고 기본은 끔 — 켜면 브라우저가 함부로 비우지 않는다. 브라우저에 따라 허락 창이 뜬다
  - **고른 답**: 청하지 않는다(기본 끔, 설정 칸 없음)
  - **근거**: 💰 절약 검토자 — 요구에 영구 저장 청구나 설정 칸이 없다. 서버·파일이 보관처라는 기존 설명을 따른다. · 관점 범위

## 조심할 것

- saveProjectNow 는 지금 목록 첫 줄(recents.projects[0].data)에서 payload 를 꺼내 보관 폴더에 쓴다. 목록 항목에서 data 를 빼면 서버 경로 저장이 조용히 멈추므로 같은 커밋에서 함께 고친다
- 불러오기 경로는 동기로 던져진 저장 실패가 같은 try 의 「올바른 프로젝트 파일이 아닙니다」로 잡히는 데 기댄다. 비동기로 바꾸면 그 알림이 사라지거나 잡히지 않은 거부로 새어 나간다. 거부는 storage 다리에서 받아 따로 알린다
- 부팅 때 동기로 읽던 최근 목록이 비동기가 되어 첫 순간 목록이 비어 보인다. refreshProjectFolder 의 합치기가 먼저 끝나면 브라우저 쪽이 빠지거나 겹칠 수 있으니 둘을 기다린 뒤 합친다
- 작업 문서 되살리기(24절)가 IndexedDB 열기를 기다리게 된다. 되살리기 전에 담기가 돌아 빈 문서로 덮지 않게 순서를 지킨다
- IndexedDB 도 출처(주소·포트)마다 따로다. RM-28 의 포트가 바뀌면 사라져 보이는 문제는 이것으로 풀리지 않는다. RM-27 의 정적 경로 칸에 떨어지는 길을 적는다
- 의존성을 늘리지 않으려 idb · fake-indexeddb 를 쓰지 않는다. 가짜 IndexedDB 가 실제 이벤트 순서(트랜잭션 complete 뒤 resolve)와 어긋나면 시험은 푸른데 브라우저에서 깨진다. 실제 브라우저에서 한 번 눈으로 본다

## 다시 다듬기 전의 계획서

### RM-33 정적 경로의 저장을 IndexedDB 로

#### 풀어 본 설명 — 2026-09-29

서버 없이 정적 파일로 열었을 때 안무표를 브라우저 안에 담는 자리를 localStorage 에서 IndexedDB 로 옮긴다. 지금은 최근 목록이 안무표 10개의 내용을 localStorage 한 칸에 통째로 넣는다. 그래서 용량(보통 5MB 안팎)이 차면 목록에 오르지 않거나 자동 담기가 멈추는데, 사용자는 그 사실을 모른다.

##### 무엇

화면은 거의 그대로다. 서버 없이 연 앱에서 `프로젝트 저장`을 누르거나 파일을 불러오면 최근 프로젝트 목록에 안무표가 오르고, 편집하는 동안 작업 문서가 1.2초마다 자동으로 담긴다. 이 둘을 담는 자리가 localStorage 에서 IndexedDB 로 바뀐다. 목록에는 이름과 저장 시각만 올리고 안무표 내용은 열 때 따로 읽는다. 서버 경로에서 폴더 목록을 쓰는 방식과 같다. 이렇게 하면 목록을 그리려고 수백 KB 를 읽는 일이 없어진다. 처음 켜면 localStorage 에 쌓여 있던 최근 목록과 초안을 IndexedDB 로 한 번 옮긴다. 그래도 담기에 실패하면 조용히 넘어가지 않고 「브라우저에 담지 못했다 — 파일은 받아졌다」처럼 알린다. 테마·단축키·즐겨찾기 같은 작은 설정은 옮길 까닭이 적다.

##### 왜

정적 경로의 최근 목록(choreo_saved_files)은 항목마다 안무표 전체를 품고 10개까지 쌓는다. 영상 박자·마커·프레이즈가 붙은 안무표 몇 개면 용량에 닿는다. 닿으면 세 가지 일이 조용히 벌어진다. 저장 경로에서는 파일은 내려받아졌는데 목록에 없고, 예외가 잡히지 않은 채 새어 나간다. 불러오기 경로에서는 엉뚱하게 「올바른 파일이 아닙니다」류의 알림으로 뭉개진다. 자동 담기(choreo_draft)는 false 만 돌려주고 멈춰서, 사용자는 담긴 줄 알다가 새로고침 한 번에 그날의 일을 잃는다. IndexedDB 는 용량이 훨씬 크고 쿼터 실패를 오류 코드로 분명히 알려 준다. RM-25(브라우저 안 직전 판) · RM-29(판본) · RM-30(자세 분석 결과)이 서버 없이도 무엇을 남기려면 이 바닥이 먼저 서야 한다. 다만 2026-09-23 에 배포 형태를 설치형 앱(서버가 늘 곁에 있다)으로 정하면서 정적 경로가 주 입구에서 빠졌다. 그래서 급한 일은 아니고 크기 M 의 「나중」이다.

##### 어떻게

- 계약은 이미 있다. ports/storage 에 Promise 를 돌려주는 KvStore·SnapshotStore 와 StorageError(QUOTA_EXCEEDED·UNAVAILABLE·CORRUPT) 가 정의만 된 채 기다린다. 그 계약을 따르는 IndexedDB 어댑터를 새로 짓는다.
- IndexedDB 를 여는 법은 clipLibrary 가 폴더 핸들을 IndexedDB 에 담는 방식을 본뜬다. 새 선례를 만들지 않는다.
- 최근 목록은 「목록(이름·시각)」과 「내용」 두 칸으로 가른다. 여는 경로는 서버 경로의 openFromFolder 처럼 이름으로 내용을 읽어 온다.
- draftStore 의 브라우저 칸을 IndexedDB 로 바꾼다. 서버가 있으면 서버가 이기고 브라우저 칸은 읽기 폴백이라는 규칙은 그대로 둔다.
- 첫 부팅 때 localStorage 의 choreo_saved_files·choreo_draft 를 옮긴다. 옮긴 뒤 읽어 보고 맞을 때만 옛 칸을 비운다.
- 동기 호출부(pushRecent 의 persist, 불러오기의 try/catch, 부팅의 loadLocalMeta)를 비동기로 고친다. 먼저 구조만 옮기는 커밋으로 골든이 그대로인지 보고, 실패를 알리는 동작 변경은 따로 커밋한다.
- IndexedDB 가 없거나 막힌 브라우저(사파리 프라이빗 등)에서는 지금의 localStorage 경로로 떨어진다.
- 시험은 의존성 없이 돌아야 하므로 메모리 가짜 IndexedDB 를 tests 안에 직접 짓는다. 쿼터 초과·열기 실패·옮기기를 시험으로 잰다.

##### 갈리는 대목

- 무엇까지 IndexedDB 로 옮기나
  - 무거운 둘만 — 최근 프로젝트 목록과 작업 문서 — 용량 문제는 이 둘에서만 난다. 테마·단축키·즐겨찾기는 부팅 때 동기로 읽혀 첫 화면이 깜빡이지 않는다. 가장 작고 추천한다.
  - localStorage 키 전부 — 저장 자리가 하나로 모이지만, 부팅이 통째로 비동기가 되어 테마가 늦게 입혀지는 등 화면 순서가 흔들린다. 옮길 호출부도 스무 곳 넘게 늘어난다.
- 옛 localStorage 자료를 어떻게 넘기나
  - 옮기고, 다시 읽어 맞으면 옛 칸을 비운다 — 두 벌이 어긋날 일이 없다. 옮기기가 틀리면 잃으므로 확인을 반드시 거친다. 추천한다.
  - 옮기되 옛 칸은 한동안 남긴다 — 잃을 위험이 가장 적다. 다만 용량이 그대로 차 있어 localStorage 로 떨어지는 경로(IndexedDB 없는 브라우저)에서는 쿼터 문제가 남는다.
- 브라우저에 「지우지 말아 달라」(영구 저장)를 청하나 — 설정에서 켜고 끌까
  - 청하지 않는다(기본 끔) — 지금과 같다. 사파리 등은 오래 안 연 사이트의 저장소를 비울 수 있다. 서버·파일이 진짜 보관처라는 기존 설명을 따른다.
  - 설정의 켜기 칸으로 둔다 — 켜면 브라우저가 저장소를 함부로 비우지 않는다. 브라우저에 따라 허락 창이 뜰 수 있어 기본은 끔을 추천한다.

##### 조심할 것

- 지금 불러오기 경로는 저장 실패가 동기로 던져져 같은 try 안의 알림으로 잡히는 것에 기댄다. 비동기로 바꾸면 알림이 사라지거나 잡히지 않은 거부로 새어 나간다. 호출부를 함께 고쳐야 한다.
- 부팅 때 최근 목록을 동기로 읽던 것이 비동기가 된다. 첫 순간 목록이 비어 보이다가 채워진다. 서버 폴더 목록과 합치는 refreshProjectFolder 의 순서도 어긋나지 않게 한다.
- IndexedDB 도 출처(주소·포트)마다 따로다. RM-28 의 포트가 바뀌면 사라져 보이는 문제는 이것으로 풀리지 않는다.
- 사파리 프라이빗·일부 설정에서는 IndexedDB 가 없거나 창을 닫으면 비워진다. 떨어지는 길(localStorage)을 남기고 RM-27 지원 매트릭스의 정적 경로 칸을 고친다.
- 구조를 옮기는 커밋과 실패를 알리는 동작 변경을 섞지 않는다. 쿼터 실패를 어떤 급(토스트·인라인)으로 알릴지는 RM-04 와 맞춘다.
- 빌드 도구·의존성 금지 때문에 idb 같은 도우미 라이브러리나 fake-indexeddb 를 쓰지 않는다. 가짜 IndexedDB 를 시험 안에 직접 짓는다.
