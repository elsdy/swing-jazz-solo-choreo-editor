# RM-63 엄지 바의 처음으로 단추 글자가 잘린다

1200px 창에서는 영상 띠 아래 조작 줄의 단추들이 폭을 똑같이 나눠(flex 1 1 0) 갖는다. 그래서 `⏮ 처음으로` 단추가 68px밖에 못 받아 '처...'로 잘린다. 이 일에서는 그려진 단추의 글자 폭을 재고, 넘치면 짧은 꼴(⏮)로 접으며 전체 이름은 툴팁과 aria-label 로 남긴다(U-13 「재고 접을 것을 고른다」). RM-18(아이콘 스프라이트)이 생기기 전부터 있던 넘침이라 그 항목과는 따로 낸다. RM-18 의 코드는 부르지 않고 이모지 짧은 꼴만 쓴다.

크기 S · 2026-11-03 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 1200px 창에서 엄지 바의 「처음으로」 단추가 폭 68px 이라 글자가 '처...' 로 잘린다. RM-18 전(⏮ 처음으로)에도 77px 로 넘쳐 잘리던 것이라 그 항목 밖의 일이다 — 좁은 칸은 아이콘만(iconOnly) 두거나 폭을 재고 접을 것을 고른다(U-13).

## 요구

- 영상 띠 조작 줄(1200px 창)에서 `⏮ 처음으로` 단추 글자가 말줄임으로 잘리지 않는다 — 단추 폭에 글자가 넘치면 아이콘만 남는 짧은 꼴로 접는다
- 접힌 단추도 무엇인지 알 수 있다 — 전체 이름을 title 과 aria-label 로 갖는다
- 자리가 넉넉하면 전체 글자를 그대로 보인다 — 접기는 잰 결과로만 고르고 기본값으로 삼지 않는다
- 접는 것은 짧은 꼴을 가진 단추에만 한다. 주 동작(`▮ 끊기`)과 짧은 꼴이 없는 단추는 그대로 둔다
- 다시 그릴 때 자리가 넉넉해지면(창을 넓히거나 이웃 단추가 빠졌을 때) 전체 글자로 되돌아온다

## 결정 사항

- 좁은 칸의 `⏮ 처음으로` 를 어떻게 접을까 — 지금은 1200px 창에서 68px 단추에 글자가 '처...'로 잘린다
  - 재서 넘칠 때만 아이콘만(⏮)으로 접는다 — 넓은 칸과 폰에서 자리가 있으면 글자가 그대로 보인다. 접힌 때만 툴팁 · aria-label 로 이름을 알린다. render 한 곳에서 재고, 시험은 가짜 DOM 의 폭으로 판정 길을 잰다
  - 영상 띠 조작 줄(docked)에서는 늘 아이콘만 둔다 — 재는 코드가 없어 단순하다. 다만 자리가 있어도 글자가 빠져, 받아 적기 첫 차례인 단추가 무엇인지 처음 쓰는 사람이 모를 수 있다
  - 글자 폭만큼(flex auto) 주고 주 동작 `▮ 끊기` 가 남는 자리를 갖는다 — 글자는 그대로 보이지만 주 동작이 좁아진다. 탭 숫자가 늘면 다시 넘칠 수 있다
  - **고른 답**: 재서 넘칠 때만 아이콘만(⏮)으로 접는다

## 조심할 것

- RM-18(아이콘 스프라이트, 진행 중)이 thumbBar 의 글자를 SVG 로 바꾸면 thumbBar.js 의 같은 함수가 겹친다. 이 항목은 이모지 짧은 꼴만 쓰고 RM-18 의 코드는 부르지 않는다
- 재는 값은 단추가 붙고 자리(placeBand 의 width)가 정해진 뒤에만 맞다. 첫 렌더나 창 폭 변경 뒤 render 가 안 불리면 접힘이 낡는다
- 전체 글자로 그렸다가 재고 다시 바꾸는 사이에 레이아웃을 강제로 다시 계산한다. 단추 너덧뿐이라 비용은 작다고 추론한다. 다만 연속 render(탭 두드림)마다 돈다
- 탭 단추(`탭 (n) · BPM`)도 숫자가 늘면 넘칠 수 있다. 짧은 꼴 없이 두면 말줄임은 남는다 — 이번 범위 밖임을 밝혀 둔다
- 가짜 DOM 시험은 실제 글자 폭을 모른다. 실물 측정을 빼먹으면 판정 길만 초록이고 화면은 여전히 잘릴 수 있다
