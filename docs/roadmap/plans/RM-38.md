# RM-38 판 변경 올리기가 규모 불일치로 막힘

판(ROADMAP.json)이 다시 다듬으며 RM-16·18·19·24 를 L 로, RM-27 을 M 으로 바꿨는데 문서 ROADMAP.md 의 추적 표와 세 칸 항목 줄은 아직 M/S 라서, 로드맵 시험 두 개가 붉고 판 변경 올리기가 푸시 훅에 막힌다. 판이 원본이라는 D-19 에 따라 문서의 규모를 판에 맞춘다. 세 칸 항목 줄의 「(규모)」도 대조하게 해서 같은 일이 다시 생기면 곧바로 드러나게 한다. B949(판만 고쳐 로드맵 시험이 붉어진 버그)와 같은 꼴이다.

크기 S · 2026-10-20 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> items-push 가 푸시 훅에서 막혔다 — 본 트리 판(ROADMAP.json)의 RM-16·18·19·24·27 규모(L/M)가 문서 ROADMAP.md 의 규모(M/S)와 달라 tests/unit/roadmapFile.test.mjs 두 시험이 붉다. 판이 다시 다듬으며 규모를 바꾸고 문서를 따라 고치지 않은 것으로 보인다(B949 와 같은 꼴).

## 결정 사항

- 판이 규모를 다시 다듬을 때마다 문서가 또 어긋난다. 문서에 규모를 계속 적을까
  - 계속 적고 이번에 맞춘다(본문 괄호까지 대조) — 문서만 읽어도 규모가 보인다. 대신 판이 규모를 바꿀 때마다 문서 커밋이 하나 따라붙어야 한다
  - 문서에서 규모 칸과 괄호를 걷고 판에만 둔다 — 다시는 이 꼴로 붉어지지 않는다. 대신 문서 독자가 규모를 보려면 보드를 열어야 하고, 시험의 규모 대조와 표 꼴을 함께 바꿔야 한다
  - **고른 답**: 계속 적고 이번에 맞춘다(본문 괄호까지 대조)
  - **근거**: 💰 절약 검토자 — 무엇이 「문서의 규모를 판에 맞춘다」로 범위를 적었고, 표 꼴·시험 개편은 이 항목 밖 · 관점 범위
- 판이 다시 다듬으며 문서를 따라 고치지 않는 것은 엔진 쪽 일이다. 보드 판에도 올릴까
  - rb.py found --side engine 으로 보드 판에 올린다 — 다듬기가 규모를 바꿀 때 문서 표도 함께 고치거나 경고하게 하는 일이 엔진 쪽에서 따로 선다
  - 이 저장소의 대조 시험만으로 둔다 — 고칠 것은 적다. 하지만 판 변경 올리기는 계속 푸시 훅에서 처음 걸린다
  - **고른 답**: 이 저장소의 대조 시험만으로 둔다
  - **근거**: 💰 절약 검토자 — 항목 범위는 이 저장소 문서·시험이며 엔진 쪽 보드 올리기는 별도 판단, 고칠 자리도 적다 · 관점 범위 → 단순함

## 조심할 것

- 본 트리의 ROADMAP.json 과 plans/ 에 커밋하지 않은 변경이 있다 — 맞출 기준은 origin/main 이 아니라 올리려는 판의 값이다. 브랜치에서 판 값을 다시 확인한다
- 본문 항목 줄 가운데 괄호 규모가 없거나 꼴이 다른 줄이 있으면 새 대조가 엉뚱하게 붉어진다 — 읽은 줄 수 하한을 두고, 괄호가 없는 줄은 건너뛴다
- RM-38 자신은 판에만 있다 — 계획서(plans/RM-38.md)가 없으면 '판 파일에만 있고 계획서도 없다'로 붉어진다. 계획서가 함께 들어가는지 본다
- D-19 와 같은 말을 원칙에 또 쓰지 않는다 — 근거만 더한다
