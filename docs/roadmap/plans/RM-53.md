# RM-53 factoriel 이 남의 판에 plan 없는 「from-factoriel」 트랙을 더해 items-push 가 막힘

RM-53 은 판의 RM-49(진행 중, branch 단계)와 같은 버그다. 둘 다 보드가 plan 없이 더한 from-factoriel 트랙 때문에 roadmapFile 시험의 앵커 대조가 t.plan.split 에서 TypeError 로 던진다고 말하고, RM-49 계획서는 사람이 이미 확인했다. 그래서 이 항목은 고침을 다시 만들지 않는다. RM-49 가 만들 trackAnchorMismatches 로 실제 판의 출처 트랙을 한 번 더 재는 회귀 시험 하나만 더하고, 판에서 RM-49 에 합쳐 닫는다.

크기 S · 2026-11-03 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> found.py 가 swing-jazz-choreo 의 ROADMAP.json 에 트랙 {id: from-factoriel, name: 🏭 factoriel 에서 올라온 버그} 를 plan 칸 없이 더했다. 이 저장소의 tests/unit/roadmapFile.test.mjs:187 「트랙이 가리키는 문서 앵커가 문서 뷰어에서 실제로 걸린다」가 t.plan.split 에서 TypeError 로 붉어 items-push 의 푸시 훅이 막는다(시험 614 중 1 붉음). 길: found 가 트랙에 plan 을 달거나(그 저장소 ROADMAP.md 의 절), 저장소 시험이 plan 없는 from- 트랙을 건너뛰게 한다. RM-23 자리에서 찾음 — 이 항목의 push 는 ROADMAP.json 을 안 고치므로 막지 않는다.

## 요구

- RM-49 가 병합된 뒤 실제 판(from-factoriel 트랙이 plan 없이 설명만 가진 상태)으로 roadmapFile 시험 파일 전체가 초록인지 확인한다
- 이름이 from- 으로 시작하는 출처 트랙은 모두 plan 없이 설명만으로 앵커 대조를 지난다. 이것을 실제 판으로 재는 회귀 시험을 둔다. 설명까지 비면 붉다
- 버그 기록의 RM-49 항목에 「같은 버그가 RM-23 자리에서 RM-53 으로 또 올라왔다」를 근거로 더한다. 판에서는 RM-53 을 RM-49 의 중복으로 적어 닫는다

## 결정 사항

- RM-53 을 RM-49 와 겹친 항목으로 어떻게 다룰까. 두 항목 모두 같은 TypeError(from-factoriel 트랙에 plan 이 없어 items-push 가 막히는 일)를 말하고, RM-49 는 사람이 확인한 계획으로 이미 브랜치에서 진
  - 회귀 시험 하나만 더하고 RM-49 에 합쳐 닫는다 — RM-49 병합 뒤 claude 가 실제 판의 from- 트랙을 재는 시험 하나와 버그 기록 근거만 더한다. 그다음 판에서 RM-53 을 닫는다. 고침은 한 번만 만든다
  - 시험 없이 지금 바로 중복으로 지운다 — 판에서 RM-53 만 걷어 낸다. 실제 판 꼴(출처 트랙)을 콕 집어 재는 회귀 시험은 남지 않고, RM-49 의 견본 시험과 전체 앵커 시험에만 기댄다
  - 따로 두고 from- 트랙은 설명 없이도 건너뛰게 한다 — RM-53 설명의 길대로 이름 접두만 보고 건너뛴다. 그러면 RM-49 가 정한 「설명이 있어야 통과」 문턱과 어긋나 두 규칙이 생긴다
  - **고른 답**: 회귀 시험 하나만 더하고 RM-49 에 합쳐 닫는다

## 조심할 것

- RM-49 보다 먼저 시작하면 trackAnchorMismatches 가 아직 없어 새 시험이 서지 않는다. 이 항목의 시험은 RM-49 가 만드는 trackAnchorMismatches 를 그대로 부르므로 선행이 RM-49 다
- 작업 사본의 ROADMAP.json · BUG_REPORTS.md · PRINCIPLES.md 는 RM-49 자리에서 고친 것이다. 그 변경을 이 브랜치로 끌어오거나 덮지 않는다
- 회귀 시험이 from- 트랙을 하나도 못 찾으면 아무것도 재지 않고 통과한다. 그래서 적어도 하나 있는지를 함께 assert 한다. 보드가 트랙 이름을 바꾸면 이 시험이 붉어지는데, 이것은 의도한 동작이다
- 엔진 판에 올릴 일: found.py 가 남의 판에 출처 트랙을 더할 때 plan(그 저장소 ROADMAP.md 의 절)을 함께 다는 일은 factoriel SCHEMA 를 바꾸는 엔진 쪽 일이다. 이 항목에서는 다루지 않는다
