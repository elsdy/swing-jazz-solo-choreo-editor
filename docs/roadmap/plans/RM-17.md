# RM-17 디자인 토큰 한 벌

## 풀어 본 설명 — 2026-09-29

화면 곳곳에 그때그때 적어 둔 색·글자 크기·간격·모서리·그림자 값을 이름 붙은 값 몇 개(디자인 토큰)로 모은다. 지금은 글자 크기가 18가지, 색이 289가지(hex 75·rgba 214), 그림자가 56가지, 모서리가 19가지나 된다. 그래서 화면마다 다른 사람이 만든 것처럼 보이고, 테마를 바꿔도 색이 따라오지 않는 자리가 남는다. 토큰으로 모으면 테마는 토큰 값만 갈아 끼우는 일이 된다.

### 무엇

겉으로는 새 버튼이 생기지 않는다. 대신 어느 화면을 찍어도 같은 사람이 만든 것처럼 보이게 된다. 색은 여덟 개(바탕 2·면 2·글자 2·강조 1·경고 1)에 상태색 셋을 더한 것만 쓴다. 글자 크기는 네 단(11·12·13·15px), 간격도 네 단(4·8·12·16), 모서리는 세 단(6·10·끝까지 둥글게), 그림자는 두 단만 남긴다. 격자·팝업·설정·문서 창·영상 패널이 모두 이 값을 쓴다. 7px부터 16px까지 제각각이던 글자 크기와 `!important` 로 억지로 덮던 자리가 사라진다. 네온·자정 장미·솜사탕 테마는 이 토큰 값만 바꾸는 「분위기」가 된다. 지금처럼 테마 전용 표면 규칙으로 기본 테마와 다른 모양을 따로 갖지 않는다. 안무 블록의 카테고리 색이나 위험(빨강)·경고(주황)처럼 뜻을 담은 색은 정보라서 테마가 바꾸지 않는다.

### 왜

색과 크기를 쓸 때마다 새로 적어 왔다. 그러다 보니 같은 종류의 면인데 모서리와 그림자가 다르다. 글자 위계가 없어 무엇이 제목이고 무엇이 보조 글인지 크기로 읽히지 않는다. 발광 그림자가 31곳에 깔려 정말 강조할 자리가 묻힌다. 로드맵 기둥 A가 말하는 「촌스러움」의 뿌리다. 테마를 더할 때도 문제가 된다. 토큰이 26개뿐이라 토큰 밖에 적힌 색은 테마를 바꿔도 그대로 남는다. 이를 메우려고 테마 블록이 색이 아닌 표면 규칙까지 다시 적고 있다. 테마 하나를 더하거나 한 곳의 색을 고치려면 수백 줄을 훑어야 한다. 아이콘 한 벌(RM-18)도 아이콘 크기와 색을 이 토큰에 맞춰야 하므로 이 항목을 먼저 해야 한다.

### 어떻게

- 먼저 잰다: `index.html` 스타일 블록과 JS가 직접 적는 인라인 색(설정 화면·문서 창·말로 채우기 팝업에 특히 많다)을 전부 모아 값마다 몇 번 쓰였는지 표로 만든다
- `:root` 에 토큰 한 벌을 정의한다 — 지금 있는 `--bg` `--panel` `--text` `--muted` `--accent` `--danger` `--warn` `--shadow` 를 뼈대로 쓰고, 글자·간격·모서리·그림자 단계를 더한다
- 구조 커밋: 지금 값을 그대로 가리키는 토큰으로 바꿔 끼운다. 이 단계에서는 화면이 한 픽셀도 달라지지 않는다
- 동작(겉모습) 변경 커밋: 비슷한 값들을 가까운 단계 하나로 접는다(예: 10·10.5·11px → 11). 화면이 달라지므로 다섯 화면(첫 화면·받는 중·설정·문서·폰)을 전후로 찍어 비교한다
- 테마 블록을 고친다: 테마마다 적는 ① 색 블록만 남기고, ② 표면 규칙 가운데 기본 테마와 다른 모양을 만드는 것은 걷어 낸다
- 끝났는지 기계로 잰다: 스타일에서 토큰 밖 색 0, 글자 크기 5가지 이하, `!important` 0을 세는 검사를 둔다(RM-05 검사기에 한 항목으로 넣을 수도 있다)
- 라벨 문구는 바뀌지 않지만 화면 모습이 바뀌므로, 스크린샷이 든 문서가 있으면 함께 고친다

### 손댈 자리

- `index.html` 의 `<style>` 블록 전체 — `:root` 토큰 정의와 3천 줄 남짓한 규칙
- `index.html` 의 테마 절(① 색 · ② 표면 규칙)
- JS가 인라인 style로 색·크기를 적는 화면 — 설정 화면, 문서 허브, 말로 채우기 팝업, 구절 보기, 빠른 고르기, 오버레이
- `admin.html` 의 따로 된 스타일(서버 관리 화면 — `src/` 를 import 하지 않으므로 토큰을 따로 베끼거나 범위에서 뺀다)
- 테마 목록(`src/domain/themes.js`)의 설명 문구 — 「분위기」로 강등한 뜻을 반영할지

### 갈리는 대목

- 기본 테마의 모습을 이번에 바꾸나
  - 두 걸음으로 — 먼저 값을 보존한 채 토큰으로 옮기고, 다음 커밋에서 값을 접는다(추천) — 「구조와 동작을 한 커밋에 섞지 않는다」 원칙에 맞다. 첫 걸음은 화면이 그대로여서 안심하고 병합할 수 있다. 둘째 걸음의 변화만 눈으로 비교하면 된다. 커밋과 PR이 둘로 늘어난다.
  - 한 번에 접는다 — 빨리 끝난다. 다만 화면이 달라졌을 때 옮기다 틀린 것인지 일부러 바꾼 것인지 가려낼 수 없다. 테마를 고른 적 없는 사람의 화면이 달라지지 않는다는 지금의 약속(테마 절 머리말)도 깨진다.
- JS가 직접 적는 색·크기(인라인 style 약 140곳)를 범위에 넣나
  - 넣는다 — 인라인 값을 `var(--…)` 로 바꾸거나 클래스로 옮긴다 — 「토큰 밖 색 0」이 정말로 성립한다. 설정 화면·문서 허브처럼 JS로 그린 화면도 테마를 따라온다. 대신 L 크기가 꽉 찬다.
  - 스타일 블록만 하고 JS 쪽은 따로 뗀다 — 이 항목이 작아진다. 다만 설정·문서 창이 테마를 안 따라오는 자리로 남아 「한 벌로 보인다」는 기준을 못 채운다. 카테고리 색·루틴 색처럼 데이터에서 오는 색(RM-34와 닿는다)은 어느 쪽이든 토큰 밖에 둔다.
- 발광·유리 효과 줄이기와 세 테마 강등을 이 항목에 함께 넣나
  - 함께 넣는다 — 그림자 두 단으로 접을 때 발광 31곳도 「지금 있는 자리·듣는 중·경고」 셋으로 줄인다 — 그림자를 접는 일과 자리가 같아 한 번에 끝난다. 네온 테마의 계기판 느낌이 약해진다.
  - 토큰만 하고 발광·테마 모양은 뒤로 미룬다 — 이 항목이 순수한 정리로 남는다. 다만 테마의 표면 규칙이 그대로 있어 「테마는 토큰만 바꾼다」가 반쪽이 된다.

### 조심할 것

- 뜻을 담은 색(카테고리 색·팔레트 점·위험 빨강·경고 주황·지금 있는 자리 호박색)을 장식 색과 함께 접으면 읽던 뜻이 달라진다. 이런 색은 상태색·데이터 색으로 따로 둔다
- 솜사탕은 유일한 밝은 테마다. 어두운 바탕을 전제로 적은 rgba 반투명 값을 토큰으로 옮기면 밝은 바탕에서 글자가 안 보일 수 있다. 네 테마를 모두 찍어 본다
- 격자 크기 변수(`--cellW` `--cellH` `--rowLabelW` `--noteW`)는 JS가 재서 쓰는 레이아웃 값이다. 간격 토큰과 섞지 않는다. 읽는 쪽 폴백(52·68)도 원문 그대로 보존된 결함이다
- `!important` 를 걷으면 그것이 이기던 규칙 순서가 드러난다. `[hidden]` 짝 문제를 다루는 RM-05와 같은 CSS 자리를 건드리므로 순서를 맞춘다
- 로드맵은 M1 안의 순서를 명령 등록부(RM-09) → 포인터 통일(RM-11) → 직접 조작(RM-12) → 토큰·아이콘으로 정했다. 선행은 없어도 앞 항목들이 버튼과 팝업 모양을 바꾸면 여기서 접은 자리를 다시 만진다
- 스타일이 `index.html` 한 파일에 3천 줄로 모여 있다. 큰 바꿔치기를 한 커밋에 몰면 검토할 수 없다. 영역(격자·팝업·영상 패널·설정)마다 나눠 커밋한다

### 판의 옛 설명

> 색·글자·간격·모서리·그림자를 토큰 한 벌로 접는다. 지금 글자 크기 18가지·색 289가지·그림자 56가지가 흩어져 있고 테마는 토큰만 바꾸게 된다.
