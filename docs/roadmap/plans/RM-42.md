# RM-42 비고 칸 폭 재측정이 렌더마다 약 5ms 고정으로 든다

renderRows 가 끝날 때마다 setNoteWidth 는 비고 칸 폭(--noteW)을 0px 로 썼다가 칸 65개의 scrollWidth 를 다시 재서 다시 쓴다. 그래서 강제 리플로가 두 번 나고, 그린 행 수와 상관없이 매번 중앙값 4.8ms 가 든다(RM-35 의 큰 견본 재기). 이 일에서는 0px 쓰기를 없애고, 칸 안쪽의 내용 폭을 한 번만 읽어 잰다. 잰 폭이 지금과 같으면 다시 쓰지 않는다. 그러면 좁힌 렌더 5.5ms 의 거의 전부를 차지하는 이 몫이 줄어 RM-12 · RM-14 의 움직이는 동안 그리기에 여유가 생긴다. RM-35 가 측정해 올린 병목이고, 비고 열 인쇄 문제인 RM-47 과는 같은 비고 칸을 만지지만 고치는 대상은 다르다.

크기 M · 2026-11-03 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> RM-35 재기(64마디 × 3층 × 300개, Chrome · 1440폭)에서 boardView.renderRows 끝의 adjustNoteColumnWidth(cssVars.setNoteWidth)가 그린 행 수와 무관하게 중앙값 4.8ms 든다 — 비고 칸 65개를 0 으로 썼다가 다시 재는 강제 리플로 두 번. 전 행 렌더 12~15ms 의 약 1/3, 좁힌 렌더 5.5ms 의 거의 전부다. 좁힌 렌더로 가도 이 몫은 남으므로, 다시 빨라야 할 때(RM-12 · RM-14 의 움직이는 동안 그리기) 먼저 볼 자리다. deviations 「렌더 범위와 떠 있는 것들」에 측정 절차를 바꾸지 않은 까닭이 있다.

## 요구

- 렌더마다 --noteW 를 0px 로 먼저 쓰는 단계를 없앤다. 비고 칸 안쪽 감싸개의 내용 폭을 읽기만 해서 잰다. 이렇게 하면 강제 리플로가 두 번에서 한 번으로 준다.
- 잰 폭이 noteRoot 에 이미 쓰인 --noteW 와 같으면 다시 쓰지 않는다.
- 폭 규칙은 그대로 지킨다: max(60, 가장 넓은 칸 폭+16), 칸이 하나도 없으면 아무것도 쓰지 않고 null 을 돌려준다, 보드마다 자기 noteRoot 에 쓴다. 비고 글이 짧아지면 폭도 줄어야 한다.
- 새 방식으로 잰 폭은 옛 방식(0px 를 쓴 뒤 scrollWidth)으로 잰 폭과 같아야 한다. 칸의 좌우 안쪽 여백은 계산 스타일에서 한 번 읽어 내용 폭에 더한다.
- 창 크기 조절 경로(layout 의 applyNoteWidth → syncCellSize)도 같은 함수를 써서 같은 규칙으로 잰다.
- 큰 견본(64마디 × 3층 × 300개, Chrome · 1440폭)에서 다시 재어 비고 칸 폭 재측정의 몫이 줄었는지 남긴다. deviations 의 「렌더 범위와 떠 있는 것들」 표에서 이 결함 줄을 고친 것으로 옮긴다.

## 결정 사항

- 측정을 어디까지 줄일까 — 한 번 읽기만으로 둘까, 행마다 폭을 기억해 그린 행만 다시 잴까
  - 가. 한 번 읽기 + 폭이 같으면 안 쓰기만 — 강제 리플로가 두 번에서 한 번이 되고, 폭이 그대로면 쓰기로 레이아웃이 흐트러지지도 않는다. 읽기는 여전히 칸 65개 전부를 본다. 캐시를 비울 때(창 크기 · 테마 · 비고 켜고 끄기 · 골격 다시 세우기)를 따질 일이 없다.
  - 나. 가에 더해 행마다 내용 폭을 기억 — 그린 행만 다시 재므로 좁힌 렌더에서 더 아낀다. 대신 테마 · 글꼴 · 미디어 쿼리 · 인쇄로 여백이 바뀔 때 캐시를 비울 자리를 모두 지켜야 하고, 하나라도 빠뜨리면 폭이 낡은 값으로 남는다. 지금은 전 행 렌더가 규칙(D-20)이라 아낄 몫도 작다.
  - **고른 답**: 가. 한 번 읽기 + 폭이 같으면 안 쓰기만

## 조심할 것

- deviations 는 「측정 절차를 바꾸면 폭이 달라진다」를 고치지 않은 까닭으로 적어 두었다. 감싸개 offsetWidth 는 정수로 반올림되고 여백은 소수 px 일 수 있어, 옛 scrollWidth 값과 1px 어긋날 수 있다. 실제 브라우저에서 메인 · 루틴 보드와 인쇄의 폭을 옛 값과 견주고, 리팩터링이 아니라 동작 변경 커밋으로 낸다.
- 감싸개를 inline-block 이 아닌 꼴로 두면 offsetWidth 가 칸 폭을 따라가 줄지 않는다. 그러면 0px 쓰기가 막던 「이전 폭이 하한이 되는」 결함이 돌아온다. 넓은 비고를 지운 뒤 폭이 줄어드는지 꼭 본다.
- renderRowNotes 가 낸 HTML 을 감싸개 안에 넣으므로, .note-cell 의 직계 자식을 고르는 CSS(인쇄의 '.note-cell *' 색 규칙, 테마 규칙)가 달라지지 않는지 본다. 인쇄에서 비고 열이 빠지거나 찍히는 문제는 RM-47 의 몫이니 이 일에서 함께 고치지 않는다.
- --noteW 는 보드마다 다른 noteRoot(#mainBoardWrap · #reBoardWrap)에 쓴다. 「같으면 안 쓰기」의 비교도 그 noteRoot 의 인라인 값과 해야 하고, documentElement 와 비교하면 안 된다.
- 리사이즈 경로가 루틴 보드는 다시 재지 않는 보존 비대칭 #14 는 그대로 둔다.
