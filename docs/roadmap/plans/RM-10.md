# RM-10 용어집과 라벨 문자열 표

## 풀어 본 설명 — 2026-09-29

화면에 나오는 낱말(안무표·영상·동작·루틴·구간·마커·마디·카운트 등)의 뜻과 쓰는 법을 용어집 한 장에 정하고, 버튼·툴팁·안내에 쓰는 한국어 글자를 파일 하나에 모은다. 지금은 같은 일을 곳에 따라 「지우기」·「삭제」로, 되돌리기를 `Undo` 로 부르는 등 말이 제각각이고 글자가 수십 개 파일에 흩어져 있다. 그래서 라벨을 바꿀 때마다 문서가 틀어지고 영어 UI(RM-32)도 시작할 수 없다.

### 무엇

사용자 눈에는 두 가지가 달라진다. 첫째, 같은 일은 어디서나 같은 말로 불린다. 되돌릴 수 있는 없애기는 「지우기」, 되돌릴 수 없는 없애기는 「삭제」로 가른다. 지금은 안무표 블록 팝업이 `× 지우기`, 루틴 블록 팝업이 `× 삭제`로 같은 일을 다르게 부른다. 영어로 된 `Undo`·`Redo` 는 되돌리기·다시 하기가 된다. 단축키 설정에는 이미 이 말을 쓰고 있다. `[ In 지금 여기`·`Out ] 지금 여기` 는 「시작점」·「끝점」으로 바뀌고, `프로젝트 저장` 은 자동 저장이 들어온 뒤의 실제 뜻대로 「파일로 내보내기」가 된다. 둘째, 문서 허브에 「용어집」 문서가 하나 생긴다. 낱말마다 뜻, 쓰는 자리, 헷갈리는 말과의 차이를 적는다. 화면 뒤에서는 라벨·툴팁 글자의 주인이 문자열 표 파일 하나가 된다. 버튼과 팝업은 그 표에서 글자를 받아 쓰고, 튜토리얼·기능 설명서의 라벨 인용도 그 표와 대조된다.

### 왜

라벨 글자가 `index.html` 과 `src/ui` 의 여러 파일에 흩어져 있다. 한 곳만 고치면 다른 곳이 옛말로 남고, 문서는 없어진 라벨을 인용한 채 병합된다. `동작 팔레트` → `동작 목록` 개명이 그랬고, 튜토리얼 첫 절이 사라진 화면을 설명하고 있던 일도 있었다. 없애는 말이 섞여 있으면 사용자는 되돌릴 수 있는지를 말만 보고 알 수 없다. 삭제에 확인이 없고 되돌리기가 유일한 안전망인 편집기에서 이 구분은 곧 안심의 문제다. 글자가 한 파일에 모여 있지 않으면 영어 UI(RM-32)는 파일 수십 개를 뒤지는 일이 된다. 로드맵은 기둥 C 가 끝났다고 말할 조건으로 「라벨 문자열의 주인이 파일 하나」와 「문서의 인용을 그 파일과 대조해 통과」를 적었다.

### 어떻게

- 용어집을 먼저 쓴다. 화면의 명사(안무표·영상·동작·루틴·구간·마커·마디·카운트·박자)와 동사(지우기·삭제·비우기·초기화·내보내기·저장)마다 뜻 하나를 정한다. 기준은 로드맵 기둥 C 의 한 줄, 곧 「되돌릴 수 있으면 지우기, 없으면 삭제」다.
- 지금 화면을 훑어 용어집과 어긋나는 라벨 목록을 만든다(`× 지우기`/`× 삭제`, `Undo`/`Redo`, `[ In 지금 여기`, `프로젝트 저장`, 안내 문장 속 `Undo 로 되돌릴 수 있습니다` 등).
- 문자열 표 파일을 둔다. 안쪽 계층에 순수 데이터로 두어 ui·input 이 모두 읽을 수 있게 한다. RM-09 의 명령 등록부가 이미 명령의 라벨·툴팁 열을 들고 있으므로, 명령이 아닌 글자(제목·플레이스홀더·안내·확인 문구)만 이 표로 모으고 등록부는 이 표의 키를 가리키게 한다.
- 첫 걸음은 구조 커밋이다. 버튼·팝업이 글자를 직접 쓰지 않고 표에서 받게 옮기되, 화면의 글자는 한 자도 바꾸지 않는다. 골든과 단위 시험은 그대로 통과해야 한다. `index.html` 의 정적 버튼은 표의 키를 달고 부팅 때 채운다.
- 그다음 동작 변경 커밋에서 용어집대로 개명한다. 같은 커밋에서 튜토리얼·기능 설명서의 인용을 함께 고친다(CLAUDE.md 의 「라벨을 바꾸면 문서 둘을 함께」).
- RM-06 이 만든 라벨 인용 검사는 화면 글자를 긁어 오던 방식을 버리고 이 표를 읽도록 바꾼다. 문서에 인용된 라벨이 표에 없으면 붉어진다.
- 용어집 문서를 문서 등록표에 한 줄 더해 앱의 `문서` 버튼에서 읽히게 한다.

### 갈리는 대목

- 「삭제 = 되돌릴 수 없음」에서 휴지통으로 가는 것은 어느 쪽인가
  - 말 둘: 앱의 되돌리기로 돌아오면 지우기, 아니면 모두 삭제 — 휴지통에서 복구되는 안무표 삭제도 「삭제」다. 규칙이 단순하다. 대신 「삭제」라는 말이 실제보다 무섭게 들려, 복구 길이 있다는 것이 말에 드러나지 않는다.
  - 말 셋: 지우기(되돌리기) · 휴지통으로(복구) · 영구 삭제 — 사용자가 말만 보고 얼마나 돌이킬 수 있는지 안다. 파괴적 조작 규칙(메뉴 안 + `정말요?`)을 영구 삭제에만 걸 수 있다. 대신 낱말이 하나 늘고 라벨이 길어진다.
- 문자열 표가 무엇까지 담나
  - 라벨·툴팁·플레이스홀더만 — M 크기에 맞는다. 문서 인용 대조가 깔끔해진다. 긴 안내 문장과 오류 문구는 제자리에 남으므로 영어 UI(RM-32) 때 한 번 더 모아야 한다. 안내 문장은 RM-19 가 걷어낼 것이기도 하다.
  - 안내 문장·오류·토스트 문구까지 전부 — RM-32 의 준비가 끝까지 된다. 대신 크기가 L 로 커지고, 변수가 끼는 문장(`N개를 놓았습니다`)을 함수로 담는 틀을 함께 정해야 한다. RM-04·RM-19 가 만지는 문구와도 겹친다.
- 표를 처음부터 언어별로 짤까 — 시장 언어(Q3, RM-32 쪽)가 아직 정해지지 않았다
  - 한국어 한 벌만, 키로 찾는 꼴 — 지금 필요한 만큼만 짓는다. 영어를 더할 때 같은 키로 한 벌을 옆에 놓으면 된다. 언어 고르기 설정은 RM-32 에서 만든다.
  - `ko`·`en` 두 칸의 틀과 언어 고르기를 지금 — 빈 영어 칸이 번역할 거리를 보여 준다. 대신 영어권을 먼저 노릴지 결정하기 전에 틀부터 굳는다. 영어 칸이 비거나 틀리게 남을 수 있다.

### 조심할 것

- 옮기기와 고치기를 섞지 않는다. 표로 옮기는 커밋에서는 화면 글자가 한 자도 바뀌지 않아야 하고, 개명은 따로 동작 변경 커밋으로 낸다. 섞으면 어느 라벨이 실수로 바뀌었는지 가려낼 수 없다.
- 라벨을 바꾸면 튜토리얼·기능 설명서가 통째로 틀린 문서가 된다. 개명 커밋마다 두 문서를 함께 고치고, 라벨 인용 검사(RM-06, 이 항목에서 표를 읽도록 바뀜)가 통과해야 넘어간다.
- 계층 규칙: ui 와 input 은 서로 import 하지 않는다. 문자열 표는 둘이 모두 읽을 수 있는 안쪽(순수 데이터)에 두어야 한다. ui 안에 두면 input 이 못 읽는다.
- `index.html` 의 정적 버튼(89개)을 부팅 때 채우면, 스크립트가 늦거나 깨졌을 때 빈 버튼이 뜬다. 원래 글자를 HTML 에 남기고 표가 덮어쓰게 할지, 검사로 둘을 대조할지 정한다.
- 단축키 설정에 저장된 명령 id 와 문자열 키를 섞지 않는다. 키 이름을 바꾸면 사용자의 옛 단축키 설정이 조용히 기본값으로 돌아간다(RM-09 의 같은 주의).
- RM-09 의 명령 등록부와 라벨을 두 곳에 적지 않는다. 명령 라벨의 주인은 하나여야 한다. 등록부가 표의 키를 가리키게 하거나, 표가 등록부를 흡수한다.

### 판의 옛 설명

> 화면 낱말을 용어집 하나로 정하고 라벨 문자열의 주인을 파일 하나로 둔다. 지우기와 삭제처럼 헷갈리는 말을 가르고 영어 UI 의 준비가 된다.
