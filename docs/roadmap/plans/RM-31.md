# RM-31 안무표에서 고른 구간을 영상으로 잘라 내보내기

## 풀어 본 설명 — 2026-09-29

안무표에서 블록이나 마디를 고르면, 그 대목에 해당하는 영상만 잘라 새 영상 파일로 만든다. 지금은 영상 쪽에서 In/Out 시각을 손으로 찍어야만 자를 수 있다. 박자를 이미 맞춰 두었으니 「이 여섯 마디」라고 고르기만 하면 초 구간은 앱이 계산하게 하려는 것이다.

### 무엇

안무표에서 블록 하나나 여러 개, 또는 마디 범위를 고르고 「이 대목 영상으로 잘라내기」 단추를 누르면, 서버가 그 대목만 담은 MP4 를 클립 보관 폴더에 새로 만든다. 새 파일은 영상 패널의 클립 목록에 곧바로 뜬다. 파일 이름에는 초가 아니라 마디·블록 이름이 들어간다(예: 「원본 [5–8마디 Shim Sham].mp4」). 이 기능은 박자가 맞춰져 있고, 서버에 보관된 파일 영상이 열려 있고, ffmpeg 이 설치되어 있을 때만 켜진다. 하나라도 빠지면 단추가 잠기고 왜 잠겼는지 한 줄로 알려 준다. 영상 패널의 기존 「✂ 잘라서 새 클립으로」가 In/Out 기준으로 자르는 것이라면, 이 기능은 같은 일을 안무표 쪽에서 시작하는 반대 방향이다.

### 왜

특정 대목만 따로 보고 싶거나, 연습 파트너나 강사에게 「이 여덟 마디」만 보내고 싶을 때가 흔하다. 그런데 지금은 영상 패널에서 재생 위치를 옮겨 가며 In 과 Out 을 손으로 찍어야 한다. 박자는 이미 맞춰져 있어서 앱은 마디와 초를 서로 바꿀 줄 안다(블록을 누르면 영상이 그 시각으로 가는 것도 이 덕분이다). 그런데도 사람이 초를 다시 재는 것은 헛수고이고, 찍다 보면 한두 박씩 어긋나기도 한다. 로드맵의 옛 「영상 잘라 내보내기」 가운데 영상 쪽 자르기는 2026-09-10 에 들어갔고, 이 항목은 남은 절반이다.

### 어떻게

- 고른 블록(또는 마디 범위)을 박자 정보로 초 구간 [시작, 끝) 으로 바꾼다. 블록 하나를 초 구간으로 바꾸는 순수 함수와 여러 조각을 한 구간으로 묶는 함수가 이미 있고, 여러 블록이면 맨 앞 시작부터 맨 뒤 끝까지를 잡는다(사이 빈틈은 그냥 포함 — 이미 있는 규칙).
- 앞뒤 여유(몇 카운트), 0초보다 앞선 구간 자르기, 영상 길이보다 긴 구간 자르기 같은 계산은 도메인의 순수 함수로 두고 단위 시험으로 덮는다.
- 서버는 이미 있는 자르기 API(POST /api/clips/trim, ffmpeg 재인코딩)를 그대로 쓴다. 파일 이름을 마디·블록 이름으로 짓도록 이름 인자 하나만 받게 하는 정도가 고칠 거리다.
- 기존 영상 쪽 자르기는 만든 파일로 지금 영상을 갈아 끼우고 박자와 마커를 앞으로 당긴다. 내보내기는 그렇게 하면 안 된다. 지금 영상과 박자는 그대로 두고 새 클립을 목록에 더하기만 하는 별도 유스케이스를 둔다.
- 단추는 우선 영상 패널의 자르기·마커 구획에 둔다(선택으로 마커를 만드는 단추 옆). RM-14 의 선택 액션 바가 서면 거기에도 같은 명령을 건다.
- 잠김 조건(박자 미설정 · 유튜브나 브라우저 폴더 모드 · ffmpeg 없음 · 선택 없음)마다 안내 문구를 둔다. 라벨이 새로 생기므로 TUTORIAL · FEATURES 를 함께 고친다.

### 손댈 자리

- 도메인 박자 계산 — 블록·묶음을 초 구간으로 바꾸는 함수에 앞뒤 여유·범위 자르기를 더한 구간 계산
- 영상 유스케이스 — 지금 영상을 바꾸지 않고 클립 목록에만 더하는 「내보내기 결과 받기」
- 클립 서버 어댑터 — 자르기 요청에 파일 이름 인자
- server.py 자르기 핸들러 — 이름 인자 받기(선택)
- 영상 패널 — 자르기·마커 구획의 새 단추와 잠김 안내, 선택 구간 계산(마커 단추가 쓰는 것을 재사용)
- 조립(main) — 단추를 어댑터 호출·커밋에 잇는다
- index.html 단추 마크업, 튜토리얼 · 기능 설명서

### 갈리는 대목

- 잘라 낸 파일을 어떻게 쓰나 — 지금 영상을 갈아 끼울까, 곁에 둘까
  - 곁에 둔다(추천) — 새 클립은 목록에 더해지고 지금 영상·박자·마커는 그대로다. 여러 대목을 연달아 뽑을 수 있다. 기존 In/Out 자르기와 결과가 달라진다는 점을 문서에 적는다.
  - 갈아 끼운다 — 기존 자르기와 같은 동작이다. 박자가 당겨지므로 안무표의 다른 대목과 영상 싱크가 끊긴다. 「내보내기」라기보다 「이 대목만 남기기」가 된다.
  - 브라우저로 내려받기까지 — 보관 폴더에 만든 뒤 바로 다운로드도 띄운다. 남에게 보내는 쓰임에 편하지만 같은 파일이 두 곳에 생긴다.
- 구간 경계 — 박자 그대로 자를까, 앞뒤에 여유를 붙일까
  - 앞에 1~2카운트 여유(추천) — 첫 동작의 준비 움직임과 음악 들어가는 자리가 보인다. 블록을 누르면 조금 앞에서 재생을 시작하는 지금 동작과도 맞는다.
  - 정확히 박자대로 — 계산이 단순하고 마디 수와 영상 길이가 딱 맞는다. 다만 영상 첫 프레임이 이미 동작 중간이 되기 쉽다.
  - 설정으로 둔다 — 여유 카운트 수를 ⚙ 설정이나 단추 옆 칸에서 고른다. 사람마다 원하는 것이 갈리는 값이라 후보가 되지만, 설정 한 칸이 늘어난다.
- 무엇을 고를 수 있나 — 지금의 블록 선택만인가, 마디 범위도인가
  - 지금 있는 블록 선택으로 먼저(추천) — RM-14 를 기다리지 않고 바로 된다. 여러 블록을 고르는 것은 아직 클릭으로 하나씩 더하는 방식이다.
  - RM-14 뒤로 미룬다 — 범위 선택·마퀴·선택 액션 바가 선 뒤에 그 바의 단추 하나로 만든다. 모양은 깔끔하지만 이 항목에 선행이 하나 생긴다.

### 조심할 것

- 기존 자르기 유스케이스(applyTrim)를 그대로 부르면 지금 영상이 바뀌고 박자·마커가 당겨진다. 내보내기는 이것을 쓰지 말고 별도 경로로 가야 한다.
- 박자 기준점보다 앞선 마디는 초가 음수로 나오고, 영상 끝을 넘는 마디도 있을 수 있다. 서버는 0초 이상, 0.1초 이상 길이만 받으므로 앱에서 먼저 잘라 맞추고 알린다.
- 보정점이 여럿인 가변 템포에서는 카운트를 초로 바꾸는 계산이 구간마다 다르다. 시험에 가변 템포 견본을 꼭 넣는다.
- 유튜브 영상이나 서버 없이 연 브라우저 폴더 모드에서는 자를 파일이 서버에 없다. 단추를 잠그고 이유를 보여야 한다(ffmpeg 이 없을 때의 501 도 같다).
- 재인코딩이라 긴 구간은 수십 초가 걸린다. 그동안 단추를 잠그고 「잘라내는 중…」을 보인다(기존 자르기의 busy 상태를 재사용).
- 새 단추 라벨이 생기므로 TUTORIAL · FEATURES 를 같은 PR 에서 고친다. RM-06(라벨 대조 검사)이 먼저 들어오면 거기서도 잡힌다.

### 판의 옛 설명

> 안무표에서 고른 마디·블록을 템포로 초 구간으로 바꿔 영상으로 잘라 낸다. 영상 쪽 자르기와 변환 재료는 이미 있다.
