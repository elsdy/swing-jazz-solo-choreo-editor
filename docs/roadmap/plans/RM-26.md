# RM-26 예제 안무 · 첫 실행 코치마크 · 맥락 도움말 ?

처음 켠 사람이 빈 격자 앞에서 멈추지 않게 세 가지를 둔다. 하나는 저장 포맷 그대로의 예제 안무로, 불러오기와 같은 길(최근 목록에서 여는 길)로 연다. 둘은 처음 한 번만 뜨는 코치마크 3장, 셋은 문서 창의 그 절로 곧장 가는 `?` 단추다. 판의 RM-19(상시 안내 문장 걷기)와는 안내 틀을, RM-20(영상 패널 재배치)·RM-36(빠른 배치 표시)과는 채우기 줄 · 영상 단계의 자리를, RM-10(라벨 표)과는 문구를 겹쳐 쓴다. 다만 앞 항목의 코드를 부르지는 않으므로 모두 점선 선행으로 둔다.

크기 M · 2026-10-13 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 처음 앱을 켠 사람이 빈 격자 앞에서 멈추지 않도록 세 가지를 둔다. 첫째, 바로 열어 볼 수 있는 예제 안무 하나다. 둘째, 처음 한 번만 뜨고 채우기 줄 → 동작 목록 → 영상 차례로 짚어 주는 안내 말풍선(코치마크) 3장이다. 셋째, 화면 곳곳에 두는 `?` 단추로, 누르면 설명서의 해당 절로 곧장 연다. 지금은 만든 사람만 쓸 줄 알고, 설치형 포장(RM-28)보다 「처음 켠 사람이 10분 안에 쓸 수 있는가」가 먼저라서 이 항목을 앞에 둔다.

## 요구

- 8마디 표준 루틴(Shim Sham 같은 것)의 예제 안무를 저장 포맷 그대로의 정적 JSON 으로 저장소에 둔다. 공개 영상 링크와 박자를 담고, 서버 없이 정적 호스팅에서도 fetch 로 읽혀 열린다
- 빈 안무표 안내를 네 갈래 나열에서 한 걸음(「예제를 열어 보거나, 영상을 넣으세요」)으로 줄이고 곁에 `예제 열기` 를 둔다. 안무표가 비었으면 바로 열고, 내용이 있으면 `정말요?` 확인(confirmOnce)을 거친다. 연 뒤 되돌리기 한 번이면 연 앞의 상태로 돌아간다
- 처음 켠 사람에게 코치마크 3장(① 채우기 줄 ② 동작 목록 ③ 영상)을 차례로 띄운다. 한 번 본 뒤에는 뜨지 않는다. 3장의 차례 · 문구 · 대상 요소 id 는 표 한 곳에 적고, 말풍선은 위치가 아니라 id 로 붙인다
- ⚙ 설정에 「처음 한 번 안내 다시 보기」를 둔다. 기본값은 켬(처음 한 번만)이다
- 아직 쓸 수 없는 입구(LLM 키가 없는 `✨ 말로 채우기`, 서버가 없어 막힌 것)를 흐리게 두고 까닭을 한 줄 적는다. 판정은 이미 있는 서버 유무 · LLM 상태를 읽고 새로 만들지 않는다
- 영상 패널의 단계, 파일 메뉴, 팝업에 작은 `?` 를 붙인다. 누르면 문서 창이 튜토리얼이나 기능 설명서의 그 절로 열린다. 단추마다 가리킬 문서 id · 앵커는 표 한 곳에 모은다
- `?` 표의 앵커가 실제 문서에 있는지 문서 검사(check-docs)가 재고, 없으면 붉어진다
- 문서 등록부의 갈래 넷을 「도움말」(튜토리얼 · 기능 · 바뀐 것)과 「개발」 둘로 다시 묶는다. 「개발」은 목록에서 평소에 숨기되, 문서끼리의 링크로는 열린다
- 튜토리얼 · 기능 설명서의 첫 절을 예제와 코치마크 차례에 맞춰 고쳐 쓴다. 지금은 거짓인 「새로고침하면 안무표는 비워진다」(작업 중 문서는 2026-09-20 부터 되살아난다)도 고친다
- `btnInvite` 깜빡임은 코치마크가 가리키는 대상에서만 쓴다

## 순서

- examples/shim-sham.json 을 저장 포맷 그대로 만든다(8마디 · 공개 영상 링크 · bpm). exampleChoreo.test.mjs 의 「저장 포맷 검사를 통과」 시험을 먼저 쓰고 초록으로 만든다
- main.js 에 openExample 을 둔다: fetch → loadProjectFromRecent 와 같은 길 → 커밋. 빈 표가 아니면 confirmOnce 를 거친다. 「되돌리기 한 번이면 돌아간다」 시험을 돌린다
- index.html 의 boardEmpty 문구를 한 걸음으로 줄이고 `예제 열기` 단추를 둔다. createModeBar 가 단추를 openExample 에 잇고, entryStates 로 막힌 입구를 흐리게 해 까닭을 title · 한 줄로 단다. modeBar.test.mjs 를 돌린다
- localStore 에 loadCoachSeen/saveCoachSeen 을 두고, coachmarks.js 에 3장 표와 흐름(시작 · 다음 · 건너뛰기 · 다시 보기)을 저장소 주입으로 만든다. 말풍선은 대상 id 로 붙이고, btnInvite 깜빡임은 지금 가리키는 대상에만 준다. coachmarks.test.mjs 를 돌린다
- main.js 의 startCoachmarks 를 부팅 끝(작업 중 문서 되살리기 뒤)에 부른다. 되살린 안무표가 있으면 ① 대신 ② 부터 띄울지는 표의 조건으로 둔다
- createSettingsView 에 「처음 한 번 안내 다시 보기」 단추를 두고 coachmarks 의 다시 보기를 주입받는다
- helpLinks.js 에 `?` 표(단추 id → 문서 id · 앵커)를 두고, index.html 의 영상 단계 summary · 파일 메뉴에 data-help 단추를 단다. createDocsHub 가 문서 전체의 [data-help] 누름을 위임받아 open(docId, anchor) 한다. createFileMenu 의 메뉴 안 `?` 도 같은 표를 쓴다
- check-docs 에서 anchorsOf 를 다시 써 helpLinks 표의 앵커를 대조하고, checkDocs.test.mjs 의 ? 앵커 시험 둘을 돌린다
- DOC_GROUPS 를 도움말/개발 둘로 고치고 DOCS 의 group 을 옮긴다. createDocsHub 목록은 「개발」을 접어 숨기되 링크 · URL 로는 연다. check-docs 의 갈래 검사와 갈래 시험을 돌린다
- TUTORIAL 「첫 실행」·「결과 받기」와 FEATURES 첫 절을 새 화면에 맞춰 고쳐 쓰고, HISTORY 에 한 줄을 더한다. node tools/check-docs.mjs 로 라벨 대조를 돌린다
- /pre-pr-docs 를 돌리고, 폰 폭에서 말풍선이 엄지 바와 겹치는지 브라우저로 본다

## 확인 시나리오

병합 뒤 눈으로 볼 사람 확인 줄이 생기면 브라우저 노드가 main 커밋의 임시 보드(예시 판 — 프로젝트 {pid}, 이 항목은 {item})에서 이 걸음을 따라 하며 영상을 찍는다(B667). 할 것: open(열기) · click(누르기) · type(적기) · wait(기다리기) · see(보임 확인).

| 걸음 | 할 것 | 대상 | 값 | 기대 |
|---|---|---|---|---|
| 1 | open | #/p/{pid}/{item} | — | 항목 화면이 열린다 |
| 2 | see | #boardEmpty | 예제 | 빈 안무표 안내가 한 걸음 문장과 `예제 열기` 단추로 보인다 |
| 3 | click | text=예제 열기 | — | 8마디 예제가 격자에 놓이고 영상 링크 · 박자가 함께 들어온다 |
| 4 | see | .coachmark | 채우기 | 처음 켠 브라우저에서 첫 코치마크가 채우기 줄을 가리킨다 |
| 5 | click | text=다음 | — | 둘째 장이 동작 목록을, 셋째 장이 영상을 가리킨다 |
| 6 | click | [data-help] | — | 문서 창이 튜토리얼이나 기능 설명서의 그 절로 열린다 |
| 7 | see | .docs-group-label | 도움말 | 문서 목록에 「도움말」 갈래만 펴져 있고 「개발」은 숨어 있다 |

## 조심할 것

- 예제 열기가 사용자 안무를 말없이 덮으면 안 된다. 부팅의 작업 중 문서 되살리기는 비어 있을 때만 되살리는데, 예제를 그 전에 열면 되살릴 것을 예제가 이긴다. 그래서 `예제 열기` 는 되살리기(clipServerReady 뒤)가 끝난 다음에만 누를 수 있게 둔다
- 되살리기는 History.reset 으로 바닥을 새로 깐다. 예제를 연 뒤의 Undo 가 그 바닥 아래(빈 표)로 내려가지 않는지, 반대로 예제 앞으로는 돌아가는지 시험에서 함께 잰다
- ui 계층은 localStorage 를 만지지 못한다(check-arch). 본 기록은 adapters/localStore 에 두고 main 이 주입한다. 예제 fetch 도 main(조립)에서 한다
- 코치마크 대상 · `?` 단추를 id 로 붙여도 RM-20(영상 패널 재배치) · RM-18(아이콘) · RM-36(빠른 배치)이 같은 마크업을 고친다. id 존재 시험으로 붙들고, 같은 index.html 자리를 고치는 항목과는 차례를 맞춘다
- 「개발」 갈래를 숨겨도 문서끼리의 링크 · URL 해시로는 열려야 한다. docsByGroup 을 고칠 때 resolveDoc · idForFileName 은 건드리지 않는다
- `✨ 말로 채우기` 의 막힘 판정은 composeView · llmServer 가 이미 쥔 상태를 읽어야 한다. 그 함수 이름은 구현 때 확인하고, 새 판정을 짓지 않는다

## 다시 다듬기 전의 계획서

### RM-26 예제 안무 · 첫 실행 코치마크 · 맥락 도움말 ?

#### 풀어 본 설명 — 2026-09-29

처음 앱을 켠 사람이 빈 격자 앞에서 멈추지 않도록 세 가지를 둔다. 첫째, 바로 열어 볼 수 있는 예제 안무 하나다. 둘째, 처음 한 번만 뜨고 채우기 줄 → 동작 목록 → 영상 차례로 짚어 주는 안내 말풍선(코치마크) 3장이다. 셋째, 화면 곳곳에 두는 `?` 단추로, 누르면 설명서의 해당 절로 곧장 연다. 지금은 만든 사람만 쓸 줄 알고, 설치형 포장(RM-28)보다 「처음 켠 사람이 10분 안에 쓸 수 있는가」가 먼저라서 이 항목을 앞에 둔다.

##### 무엇

빈 안무표 안내가 지금은 채우는 방법 네 가지를 나열한다. 이것을 한 걸음(「예제를 열어 보거나, 영상을 넣으세요」)으로 줄이고, 그 곁에 「예제 열기」를 둔다. 예제는 Shim Sham 같은 표준 루틴 8마디로 한다. 공개 영상 링크와 박자가 들어 있어서, 열자마자 받아 적기·박자·반복이 어떻게 보이는지 드러난다. 강사에게는 그대로 교재가 된다. 처음 켠 사람에게는 코치마크 3장이 차례로 뜬다. ① 채우기 줄 ② 동작 목록 ③ 영상. 한 번 본 뒤에는 뜨지 않는다. 키가 없거나 서버가 없어 아직 쓸 수 없는 입구는 흐리게 두고 까닭을 한 줄 적는다. 영상 패널의 단계, 팝업, 파일 메뉴에는 작은 `?` 를 붙인다. 누르면 문서 창이 튜토리얼이나 기능 설명서의 그 절로 바로 열린다. 문서 창의 갈래는 「도움말」(튜토리얼·기능·바뀐 것)과 「개발」로 나누고, 「개발」은 평소에 숨긴다.

##### 왜

지금 앱은 저자 한 사람이 쓰는 도구로 자랐다. 그래서 처음 켠 사람은 빈 격자와 버튼 여러 개 앞에서 어디부터 누를지 모른다. 게다가 채우기 줄의 첫 버튼인 `✨ 말로 채우기` 는 LLM 키가 있어야 돌아간다. 처음 쓰는 사람에게는 가장 먼저 눈에 띄는 입구가 막다른 길인 셈이다. 설명서는 있지만 「문서」 단추를 눌러 목차에서 찾아야 해서, 막힌 자리에서 바로 닿지 않는다. 문서 목록에도 원칙·버그 기록·아키텍처 같은 개발용 글이 섞여 있어서 사용자가 읽을 글이 묻힌다. 예제 하나가 있으면 무엇을 만드는 도구인지를 말보다 먼저 결과물로 보여 줄 수 있다.

##### 어떻게

- 예제 안무는 저장 포맷 그대로의 정적 JSON 파일로 저장소에 둔다. 서버 없이 정적 호스팅으로 열어도 fetch 로 읽어 불러오기와 같은 길로 연다.
- 예제를 열면 지금 안무를 덮어쓰는 셈이므로, 빈 안무표일 때만 바로 연다. 내용이 있으면 버튼을 `정말요?` 로 바꾸는 확인 방식을 따른다.
- 코치마크는 대상 요소에 붙는 말풍선 하나와 「본 기록」(브라우저 저장소의 표시 하나)으로 만든다. 3장의 순서와 문구는 표 한 곳에 적는다.
- 쓸 수 없는 입구는 이미 있는 판정(서버 유무·LLM 키 유무)을 읽어 흐리게 두고 까닭을 적는다. 새 판정 로직은 만들지 않는다.
- ⚙ 설정에 「처음 한 번 안내 다시 보기」를 둔다. 코치마크는 눈에 띄는 것이라 사람마다 원하는 것이 갈린다. 기본값은 켬(처음 한 번만)을 권한다.
- `?` 단추는 문서 창의 open(문서, 앵커)을 부른다. 이 함수는 이미 앵커를 받으므로, 단추마다 가리킬 문서 id 와 앵커를 한 표에 모은다.
- 그 앵커가 실제 문서에 있는지는 문서 검사(check-docs)가 확인하게 한다. 문서 제목이 바뀌어 `?` 가 허공을 가리키는 일을 막는다.
- 문서 등록부의 갈래 넷(시작하기·기능과 사용법·바뀐 것·만드는 사람을 위해)을 「도움말」과 「개발(숨김)」 둘로 다시 묶는다.
- 튜토리얼의 첫 절을 예제와 코치마크 순서에 맞춰 고쳐 쓴다. 이제는 거짓이 된 「새로고침하면 비워진다」 같은 문장도 이때 고친다.

- 코치마크가 가리키는 버튼 자리는 RM-20(영상 패널 재배치)·RM-09(명령 등록부)·RM-18(아이콘)에서 바뀐다. 요소를 위치가 아니라 id 로 붙여야 흔들리지 않는다.
- 폰에서는 말풍선이 엄지 바·좁은 화면과 겹친다. 폰 화면을 따로 확인한다.
- 문서 갈래를 「도움말/개발」로 바꾸면 docsRegistry 와 check-docs 의 등록 검사도 함께 고쳐야 한다. 「개발」을 숨겨도 링크로는 열리게 둔다(문서끼리 서로 링크한다).
- 화면 문구가 바뀌므로 튜토리얼·기능 설명서를 같은 PR 에서 고친다(CLAUDE.md 「화면에 적힌 글자」).
