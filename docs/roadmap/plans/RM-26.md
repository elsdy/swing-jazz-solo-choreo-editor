# RM-26 예제 안무 · 첫 실행 코치마크 · 맥락 도움말 ?

## 풀어 본 설명 — 2026-09-29

처음 앱을 켠 사람이 빈 격자 앞에서 멈추지 않도록 세 가지를 둔다. 첫째, 바로 열어 볼 수 있는 예제 안무 하나다. 둘째, 처음 한 번만 뜨고 채우기 줄 → 동작 목록 → 영상 차례로 짚어 주는 안내 말풍선(코치마크) 3장이다. 셋째, 화면 곳곳에 두는 `?` 단추로, 누르면 설명서의 해당 절로 곧장 연다. 지금은 만든 사람만 쓸 줄 알고, 설치형 포장(RM-28)보다 「처음 켠 사람이 10분 안에 쓸 수 있는가」가 먼저라서 이 항목을 앞에 둔다.

### 무엇

빈 안무표 안내가 지금은 채우는 방법 네 가지를 나열한다. 이것을 한 걸음(「예제를 열어 보거나, 영상을 넣으세요」)으로 줄이고, 그 곁에 「예제 열기」를 둔다. 예제는 Shim Sham 같은 표준 루틴 8마디로 한다. 공개 영상 링크와 박자가 들어 있어서, 열자마자 받아 적기·박자·반복이 어떻게 보이는지 드러난다. 강사에게는 그대로 교재가 된다. 처음 켠 사람에게는 코치마크 3장이 차례로 뜬다. ① 채우기 줄 ② 동작 목록 ③ 영상. 한 번 본 뒤에는 뜨지 않는다. 키가 없거나 서버가 없어 아직 쓸 수 없는 입구는 흐리게 두고 까닭을 한 줄 적는다. 영상 패널의 단계, 팝업, 파일 메뉴에는 작은 `?` 를 붙인다. 누르면 문서 창이 튜토리얼이나 기능 설명서의 그 절로 바로 열린다. 문서 창의 갈래는 「도움말」(튜토리얼·기능·바뀐 것)과 「개발」로 나누고, 「개발」은 평소에 숨긴다.

### 왜

지금 앱은 저자 한 사람이 쓰는 도구로 자랐다. 그래서 처음 켠 사람은 빈 격자와 버튼 여러 개 앞에서 어디부터 누를지 모른다. 게다가 채우기 줄의 첫 버튼인 `✨ 말로 채우기` 는 LLM 키가 있어야 돌아간다. 처음 쓰는 사람에게는 가장 먼저 눈에 띄는 입구가 막다른 길인 셈이다. 설명서는 있지만 「문서」 단추를 눌러 목차에서 찾아야 해서, 막힌 자리에서 바로 닿지 않는다. 문서 목록에도 원칙·버그 기록·아키텍처 같은 개발용 글이 섞여 있어서 사용자가 읽을 글이 묻힌다. 예제 하나가 있으면 무엇을 만드는 도구인지를 말보다 먼저 결과물로 보여 줄 수 있다.

### 어떻게

- 예제 안무는 저장 포맷 그대로의 정적 JSON 파일로 저장소에 둔다. 서버 없이 정적 호스팅으로 열어도 fetch 로 읽어 불러오기와 같은 길로 연다.
- 예제를 열면 지금 안무를 덮어쓰는 셈이므로, 빈 안무표일 때만 바로 연다. 내용이 있으면 버튼을 `정말요?` 로 바꾸는 확인 방식을 따른다.
- 코치마크는 대상 요소에 붙는 말풍선 하나와 「본 기록」(브라우저 저장소의 표시 하나)으로 만든다. 3장의 순서와 문구는 표 한 곳에 적는다.
- 쓸 수 없는 입구는 이미 있는 판정(서버 유무·LLM 키 유무)을 읽어 흐리게 두고 까닭을 적는다. 새 판정 로직은 만들지 않는다.
- ⚙ 설정에 「처음 한 번 안내 다시 보기」를 둔다. 코치마크는 눈에 띄는 것이라 사람마다 원하는 것이 갈린다. 기본값은 켬(처음 한 번만)을 권한다.
- `?` 단추는 문서 창의 open(문서, 앵커)을 부른다. 이 함수는 이미 앵커를 받으므로, 단추마다 가리킬 문서 id 와 앵커를 한 표에 모은다.
- 그 앵커가 실제 문서에 있는지는 문서 검사(check-docs)가 확인하게 한다. 문서 제목이 바뀌어 `?` 가 허공을 가리키는 일을 막는다.
- 문서 등록부의 갈래 넷(시작하기·기능과 사용법·바뀐 것·만드는 사람을 위해)을 「도움말」과 「개발(숨김)」 둘로 다시 묶는다.
- 튜토리얼의 첫 절을 예제와 코치마크 순서에 맞춰 고쳐 쓴다. 이제는 거짓이 된 「새로고침하면 비워진다」 같은 문장도 이때 고친다.

### 손댈 자리

### 갈리는 대목

- 첫 대상과 시장 언어(결정 대기 Q3 — 「RM-26 을 시작할 때」 정하기로 했다)
  - 혼자 배우는 댄서 · 국내 — 예제는 연습용 루틴이 되고, 코치마크는 「영상 보며 받아 적기」를 중심에 둔다. 한국어 문구만 쓰면 되어 작게 끝난다.
  - 강사 · 국내 — 예제는 교재 꼴(파트·반복 표시·카운트 시트)이어야 해서 RM-21(카운트 시트)·RM-23(파트)과 가까워진다. 코치마크도 「가르칠 자료 만들기」 쪽으로 간다.
  - 영어권까지 — 코치마크·`?`·예제 문구를 처음부터 문자열 표로 빼야 해서 RM-10(용어집·라벨 표)·RM-32(영어 UI)가 선행처럼 된다. 크기가 M 을 넘는다.
- 「처음 한 번」 안내의 틀을 RM-19(상시 안내 문장 걷기)와 어떻게 나눌까
  - RM-26 이 틀을 먼저 세운다 — 말풍선과 본 기록의 틀이 여기서 서고, RM-19 는 걷은 문장을 그 틀에 옮겨 담기만 한다. 틀이 한 벌로 남는다. 대신 상태줄(RM-19)이 그만큼 늦어진다.
  - RM-19 가 최소 틀을 세우고 이 항목은 3장만 얹는다 — RM-19 계획서의 첫 선택지다. 안내 문장을 걷는 날 설명이 사라지지 않는다. 대신 RM-19 가 커지고, 이 항목은 그 뒤로 밀린다.
- 예제에 딸린 영상을 무엇으로 할까
  - 공개 유튜브 링크만 적는다 — 저장소가 가볍고 저작권 걱정이 적다. 대신 영상이 내려가면 예제가 반쪽이 되고, 오프라인이나 서버 없는 폰에서는 영상 없이 격자만 보인다.
  - 직접 찍은 짧은 클립을 함께 넣는다 — 언제나 영상이 열리고 설치형 앱(RM-28)에도 그대로 들어간다. 대신 저장소·설치본이 무거워지고, 누가 찍어 어떤 권리로 넣을지를 정해야 한다.

### 조심할 것

- 예제를 여는 동작이 사용자의 안무를 말없이 덮으면 안 된다. 빈 안무표일 때만 바로 열고, 아니면 한 번 더 확인받는다. 되돌리기(Undo)에서 예제 이전 상태로 돌아가는지도 시험한다(RM-07 유령 단계와 닿는다).
- `?` 가 가리키는 앵커는 문서 제목이 바뀌면 조용히 깨진다. check-docs 가 잡게 해야 한다. 라벨을 인용한 문서와 코드를 대조하는 RM-06 과 같은 검사기에 두는 편이 맞다.
- 코치마크가 가리키는 버튼 자리는 RM-20(영상 패널 재배치)·RM-09(명령 등록부)·RM-18(아이콘)에서 바뀐다. 요소를 위치가 아니라 id 로 붙여야 흔들리지 않는다.
- 폰에서는 말풍선이 엄지 바·좁은 화면과 겹친다. 폰 화면을 따로 확인한다.
- 문서 갈래를 「도움말/개발」로 바꾸면 docsRegistry 와 check-docs 의 등록 검사도 함께 고쳐야 한다. 「개발」을 숨겨도 링크로는 열리게 둔다(문서끼리 서로 링크한다).
- 화면 문구가 바뀌므로 튜토리얼·기능 설명서를 같은 PR 에서 고친다(CLAUDE.md 「화면에 적힌 글자」).
