# RM-67 튜토리얼 맥 첫 실행 안내가 지금 macOS 와 어긋남

튜토리얼 「설치형 앱으로 켠다」의 맥 줄을 고친다. 지금은 .dmg 안에서 `안무 편집기` 를 끌라고 하는데 Finder 에는 「SwingChoreo」로 보이고, 첫 길로 내세운 「오른쪽 단추 → 열기」는 macOS 15 부터 서명 안 된 앱에서 막혔다. 그래서 시스템 설정 → 개인정보 보호 및 보안의 「그래도 열기」를 첫 길로 올리고, 앱 이름은 화면에 보이는 것과 맞춘다. 같은 경고 안내가 packaging/README.md 에도 있어 판의 RM-68(포장 README 의 아직 재지 못한 것 갱신)과 그 파일이 겹친다.

## 다시 다듬기 전의 설명

> RM-28 마무리에서 잼: ① 튜토리얼 「설치형 앱으로 켠다」는 .dmg 에서 `안무 편집기` 를 끌어 넣으라 하지만 Finder 는 앱을 「SwingChoreo」로 보인다(Info.plist 의 CFBundleDisplayName 만 안무 편집기, lproj 없음 — Finder displayed name 을 osascript 로 잼). ② 첫 안내가 「오른쪽 단추 → 열기」인데, macOS 15(Sequoia)부터 서명 · 공증 안 된 앱은 Control-클릭 열기로 넘길 수 없고 시스템 설정 → 개인정보 보호 및 보안 → 「그래도 열기」만 된다(애플 발표 근거 — 화면으로는 재지 못함). 이 맥 · mac-mini 는 macOS 27. 「그래도 열기」를 첫 길로, 이름은 화면과 맞게(또는 앱 파일 이름을 바꾸게).

## 요구

- 튜토리얼이 .dmg 에서 끌어 넣으라고 적은 앱 이름이 Finder 에 실제로 보이는 이름과 같다
- 맥 첫 실행 안내의 첫 길은 시스템 설정 → 개인정보 보호 및 보안 맨 아래의 「그래도 열기」다. 그다음 뜨는 확인 창에서 다시 「그래도 열기」를 누르고 암호를 넣는다는 데까지 적는다
- 「오른쪽 단추 → 열기」는 첫 길에서 내리고, macOS 14 이하에서만 되는 길이라고 밝힌다(또는 지운다)

- Finder 이름을 앱 쪽에서 맞추기로 하면 build.py 가 맥 앱 묶음에 한국어 이름 표를 넣어 Finder 에 「안무 편집기」가 보이게 한다

## 결정 사항

- Finder 에 보이는 앱 이름과 튜토리얼 글자를 어느 쪽에 맞출까 — 지금 Info.plist 는 보이는 이름만 「안무 편집기」이고 한국어 이름 표가 없어, Finder 에는 묶음 이름 「SwingChoreo」가 보인다(설명의 osascript 측정
  - 앱을 문서에 맞춘다 — build.py 가 ko.lproj 이름 표를 넣어 Finder 에 「안무 편집기」가 보이게 — 튜토리얼 · 윈도우 시작 메뉴 · 「켜져 있음」 창의 이름이 모두 「안무 편집기」로 하나가 된다. build.py 한 함수와 그 시험이 늘고, 다시 지은 .dmg 로 손 점검이 한 번 더 필요하다. 한국어가 아닌 언어로 쓰는 맥에서는 여전히 SwingChoreo 로 보인다
  - 문서를 앱에 맞춘다 — 튜토리얼에 「SwingChoreo(안무 편집기)」로 적는다 — 문서 두 곳만 고쳐 가장 작다. 대신 Finder 이름과 독(Dock) · 창 제목의 이름이 계속 갈린다
  - 앱 파일 이름 자체를 「안무 편집기.app」으로 바꾼다 — 어느 언어로 쓰는 맥에서나 같게 보인다. 하지만 PyInstaller --name · .dmg 파일 이름 · 윈도우 iss 의 AppName 까지 한글 경로가 되어 빌드와 설치 경로가 덜 굳는다
  - **고른 답**: 앱을 문서에 맞춘다 — build.py 가 ko.lproj 이름 표를 넣어 Finder 에 「안무 편집기」가 보이게
- 「그래도 열기」로도 막히는 경우의 터미널 길(xattr 로 격리 표시를 지우는 것)을 튜토리얼에 적을까
  - 적지 않는다 — 시스템 설정의 길 하나만 둔다 — 튜토리얼이 손 조작만으로 끝난다. 드물게 막히는 사람은 README 를 보거나 직접 묻는다
  - 문제 해결 표에 한 줄로 둔다 — 막힌 사람이 혼자 풀 수 있다. 다만 보안 경고를 일괄로 우회하는 명령을 사용자 문서에 싣게 되고, 손으로 재 보지 못한 문장이 하나 는다
  - **고른 답**: 적지 않는다 — 시스템 설정의 길 하나만 둔다

## 조심할 것

- macOS 15 이상에서 Control-클릭 열기가 막힌다는 것은 애플 발표가 근거이고 화면으로 재지 않았다. 이 맥(macOS 27)에서 지은 .dmg 를 격리 표시가 붙은 채(내려받기 · AirDrop 으로 옮겨) 한 번 따라가 보고 단추 글자(「그래도 열기」 · 확인 창 차례)를 맞춘다. 로컬에서 지은 것은 격리 표시가 없어 경고 자체가 뜨지 않는다
- 이름 표는 finish_mac 의 codesign 다시 봉하기 전에 넣어야 한다. 뒤에 넣으면 봉인이 깨져 「손상되었기 때문에 열 수 없습니다」로 막힌다(build.py 의 ⚠ 주석과 같은 함정)
- 튜토리얼에서 백틱으로 인용한 `안무 편집기` 는 check-docs 의 라벨 대조를 받는다. OS 화면 글자(「그래도 열기」 · 「개인정보 보호 및 보안」)는 지금처럼 「」 로 적어야 화면 라벨 검사에 걸리지 않는다
- packaging/README.md 는 RM-68 도 고치는 파일이다. 경고 넘기기 문단만 건드려 겹침을 줄인다
