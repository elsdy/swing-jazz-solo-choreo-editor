# RM-20 영상 패널을 「차례」와 「도구」로 · 유튜브 주소를 ① 로

영상 패널의 여섯 단계를 둘로 가른다. 차례대로 하는 ①②③만 번호와 ✓를 달고, 구간 자르기 · 마커 · 자세 분석은 번호 없는 「도구」 탭으로 뺀다. 유튜브 주소 칸은 링크 줄에서 `① 영상 고르기` 안으로 옮기고, ②는 「탭 → BPM 확인 → 첫 박」 한 줄로 좁힌다. 처음 온 사람이 영상을 어디에 넣는지, 어디서 멈춰도 되는지 화면에서 읽히게 하려는 것이다. 같은 패널의 안내 줄을 걷는 RM-19와 겹친다. 패널 뼈대를 이 항목이 먼저 세우면 RM-19가 새 자리에 맞춰 한 번에 옮긴다.

크기 M · 2026-10-13 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 영상 패널에 섞여 있는 여섯 단계를 가른다. 차례대로 하는 ①영상 고르기 · ②박자 맞추기 · ③받아 적기만 번호와 완료 표시를 달고, 필요할 때만 꺼내 쓰는 구간 자르기 · 마커 · 자세 분석은 「도구」 탭으로 뺀다. 유튜브 주소 칸도 안무표 위 `🔗 링크` 줄에서 `① 영상 고르기` 안으로 옮긴다. 그래야 처음 온 사람이 영상을 어디서 넣는지 찾아 헤매지 않는다.

## 요구

- 패널 위쪽 「차례」에는 ①영상 고르기 · ②박자 맞추기 · ③받아 적기 셋만 번호와 완료 ✓를 달고 남는다. 아래쪽 「도구」는 구간 잡고 잘라내기 · 마커 · 자세 분석을 번호도 ✓도 없는 탭으로 두고, 한 번에 하나만 펼친다
- 유튜브 주소 칸(같은 입력칸 · 제목 칩 · ✕)을 링크 줄에서 `① 영상 고르기` 맨 위로 옮긴다. 링크 줄에는 ClickUp과 직접 더한 링크만 남는다. 저장 파일의 링크 데이터 모양은 바꾸지 않는다
- `② 박자 맞추기`에 처음 보이는 것은 탭 → BPM 확인 → 첫 박 한 줄이다. 두 점 앵커 · 직접 입력 · 보정점은 「세로선이 어긋날 때」라는 접힌 칸 아래로 내려간다(지금의 `고급` 칸을 넓힌다)
- 좁은 화면의 눕힌 띠에서는 작업 차례 줄이 ①②③만 화살표로 잇는다. 「단계를 하나만 연다」 규칙은 도구 탭까지 함께 지켜 안무표가 밀려나지 않는다
- 도구 탭에서도 작업 차례 기록과 단계별 할 일은 지금 열쇠(step4~6) 그대로 쌓이고 그대로 보인다. 이미 저장된 할 일이 갈 곳을 잃지 않는다
- 마커의 `이 마디에 맵핑`은 앵커 칸이 접혀 있어도 마디를 고를 수 있다
- 단계 이름을 가리키는 안내 문구(BPM 배지 · 엄지 바 · 받아 적기 밀림 경고 · `⚙ 설정 → 작업 차례` 표 · 파일 놓기 버튼의 「링크바」 문구)가 새 이름과 새 자리를 가리킨다
- 기능 설명서와 튜토리얼의 영상 패널 절 · 링크 줄 설명을 새 자리와 라벨에 맞춘다

## 결정 사항

- 유튜브 칸을 옮긴 뒤 `🔗 링크` 줄을 어떻게 둘까
  - 링크 줄에서 유튜브를 아예 뺀다 — 주소를 넣고 보는 곳이 `① 영상 고르기` 하나가 된다. 링크 줄은 ClickUp · 커스텀만 두는 참고 칸이 되고, 유튜브 주소만 든 파일을 열어도 링크 줄이 펴지지 않는다
  - 링크 줄에 주소와 제목을 읽기 전용으로 남긴다 — 패널을 안 연 사람도 「이 안무의 영상」을 본다. 대신 보여 주는 자리가 둘이 되어 라벨 · 모양을 두 곳에서 함께 고쳐야 한다
  - **고른 답**: 링크 줄에서 유튜브를 아예 뺀다
  - **근거**: 💰 절약 검토자 — 요구 2가 링크 줄에는 ClickUp과 커스텀만 남는다고 적었고 시험도 linksBar 안에 없음을 잰다. · 관점 범위
- 앵커 칸을 접은 뒤 마커의 `이 마디에 맵핑`은 마디를 어디서 고를까
  - 마커 탭에 마디 고르기 칸을 따로 둔다 — ②를 접어도 마커만으로 일이 끝난다. 「첫 박이 어느 마디인가」와 「이 구간이 어느 마디인가」는 뜻이 달라 칸이 둘이어도 같은 상태를 두 번 두는 것이 아니다
  - 지금처럼 ②의 `여기가` 칸을 그대로 읽는다 — 코드는 그대로지만 마커를 쓰려면 ②의 접힌 칸을 펴야 한다. 버튼 title의 「위 '여기가' 칸」이 보이지 않는 자리를 가리킨다
  - **고른 답**: 마커 탭에 마디 고르기 칸을 따로 둔다
  - **근거**: 💰 절약 검토자 — 요구 6이 앵커 칸이 접혀도 마디를 고를 수 있어야 한다고 적었으므로 마커 탭에 칸을 따로 둔다. · 관점 범위

## 조심할 것

- 단계 열쇠가 지금은 마크업 위치 차례(`step${i+1}`, `.video-body > .vstep`)다. ④⑤⑥을 다른 그릇으로 옮기면 열쇠가 끊기거나 밀린다. 그러면 이미 저장된 할 일(stepTodos의 step4~6)과 2026-10-05 판정에 쓰던 작업 차례 기록이 갈 곳을 잃는다. 열쇠는 data-step으로 박아 둔다
- 영상 iframe은 DOM에서 부모가 바뀌면 다시 읽혀 재생이 끊긴다. 탭으로 다시 짤 때 프레임 칸은 옮기지 않는다
- 띠의 「하나만 연다」 규칙(openOnlyStep · toggle 핸들러)이 차례 셋만 보면 도구 탭이 함께 펼쳐져 폰에서 안무표가 밀려난다
- linksBarView는 #youtubeUrlInput · #ytUrlGroup · #ytResetBtn을 id로 묶는다. 칸을 새로 만들지 말고 같은 엘리먼트를 옮겨야 저장 · 제목 불러오기가 그대로 산다. 링크 줄 전용 CSS(.link-row · .yt-url-group)가 새 자리에서 깨지지 않는지 본다
- `✕ 파일 놓기` title(「링크바의 유튜브 주소로 돌아갑니다」)과 `🔗 링크` title(「YouTube · ClickUp」)이 없어진 자리를 가리킨다
- 기능 설명서 · 튜토리얼에서 자리만 옮겨 간 설명은 check-docs가 잡지 못한다(라벨 글자는 그대로 남으므로). 눈으로 다시 읽는다

## 다시 다듬기 전의 계획서

### RM-20 영상 패널을 「차례」와 「도구」로 · 유튜브 주소를 ① 로

#### 풀어 본 설명 — 2026-09-29

영상 패널에 섞여 있는 여섯 단계를 가른다. 차례대로 하는 ①영상 고르기 · ②박자 맞추기 · ③받아 적기만 번호와 완료 표시를 달고, 필요할 때만 꺼내 쓰는 구간 자르기 · 마커 · 자세 분석은 「도구」 탭으로 뺀다. 유튜브 주소 칸도 안무표 위 `🔗 링크` 줄에서 `① 영상 고르기` 안으로 옮긴다. 그래야 처음 온 사람이 영상을 어디서 넣는지 찾아 헤매지 않는다.

##### 무엇

영상 패널의 위쪽은 「차례」가 된다. ①영상 고르기 → ②박자 맞추기 → ③받아 적기 세 단계만 남고, 단계마다 번호가 붙으며 끝나면 ✓ 표시가 켜진다. 아래쪽은 「도구」 탭이다. 구간 잡고 잘라내기 · 마커 · 자세 분석을 탭으로 골라 한 번에 하나만 펼친다. 이 셋에는 번호도 완료 표시도 없다. 차례를 따라가는 일이 아니라 필요할 때 여는 연장이기 때문이다. `① 영상 고르기`를 열면 맨 위에 유튜브 주소 칸이 있고, 그 옆에 `📁 영상 파일 열기`와 영상 목록이 선다. 링크 줄에는 ClickUp과 직접 더한 링크만 남는다. `② 박자 맞추기`도 좁힌다. 처음 보이는 것은 「탭으로 두드리기 → BPM 확인 → 첫 박 찍기」 한 줄뿐이다. 두 점 앵커(`여기가 ○마디의 ○카운트 · 지금 여기`), 직접 입력, 보정점은 「세로선이 어긋날 때」라는 접힌 칸 아래로 내려간다. 좁은 화면에서 영상 밑에 눕혀 보이는 작업 차례 줄도 ①②③만 화살표로 잇는다.

##### 왜

지금은 여섯 단계가 같은 모양으로 늘어서 있다. 그래서 반드시 차례대로 해야 하는 ①②③과, 없어도 되는 ④⑤⑥이 구별되지 않는다. 처음 온 사람은 ⑥까지 다 해야 끝나는 줄 알거나, 어디서 멈춰도 되는지 모른다. 코드도 이미 ④⑤⑥을 「끝났다고 말하지 않는다」며 따로 다루는데, 화면은 이 구분을 보여 주지 않는다. 유튜브 주소는 사정이 더 나쁘다. 영상 패널이 영상을 받는 유일한 입구인데 패널 안에는 주소 칸이 없고, 안무표 위 `🔗 링크`를 눌러 펼쳐야 보인다. 그곳은 ClickUp 같은 참고 링크를 두는 층이라, 영상을 넣으려는 사람이 거기까지 찾아가지 않는다. 박자 맞추기도 비슷하다. 두 점 찍기 · 탭 · 직접 입력 · 보정점 네 길이 한꺼번에 펼쳐져 있어 무엇부터 할지 고르게 만든다. 이 항목은 기둥 C(무엇이 어디 있는지 배울 만하게)의 한 조각이다. 목표는 「같은 일은 한 자리」를 영상 패널에서 이루는 것이다.

##### 어떻게

- index.html에서 여섯 단계를 두 묶음으로 가른다. 「차례」 쪽에는 ①②③ 세 개를 지금처럼 접고 펴는 칸으로 두고, 「도구」 쪽에는 ④⑤⑥ 을 탭 머리와 탭 몸으로 다시 짠다.
- 유튜브 주소 입력 칸을 링크 줄에서 `① 영상 고르기` 안으로 옮긴다. 칸을 하나 더 만들지 않고 같은 칸을 옮긴다. 주소가 두 곳에 있으면 어느 쪽이 진짜인지 갈린다(영상 패널의 원칙 「상태를 두 곳에 두지 않는다」).
- 주소를 저장하고 제목을 불러오는 쪽(링크 명령 · 링크 줄 뷰)은 칸의 자리만 바뀌었다고 보고 그대로 쓴다. 저장 파일의 모양(링크 데이터)은 바꾸지 않는다.
- ②를 「탭 → 확인 → 첫 박」 한 줄로 좁힌다. 두 점 앵커 · 직접 입력 · 보정점은 「세로선이 어긋날 때」 접힌 칸으로 내린다. 지금 있는 `고급` 칸을 넓혀 받아들이는 모양이다.
- 영상 패널의 단계 목록 · 완료 판정 · 눕힌 띠의 작업 차례 줄이 ①②③만 보게 고친다. 지금은 패널 바로 밑의 모든 단계를 읽는다.
- 완료 표시는 지금 판정을 그대로 쓴다. ①은 영상이 있으면, ②는 쓸 수 있는 박자가 있으면, ③은 놓인 블록이 있으면 끝이다.
- `② 박자 맞추기`, `③ 받아 적기` 같은 단계 이름을 가리키는 안내 문구(BPM 배지, 엄지 바, 받아 적기 경고)가 여전히 맞는지 대조한다.
- 라벨과 자리가 바뀌므로 기능 설명서와 튜토리얼의 영상 패널 절을 같은 PR에서 고친다. 두 문서에는 지금 「패널 안에 주소를 넣을 곳은 없다」고 적혀 있다.
- 골든(격자 알고리즘)은 건드리지 않는 화면 개편이다. 네 검사가 모두 통과하는지만 본다.
