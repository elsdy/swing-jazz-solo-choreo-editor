# RM-18 아이콘 한 벌(SVG 스프라이트)

버튼 라벨 앞의 이모지와 유니코드 기호를 index.html 안의 SVG 스프라이트 한 벌로 바꾼다. 아이콘 이름은 명령 등록부에 새 열로 단다. 등록부는 RM-09로 이미 병합되어 있다. 이모지는 OS마다 다르게 그려지고 글자색과 테마를 따르지 않아 화면을 가장 촌스럽게 만든다. 판의 RM-10(라벨 문자열 표), RM-20(영상 패널 단계 머리), RM-36(빠른 배치 버튼)과 같은 라벨을 만지고, 크기와 색은 RM-17 토큰이 오면 그 토큰을 따른다.

크기 L · 2026-10-13 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 지금 버튼 라벨 앞에 붙은 이모지 29개(✨ 📁 🎤 같은 컬러 그림과 ▶ ⤢ ▮ 같은 흑백 기호가 한 줄에 섞여 있다)를 모양이 고른 SVG 아이콘 한 벌로 바꾼다. 이모지는 OS마다 다르게 그려지고, 어두운 바탕 위에서 채도가 튀어 화면을 가장 촌스럽게 만든다. 글자 라벨이 주인이고 아이콘은 옆에서 돕기만 한다.

## 요구

- 아이콘 정의를 index.html 맨 앞의 숨은 SVG 한 덩어리(<symbol>)에 모은다. 모든 아이콘은 같은 viewBox와 선 굵기를 쓰고 색은 currentColor라서 글자색과 테마를 따른다
- 명령 등록부의 명령마다 아이콘 이름 열을 둔다. 등록부의 버튼 글자에서 이모지를 걷고, data-command 버튼과 엄지 바가 그 열에서 아이콘을 그린다
- 등록부 밖에서 JS가 만드는 버튼(말로 채우기, 설정, 프레이즈, 루틴 팝업 편집, 동작 정하기, 영상 패널의 상태 버튼, 연습 바 재생, 자세 따라 그리기)도 ui 계층의 작은 도우미로 아이콘과 글자 칸을 함께 만든다
- 상태에 따라 라벨이 바뀌는 자리(마이크 켜기/끄기, 말하기/그만 듣기, 크게/제자리로, PiP 켜기/끄기, 잘라내는 중, 재생/멈춤, 다른 파일 열기)는 글자 칸만 바꾸고 아이콘을 지우지 않는다
- 글자 없이 기호만 있던 버튼(✕ 빼기, ✎ 이름 바꾸기, ✏ 루틴 편집, ▶ 클립 재생)에 aria-label과 title을 채워 접근 가능한 이름이 남게 한다
- 스타일시트가 content:로 그리는 기호(잠금 🔒/🔓, 서랍 ▸/▾)와 영상 패널 단계 머리의 data-icon도 같은 한 벌에서 가져온다
- 라벨이 다시 이모지로 시작하면 원칙 검사기가 붉어진다
- 튜토리얼, 기능 설명서, 영상→안무표 안내의 라벨 인용을 새 글자에 맞춘다
- 어두운 테마와 밝은 테마 모두에서 아이콘이 글자와 같은 색과 높이로 줄에 맞는다

## 순서

- 목록부터 만든다: index.html 라벨, 등록부의 button, ui의 textContent 라벨, CSS content:, data-icon을 모아 기호마다 갈 아이콘 이름을 표로 계획서에 적는다
- index.html 맨 앞에 숨은 스프라이트와 아이콘 스타일(높이 1em, currentColor, 글자와 세로 가운데)을 둔다. icon.test.mjs의 스프라이트 시험을 쓴다
- src/ui/icon.js에 아이콘+글자 버튼을 만드는 도우미와 글자 칸만 가는 도우미를 만든다. icon.test.mjs의 도우미 시험과 check-arch를 돌린다
- 등록부에 icon 열을 더하고 button 글자에서 이모지를 걷는다. commandFace가 아이콘을 내주게 하고 마크업의 data-command 버튼을 <svg><use>+<span> 꼴로 바꾼다. commandButtons.test.mjs를 돌린다
- 채우기 줄과 앱바(말로 채우기, 프레이즈, 설정)와 엄지 바를 옮기고, 그 라벨을 인용하는 문서를 함께 고쳐 커밋한다. check-docs를 돌린다
- 영상 패널(상태 라벨, 단계 머리 data-icon, 클립 목록의 기호 버튼)과 연습 바, 자세 분석을 옮긴다. 기호만 있던 버튼에 aria-label과 title을 채운다. 문서 인용과 함께 커밋한다
- 루틴 팝업, 루틴 목록, 블록 팝업과 스타일시트 content: 기호(잠금, 서랍)를 옮긴다. CSS는 스프라이트를 부를 수 없으니 mask 꼴로 둔다. icon.test.mjs의 스타일 시험을 돌린다
- check-principles의 RULES에 「라벨이 이모지로 시작」 규칙을 더하고, 일부러 어긴 조각이 붉어지는 시험을 checkPrinciples.test.mjs에 둔다. PRINCIPLES.md에 원칙을 적는다
- /pre-pr-docs로 기능 설명서, 튜토리얼, 이력, 로드맵 문서와 판 JSON을 맞춘다

## 결정 사항

- 아이콘을 어디에 둘까 — 이모지가 있던 자리만, 주요 명령 전부
  - 이모지나 기호가 있던 자리만 바꾸고, 없던 버튼은 글자만 둔다 — 「글자가 주인」에 가장 충실하다. 아이콘 수가 적어 크기가 지금 계획에 머문다. 아이콘이 있는 버튼과 없는 버튼이 섞인다
  - 등록부의 주요 명령 전부에 아이콘을 단다 — 줄이 고르게 보이고 폰에서 글자를 숨겨도 알아본다. 대신 그릴 아이콘이 늘고 뜻이 모호한 아이콘이 생긴다
  - **고른 답**: 이모지나 기호가 있던 자리만 바꾸고, 없던 버튼은 글자만 둔다
  - **근거**: 💰 절약 검토자 — 무엇이 「이모지·기호가 있던 자리」만 바꾸라 했고 요구 2도 그 자리만 다룬다. · 관점 범위
- ✕ ↑ ↓ ▸ ▾ 같은 단순 흑백 기호도 SVG로 바꿀까
  - 라벨 앞의 기호와 기호만 있는 버튼은 바꾸고, 정렬 방향 ↑/↓와 서랍 ▸/▾처럼 글자 속 방향 표시는 둔다 — 튀는 것과 굵기가 어긋나는 것은 사라진다. CSS mask로 옮길 자리는 잠금 하나로 줄어든다

## 조심할 것

- 이모지를 걷으면 문서의 백틱 인용 200곳 가까이가 check-docs에서 붉어진다. 구역마다 그 구역의 인용을 같은 커밋에서 고친다. 옛 라벨을 이력으로 말할 때는 「」로 적는다
- textContent로 라벨을 통째로 바꾸는 자리(영상 패널, 말로 채우기, 엄지 바의 render, 연습 바)가 아이콘을 지운다. 목록에 빠짐없이 넣고 글자 칸 도우미로만 바꾼다
- commandButtons 시험은 마크업 글자와 등록부 button을 견준다. 버튼 안에 svg가 들어오면 글자 칸만 견주도록 고쳐야 빈 손 통과나 거짓 붉음이 없다
- CSS content:와 mask는 스프라이트를 부를 수 없어 같은 경로를 두 번 적게 된다. 두 벌이 갈리지 않게 시험으로 묶는다
- golden-adapter가 루틴 칩을 `▶ 이름`으로 그린다. 칩의 글자를 바꾸면 골든이 깨지므로 동작 변경 커밋으로 따로 내거나, CSS 쪽에서만 바꾼다
- adapters의 clockPlayer는 ui 도우미를 import할 수 없다(계층 규칙). 그 제목 기호는 글자만 걷거나 범위에서 뺀다

## 다시 다듬기 전의 계획서

### RM-18 아이콘 한 벌(SVG 스프라이트)

#### 풀어 본 설명 — 2026-09-29

지금 버튼 라벨 앞에 붙은 이모지 29개(✨ 📁 🎤 같은 컬러 그림과 ▶ ⤢ ▮ 같은 흑백 기호가 한 줄에 섞여 있다)를 모양이 고른 SVG 아이콘 한 벌로 바꾼다. 이모지는 OS마다 다르게 그려지고, 어두운 바탕 위에서 채도가 튀어 화면을 가장 촌스럽게 만든다. 글자 라벨이 주인이고 아이콘은 옆에서 돕기만 한다.

##### 무엇

화면에 새 기능은 생기지 않는다. 버튼과 단계 제목 앞의 그림만 바뀐다. `✨ 말로 채우기` · `▶ 영상으로 채우기` · `✋ 직접 놓기` · `🎵 프레이즈` · `🔗 링크` · `📁 영상 파일 열기` · `🎤 마이크 켜기` · `▮ 끊기` · `■ 그만` · `✂ 잘라서 새 클립으로` · `⤢ 크게` · `⧉ PiP` · `✕ 닫기` 같은 라벨의 이모지를 선 굵기 · 크기 · 색이 같은 SVG 아이콘으로 바꾼다. 아이콘 색은 글자색을 따라가므로 테마를 바꾸면 함께 바뀐다. 영상 패널 단계 ①~⑥의 머리 기호(▶ ♪ ✎ ✂ ⚑ ◎), 스타일시트가 그리는 기호(잠금 🔒/🔓, 루틴 칩의 ▶, 끌기 손잡이 ⋮⋮)도 같은 한 벌에서 가져온다. 아이콘 정의는 `index.html` 안의 숨은 SVG 한 덩어리(`<symbol>` 스프라이트)에 모으고, 버튼은 그 이름을 불러 쓴다. 파일도 의존성도 늘지 않는다. 옮기는 순서는 눈이 먼저 가는 자리부터다 — 채우기 줄, 폰의 엄지 바, 영상 패널의 작업 차례 띠.

##### 왜

지금은 아이콘 체계가 없다. 누가 만들든 그때 떠오른 이모지나 유니코드 기호를 라벨 앞에 붙여 왔다. 그래서 같은 줄에 컬러 이모지와 흑백 기호가 섞이고, 맥 · 윈도 · 안드로이드마다 모양과 크기가 다르게 그려진다. 어두운 테마 위에서는 이모지 채도만 튀어서 로드맵 기둥 A가 꼽은 「촌스러움」의 가장 직접적인 원천이 됐다. 이모지는 글자색도 따르지 않아 테마를 바꿔도 그대로 남는다. 한 벌로 모으면 아이콘도 크기 · 색 토큰(RM-17)을 따르고, 새 버튼을 만들 때 고를 목록이 생겨 다시 흩어지지 않는다.

##### 어떻게

- 먼저 목록을 만든다 — HTML 라벨, JS가 `textContent` 로 적는 라벨(말로 채우기 팝업 · 루틴 팝업의 `✏ 편집` 등), CSS `content:` 로 그리는 기호, 단계 머리의 `data-icon` 을 모두 모아 어느 아이콘으로 갈지 표로 만든다
- RM-17이 정한 글자 크기 · 글자색 토큰에 맞춰 아이콘 크기(글자 한 단과 같은 높이)와 색(`currentColor`)을 정한다
- `index.html` 맨 앞에 숨은 `<svg>` 스프라이트를 두고 아이콘마다 `<symbol id>` 하나씩 적는다. 직접 그리거나 라이선스가 맞는 공개 아이콘 세트에서 베껴 넣는다. 의존성은 0이다
- HTML 버튼은 `<svg><use href="#…"></svg>` + 글자 `<span>` 꼴로 바꾼다. JS가 만드는 버튼용으로 ui 계층에 아이콘 요소를 만드는 작은 함수 하나를 둔다(ui와 input은 서로 import하지 않으므로 ui 안에 둔다)
- 라벨을 바꿔 쓰는 자리(마이크 `🎤 말하기` ↔ `⏹ 그만 듣기` 처럼 `textContent` 를 통째로 갈던 곳)는 글자 칸만 갈도록 고친다. 안 그러면 아이콘이 지워진다
- 글자 없이 기호만 있던 버튼(✕ · ⇄ · ✎ · ↑)은 `aria-label` · `title` 을 채워 화면 읽기 프로그램이 읽을 글자를 준다
- 구역(채우기 줄 → 엄지 바 → 영상 패널 → 나머지)마다 커밋을 나눈다. 라벨 글자가 바뀌므로 각 커밋에서 튜토리얼 · 기능 설명서의 인용을 함께 고친다
- 끝났는지 기계로 잰다 — 화면 문자열에서 이모지로 시작하는 라벨이 0개인지 세는 검사를 RM-05 검사기에 한 항목으로 넣는다

##### 손댈 자리

- `index.html` 스타일 — `content:` 로 그리는 기호(서랍 ▸/▾, 잠금 🔒/🔓, 루틴 칩 ▶, 끌기 손잡이 ⋮⋮), `.vstep` 머리 기호, 아이콘 크기 · 정렬 규칙

  - RM-09 뒤에 등록부의 열로 — 추천 — 명령마다 라벨 · 툴팁 · 단축키 옆에 아이콘 이름이 한 칸 붙는다. 같은 명령이 다섯 곳에 있어도 아이콘이 저절로 같아지고, Ctrl+K 팔레트에도 같은 아이콘이 뜬다. 로드맵이 정한 M1 순서(등록부 → … → 토큰 · 아이콘)와도 맞다. 대신 RM-09가 끝날 때까지 기다린다
  - 지금 버튼마다 직접 단다 — RM-17만 끝나면 바로 시작할 수 있다. 그러나 RM-09가 버튼을 표로 옮길 때 이 자리를 다시 한 번 모두 만진다

  - 주요 명령 전부에 아이콘 — 줄이 고르게 보이고 폰처럼 좁은 화면에서 글자를 숨겨도 알아볼 수 있다. 그리는 아이콘 수가 늘어 M 크기를 넘고, 뜻이 모호한 아이콘이 생긴다
- ✕ ▸ ↑ ← 같은 단순한 흑백 기호도 SVG로 바꿀까
  - 바꾼다 — 한 벌로 통일 — OS마다 굵기와 크기가 달라지는 문제까지 없어진다. 목록이 29개보다 늘고, 스타일시트의 `content:` 기호도 마스크나 배경 이미지로 옮겨야 한다
  - 컬러 이모지만 바꾸고 흑백 기호는 둔다 — 가장 튀는 것만 빨리 없앤다. 흑백 글꼴 기호는 글자색을 따르므로 테마 문제는 없지만, SVG 아이콘 옆에 놓이면 굵기가 어긋나 보일 수 있다

##### 조심할 것

- 라벨 글자가 바뀐다(`✨ 말로 채우기` → `말로 채우기`). CLAUDE.md가 경고한 대로 튜토리얼 · 기능 설명서가 통째로 틀린 문서가 된다. 라벨을 인용하는 문서 검사(RM-06)가 먼저 들어와 있으면 누락을 잡는다
- JS가 `textContent` 로 라벨을 통째로 바꾸는 자리(마이크 켜기/그만 듣기, 빠른 배치 토글 등)에서 아이콘이 지워지거나 옛 이모지가 돌아온다. 이런 자리를 목록에 빠짐없이 넣는다
- 버튼 글자로 요소를 찾는 시험이나 코드가 있으면 깨진다. 라벨이 아니라 id로 찾는지 먼저 확인한다
- 기호만 있던 버튼을 SVG로 바꾸면 접근 가능한 이름이 사라진다. `aria-label` 을 반드시 채운다
- `admin.html` 은 서버가 내는 화면이고 `src/` 를 import하지 않는다. 앱이 깨져도 떠야 하므로 스프라이트를 공유하지 말고 따로 베끼거나 범위에서 뺀다
- 공개 아이콘 세트를 베낀다면 라이선스를 함께 적는다. 앞으로 상용으로 낼 것이므로(M3) 표기 조건을 확인한다
