# RM-18 아이콘 한 벌(SVG 스프라이트)

## 풀어 본 설명 — 2026-09-29

지금 버튼 라벨 앞에 붙은 이모지 29개(✨ 📁 🎤 같은 컬러 그림과 ▶ ⤢ ▮ 같은 흑백 기호가 한 줄에 섞여 있다)를 모양이 고른 SVG 아이콘 한 벌로 바꾼다. 이모지는 OS마다 다르게 그려지고, 어두운 바탕 위에서 채도가 튀어 화면을 가장 촌스럽게 만든다. 글자 라벨이 주인이고 아이콘은 옆에서 돕기만 한다.

### 무엇

화면에 새 기능은 생기지 않는다. 버튼과 단계 제목 앞의 그림만 바뀐다. `✨ 말로 채우기` · `▶ 영상으로 채우기` · `✋ 직접 놓기` · `🎵 프레이즈` · `🔗 링크` · `📁 영상 파일 열기` · `🎤 마이크 켜기` · `▮ 끊기` · `■ 그만` · `✂ 잘라서 새 클립으로` · `⤢ 크게` · `⧉ PiP` · `✕ 닫기` 같은 라벨의 이모지를 선 굵기 · 크기 · 색이 같은 SVG 아이콘으로 바꾼다. 아이콘 색은 글자색을 따라가므로 테마를 바꾸면 함께 바뀐다. 영상 패널 단계 ①~⑥의 머리 기호(▶ ♪ ✎ ✂ ⚑ ◎), 스타일시트가 그리는 기호(잠금 🔒/🔓, 루틴 칩의 ▶, 끌기 손잡이 ⋮⋮)도 같은 한 벌에서 가져온다. 아이콘 정의는 `index.html` 안의 숨은 SVG 한 덩어리(`<symbol>` 스프라이트)에 모으고, 버튼은 그 이름을 불러 쓴다. 파일도 의존성도 늘지 않는다. 옮기는 순서는 눈이 먼저 가는 자리부터다 — 채우기 줄, 폰의 엄지 바, 영상 패널의 작업 차례 띠.

### 왜

지금은 아이콘 체계가 없다. 누가 만들든 그때 떠오른 이모지나 유니코드 기호를 라벨 앞에 붙여 왔다. 그래서 같은 줄에 컬러 이모지와 흑백 기호가 섞이고, 맥 · 윈도 · 안드로이드마다 모양과 크기가 다르게 그려진다. 어두운 테마 위에서는 이모지 채도만 튀어서 로드맵 기둥 A가 꼽은 「촌스러움」의 가장 직접적인 원천이 됐다. 이모지는 글자색도 따르지 않아 테마를 바꿔도 그대로 남는다. 한 벌로 모으면 아이콘도 크기 · 색 토큰(RM-17)을 따르고, 새 버튼을 만들 때 고를 목록이 생겨 다시 흩어지지 않는다.

### 어떻게

- 먼저 목록을 만든다 — HTML 라벨, JS가 `textContent` 로 적는 라벨(말로 채우기 팝업 · 루틴 팝업의 `✏ 편집` 등), CSS `content:` 로 그리는 기호, 단계 머리의 `data-icon` 을 모두 모아 어느 아이콘으로 갈지 표로 만든다
- RM-17이 정한 글자 크기 · 글자색 토큰에 맞춰 아이콘 크기(글자 한 단과 같은 높이)와 색(`currentColor`)을 정한다
- `index.html` 맨 앞에 숨은 `<svg>` 스프라이트를 두고 아이콘마다 `<symbol id>` 하나씩 적는다. 직접 그리거나 라이선스가 맞는 공개 아이콘 세트에서 베껴 넣는다. 의존성은 0이다
- HTML 버튼은 `<svg><use href="#…"></svg>` + 글자 `<span>` 꼴로 바꾼다. JS가 만드는 버튼용으로 ui 계층에 아이콘 요소를 만드는 작은 함수 하나를 둔다(ui와 input은 서로 import하지 않으므로 ui 안에 둔다)
- 라벨을 바꿔 쓰는 자리(마이크 `🎤 말하기` ↔ `⏹ 그만 듣기` 처럼 `textContent` 를 통째로 갈던 곳)는 글자 칸만 갈도록 고친다. 안 그러면 아이콘이 지워진다
- 글자 없이 기호만 있던 버튼(✕ · ⇄ · ✎ · ↑)은 `aria-label` · `title` 을 채워 화면 읽기 프로그램이 읽을 글자를 준다
- 구역(채우기 줄 → 엄지 바 → 영상 패널 → 나머지)마다 커밋을 나눈다. 라벨 글자가 바뀌므로 각 커밋에서 튜토리얼 · 기능 설명서의 인용을 함께 고친다
- 끝났는지 기계로 잰다 — 화면 문자열에서 이모지로 시작하는 라벨이 0개인지 세는 검사를 RM-05 검사기에 한 항목으로 넣는다

### 손댈 자리

- `index.html` — 스프라이트 정의, 캔버스 바 · 채우기 줄 · 링크 줄 · 영상 패널(단계 ①~⑥)의 버튼 라벨
- `index.html` 스타일 — `content:` 로 그리는 기호(서랍 ▸/▾, 잠금 🔒/🔓, 루틴 칩 ▶, 끌기 손잡이 ⋮⋮), `.vstep` 머리 기호, 아이콘 크기 · 정렬 규칙
- 말로 채우기 버튼과 팝업(`✨ 말로 채우기` · `🎤 말하기` · `⏹ 그만 듣기` · `✕ 닫기`)
- 루틴 팝업의 `✏ 편집`, 블록 위 `✎` 이름 정하기 손잡이
- 앱이 붙이는 앱바 버튼(`⚙ 설정` · `🎵 프레이즈`)과 폰 엄지 바(`≡ 동작`)
- 튜토리얼 · 기능 설명서 · 영상→안무표 안내의 라벨 인용(문서 전체에 이모지 라벨 인용이 200곳 가까이 있다)

### 갈리는 대목

- 아이콘을 명령 등록부(RM-09)의 한 열로 둘까, 버튼마다 따로 달까
  - RM-09 뒤에 등록부의 열로 — 추천 — 명령마다 라벨 · 툴팁 · 단축키 옆에 아이콘 이름이 한 칸 붙는다. 같은 명령이 다섯 곳에 있어도 아이콘이 저절로 같아지고, Ctrl+K 팔레트에도 같은 아이콘이 뜬다. 로드맵이 정한 M1 순서(등록부 → … → 토큰 · 아이콘)와도 맞다. 대신 RM-09가 끝날 때까지 기다린다
  - 지금 버튼마다 직접 단다 — RM-17만 끝나면 바로 시작할 수 있다. 그러나 RM-09가 버튼을 표로 옮길 때 이 자리를 다시 한 번 모두 만진다
- 모든 라벨에 아이콘을 둘까, 눈이 가는 자리에만 둘까
  - 이모지가 있던 29곳만 바꾸고, 없던 버튼은 글자만 둔다 — 추천 — 「글자가 주인」에 가장 충실하다. 아이콘이 드물어서 있는 자리가 도드라진다. 버튼 89개 가운데 아이콘이 있는 것과 없는 것이 섞인다
  - 주요 명령 전부에 아이콘 — 줄이 고르게 보이고 폰처럼 좁은 화면에서 글자를 숨겨도 알아볼 수 있다. 그리는 아이콘 수가 늘어 M 크기를 넘고, 뜻이 모호한 아이콘이 생긴다
- ✕ ▸ ↑ ← 같은 단순한 흑백 기호도 SVG로 바꿀까
  - 바꾼다 — 한 벌로 통일 — OS마다 굵기와 크기가 달라지는 문제까지 없어진다. 목록이 29개보다 늘고, 스타일시트의 `content:` 기호도 마스크나 배경 이미지로 옮겨야 한다
  - 컬러 이모지만 바꾸고 흑백 기호는 둔다 — 가장 튀는 것만 빨리 없앤다. 흑백 글꼴 기호는 글자색을 따르므로 테마 문제는 없지만, SVG 아이콘 옆에 놓이면 굵기가 어긋나 보일 수 있다

### 조심할 것

- 라벨 글자가 바뀐다(`✨ 말로 채우기` → `말로 채우기`). CLAUDE.md가 경고한 대로 튜토리얼 · 기능 설명서가 통째로 틀린 문서가 된다. 라벨을 인용하는 문서 검사(RM-06)가 먼저 들어와 있으면 누락을 잡는다
- JS가 `textContent` 로 라벨을 통째로 바꾸는 자리(마이크 켜기/그만 듣기, 빠른 배치 토글 등)에서 아이콘이 지워지거나 옛 이모지가 돌아온다. 이런 자리를 목록에 빠짐없이 넣는다
- 버튼 글자로 요소를 찾는 시험이나 코드가 있으면 깨진다. 라벨이 아니라 id로 찾는지 먼저 확인한다
- 기호만 있던 버튼을 SVG로 바꾸면 접근 가능한 이름이 사라진다. `aria-label` 을 반드시 채운다
- `admin.html` 은 서버가 내는 화면이고 `src/` 를 import하지 않는다. 앱이 깨져도 떠야 하므로 스프라이트를 공유하지 말고 따로 베끼거나 범위에서 뺀다
- 공개 아이콘 세트를 베낀다면 라이선스를 함께 적는다. 앞으로 상용으로 낼 것이므로(M3) 표기 조건을 확인한다
