# RM-30 자세 분석 결과 저장과 테이크 비교

분석이 끝나면 원본 관절점을 클립 곁 짝 파일로 서버에 남긴다. 다시 열면 분석하지 않고 되살리며, 두 테이크의 가동 범위 요약을 관절마다 전 → 후 · 차이로 견준다. 이 항목은 영상을 바꾸면 결과가 사라져 이미 만든 비교 계산(rom.compare)을 부를 자리가 없는 문제를 푼다. RM-29(연습 기록 줄의 잰 값 한 칸)와 RM-22(카운트 구간 문법)와 겹치되, 짝 파일 · 요약 표 · 클립끼리 비교는 둘 없이 먼저 선다.

크기 L · 2026-10-01 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 영상에서 잰 관절 각도를 저장해 두고, 같은 동작을 찍은 지난 테이크와 오늘 테이크를 나란히 견준다. 각도 계산, 모델, 영상 위 뼈대 그림은 이미 되어 있다. 하지만 결과가 어디에도 저장되지 않아 영상을 바꾸면 사라진다. 그래서 「무릎이 지난주보다 20° 더 열렸다」를 말할 수 없다.

## 요구

- 분석이 끝나면 원본 관절점을 클립 곁 짝 파일로 서버에 저장한다. 모델 이름 · 좌표계 · 화면 비율 · fps · 분석 구간 · 앵커도 함께 적는다
- 짝 파일이 있는 클립을 다시 열면 분석하지 않고 그 파일을 읽어 오버레이 · 궤적 · 앵커를 되살린다
- 자세 분석 구획에 가동 범위 요약 표를 보인다(관절별 범위 · 좌우 차 · 커버리지). 충분히 보지 못한 관절은 흐리게 두어 믿지 말라고 알린다
- 두 테이크를 골라 관절마다 전 → 후 · 차이를 보인다. 좌표계 · 모델 · 화면 비율이 다르면 비교를 거절한다
- 카운트별 요약은 그 클립의 템포로 만들고, 템포를 고치면 짝 파일에서 다시 만든다. 어느 템포로 만들었는지 함께 적는다
- 짝 파일은 클립 목록에 영상으로 끼지 않는다. 자르기로 생긴 새 클립에는 옛 짝 파일이 붙지 않는다
- 관절점은 store · 안무 파일 · 되돌리기 스냅샷에 들어가지 않는다. 분석을 안 쓴 사람의 저장 바이트는 그대로다
- 왼쪽 사이드바 영상 목록 줄에 분석해 둔 테이크를 표시하고, 그 줄에서 비교로 들어간다
- 튜토리얼 · 기능 설명서 · 포트 문서의 자세 분석 대목을 새 라벨에 맞춰 고친다

## 순서

- 갈림 ①은 저장소가 이미 답했다. poseReadiness가 서버 없이는 'no-server'를 내므로 분석 자체가 서버 경로에서만 된다. 그래서 짝 파일도 서버에만 두고, 정적 경로 대안과 RM-33 대기는 버린다
- 짝 파일 경로 규칙을 정한다. 클립 폴더 안 숨은 자리 `<subdir>/<프로젝트>/.pose/<클립 파일>.json`으로 두어 목록 · 정적 서빙에서 저절로 빠지게 하고, domain/clips.js와 server.py에 같은 모양으로 적는다
- server.py에 짝 파일 GET · PUT API를 더한다(_clip_file과 같은 루트 밖 거절). 자르기는 새 파일에 짝을 만들지 않는다. 서버 실물 시험 둘을 쓴다

- rom.js의 compare가 요약에 실린 model · aspect도 대조하게 하고, 요약 표 줄을 만드는 순수 함수를 더한다(동작 변경 커밋으로 시험과 함께)

## 결정 사항

- 두 테이크의 「같은 동작」을 무엇으로 맞대나
  - 마커 이름으로 맞댄다(추천) — 클립마다 이미 있는 마커(이름 + 카운트 구간)끼리 같은 이름을 짝짓는다. 박자가 조금 어긋나도 사람이 찍은 구간이라 엉뚱한 동작끼리 붙지 않는다. 마커가 없는 테이크는 전체만 견준다
  - 마디 · 카운트 구간으로 맞댄다 — 각 테이크 템포로 초를 카운트로 바꿔 같은 8x3~8x4를 견준다. RM-22 구간 문법과 같다. 다만 박자가 어긋난 테이크는 다른 동작끼리 견준다
  - 테이크 전체만 맞댄다 — 가장 싸고 먼저 낼 수 있다. 「어느 대목이 나아졌나」는 말하지 못한다
  - **고른 답**: 마커 이름으로 맞댄다(추천)
- 가동 범위 요약을 어디에 두나
  - 짝 파일에만 둔다(추천) — 안무 파일 포맷이 바뀌지 않고 RM-29를 기다리지 않는다. 요약은 원본에서 언제든 다시 만든다. 대신 남에게 준 안무 파일에는 잰 값이 따라가지 않는다
  - 영상 목록 항목(클립)에 싣는다 — 파일만으로 숫자가 남는다. 다만 media는 되돌리기 스냅샷을 타서 되돌리면 요약이 사라질 수 있으므로 되돌리기 밖으로 빼는 장치가 필요하다. 필드 등록표 · 왕복 견본도 는다
  - RM-29 연습 기록 줄에 싣는다 — 로드맵 문장과 가장 가깝다. 다만 RM-29 스키마가 정해질 때까지 이 대목이 멈춘다
  - **고른 답**: 짝 파일에만 둔다(추천)
- 「분석 지우기」가 짝 파일도 지우나
  - 화면에서만 지우고 짝 파일은 둔다(추천) — 되돌릴 수 없는 삭제를 만들지 않는다(클립을 지우지 않기로 한 2026-09-13 결정과 같은 태도). 다시 분석하면 덮어쓴다
  - 짝 파일까지 지운다 — 남은 자리가 깔끔하다. 대신 확인을 confirmOnce로 한 번 더 받고 서버에 DELETE를 더해야 한다
  - **고른 답**: 화면에서만 지우고 짝 파일은 둔다(추천)

## 조심할 것

- 서버의 클립 목록은 점으로 시작하지 않는 파일을 모두 영상으로 낸다. 짝 파일을 클립 곁에 `.pose.json` 꼴로 그냥 두면 목록에 영상처럼 끼므로 숨은 폴더나 확장자 거르기가 꼭 필요하다
- 숨은 경로는 정적 서빙이 막으므로(_hidden) 짝 파일은 반드시 API로만 읽고 쓴다
- 경로 규칙이 server.py와 domain/clips.js에 두 번 적힌다. 한쪽만 고치면 짝을 못 찾는다
- 짝 파일 열쇠는 클립 id가 아니라 보관 경로다. 파일 클립의 id는 이름에서 경로로 바뀌기도 하고(clipIdOf), 브라우저 폴더 모드에는 짝 파일이 없다
- media는 되돌리기 스냅샷을 타므로, 요약을 클립에 실으면 되돌리기 한 번에 요약이 사라지거나 옛 값으로 돌아갈 수 있다
- 짝 파일은 프레임 수백 장 × 사람 둘 × 점 33개라 몇 MB까지 큰다. 저장은 분석 끝에 한 번만, 앵커 고침은 묶어서 쓴다

### RM-30 자세 분석 결과 저장과 테이크 비교

#### 풀어 본 설명 — 2026-09-29

영상에서 잰 관절 각도를 저장해 두고, 같은 동작을 찍은 지난 테이크와 오늘 테이크를 나란히 견준다. 각도 계산, 모델, 영상 위 뼈대 그림은 이미 되어 있다. 하지만 결과가 어디에도 저장되지 않아 영상을 바꾸면 사라진다. 그래서 「무릎이 지난주보다 20° 더 열렸다」를 말할 수 없다.

##### 무엇

영상 패널의 `자세 분석` 구획에서 분석을 마치면 두 가지가 남는다. 하나는 원본 관절점이다. 프레임마다 사람마다 점 수십 개라 크기가 크므로, 영상 파일 곁에 짝 파일(사이드카)로 둔다. 다시 열면 다시 분석하지 않고 그 파일을 읽어 오버레이와 요약을 곧바로 되살린다. 다른 하나는 요약이다. 관절 열 개의 가동 범위(가장 굽힌 각에서 가장 편 각까지), 좌우 차, 얼마나 봤는지(커버리지)를 구간과 카운트별로 모아 안무표 파일에 싣는다. 화면에는 요약 표가 새로 생긴다. 지금은 계산 함수만 있고 이 표를 보여 주는 화면이 없다. 이 표에서 테이크 둘(또는 RM-29의 연습 기록 두 줄)을 고르면 관절마다 「전 → 후, 차이」가 나란히 뜬다. 충분히 보지 못한 관절은 흐리게 보여 믿지 말라고 알린다. RM-29의 연습 기록 줄에는 사람이 적는 별점 곁에 잰 값 한 칸이 붙는다.

##### 왜

분석은 지금도 된다. 그런데 결과는 앱이 도는 동안 메모리에만 있다가 영상을 바꾸거나 새로고침하면 없어진다. 같은 동작을 두 번 찍어도 두 결과를 동시에 가질 수 없어서, 비교 함수(`rom.compare`)는 만들어 놓고 부를 자리가 없다. 이 기능의 목적은 자세 교정이 아니라 기록이다. 테이크마다 잰 값이 남아야 연습 기록(RM-29)이 「기분상 나아졌다」가 아니라 숫자로 나아짐을 보인다. 또 긴 영상을 볼 때마다 다시 분석하는 시간과 전기(GPU)도 아낀다.

##### 어떻게

- 원본 관절점은 영상 파일 곁에 짝 파일로 쓴다. 서버 경로라면 `video-clip/<프로젝트>/<클립>.pose.json` 같은 자리에 두고, 서버에 그 파일을 쓰고 읽는 API를 하나 더한다. 정적 경로(서버 없이 연 경우)는 브라우저 저장소에 두거나 저장하지 않는다(갈림 ①).
- 짝 파일에는 분석에 쓴 모델 이름, 좌표계(world 또는 화면), 화면 비율(aspect), 분석 구간, 찍어 둔 앵커(누가 누구인지)를 함께 적는다. 모델이나 좌표계가 다르면 비교를 거절하는 규칙(`rom.compare`의 space 검사)이 저장된 값에도 그대로 서게 하려는 것이다.
- 요약은 이미 있는 순수 함수로 만든다. 구간 요약은 `rom.summarize`, 카운트별 요약은 `rom.summarizeByCount`, 가속도 요약은 `kinematics`가 맡는다. 초를 카운트로 바꾸는 일은 그 영상의 템포(박자·오프셋)로 한다. 템포를 고치면 요약을 짝 파일에서 다시 만든다. 요약은 원본에서 언제든 다시 만들 수 있는 값으로 다룬다.
- 요약은 안무 파일의 영상 목록 항목(찍은 날·메모가 사는 자리)에 붙인다. 아니면 RM-29가 세울 연습 기록 줄에 붙인다(갈림 ③). 요약이 비어 있으면 키째 빼서 분석을 안 쓰는 사람의 저장 바이트는 그대로 둔다.
- 되돌리기(undo)에는 넣지 않는다. 지금 `session.pose`가 되돌리기를 타지 않는 규칙(poseCommands 경계 ①②)을 그대로 이어 간다.
- 비교 화면은 요약 둘을 받아 관절마다 전·후·차이·믿을 만한지를 보인다. 같은 동작을 맞대는 단위는 갈림 ②에서 정한다.
- 시험: 짝 파일 쓰기 → 읽기 왕복, 좌표계가 다른 요약의 비교 거절, 커버리지가 낮은 관절의 trusted:false, 템포를 바꾼 뒤 카운트별 요약 재계산, 요약 없는 파일의 저장 바이트 불변, 서버 짝 파일 API 실물 시험.
- 라벨(요약 표, 비교, 저장 버튼 문구)이 새로 생기므로 튜토리얼과 기능 설명서의 자세 분석 대목을 함께 고친다.

##### 갈리는 대목

- ① 원본 관절점을 어디에 남기나
  - 서버 경로에서만 클립 곁 짝 파일로 둔다 — 로드맵이 적어 둔 길이다. 영상과 한자리에 있어 클립을 옮기면 같이 간다. 서버 없이 열면 분석은 되지만 저장되지 않는다(휴지통·안전망과 같은 규약). 추천한다.
  - 정적 경로에서도 브라우저 안에 둔다 — 서버 없이도 결과가 남는다. 다만 localStorage 용량으로는 모자라서 RM-33(IndexedDB)이 먼저 서야 한다. 그러면 이 항목이 RM-33 뒤로 밀린다.
  - 원본은 남기지 않고 요약만 저장한다 — 가장 작다. 대신 다시 열면 오버레이가 없고, 템포를 고치면 카운트별 요약을 다시 만들 수 없어 영상을 다시 분석해야 한다.
- ② 「같은 동작」을 무엇으로 맞대나
  - 마디·카운트 구간으로 맞댄다 — 각 테이크의 템포로 초를 카운트로 바꿔 같은 「8x3~8x4」를 견준다. 박자만 맞춰 두면 되고 RM-22 연습기의 구간 문법과 같다. 다만 박자가 어긋난 테이크는 엉뚱한 동작끼리 견준다.
  - 안무표의 동작 블록 단위로 맞댄다 — 「이 동작의 무릎」처럼 사람이 떠올리는 단위라 읽기 쉽다. 대신 판본(RM-29)마다 블록 배치가 다르면 짝이 끊기고, 블록 이름 없는 ?(RM-24)는 묶이지 않는다.
  - 테이크 전체(분석 구간 전체)만 맞댄다 — 가장 싸고 먼저 낼 수 있다. 하지만 「어느 대목이 나아졌나」는 못 말한다. 첫 걸음으로만 적당하다.
- ③ 요약을 영상 목록 항목에 붙이나, RM-29의 연습 기록 줄에 붙이나
  - 영상 목록 항목(테이크)에 붙인다 — 잰 값은 영상에서 나오니 주인이 분명하다. RM-29가 덜 섰어도 비교를 낼 수 있다. 연습 기록 줄은 그 테이크를 가리켜 값을 빌려 온다.
  - 연습 기록 줄에 붙인다 — 로드맵 문장(「연습 기록이 잰 값 하나를 더 갖는다」)과 가장 가깝다. 다만 RM-29의 스키마가 정해질 때까지 이 항목이 멈추고, 영상 없이 한 연습 줄에는 빈칸이 생긴다.

##### 조심할 것

- 좌표계(world 또는 화면)나 모델 크기가 다른 결과를 나란히 놓으면 없던 변화가 보인다. 저장된 요약에도 좌표계·모델·aspect를 반드시 싣고, 다르면 비교를 거절하는 규칙을 그대로 쓴다.
- 커버리지를 숨기면 세 프레임으로 잰 값이 300프레임으로 잰 값처럼 보인다. 저장·비교 화면 모두 「몇 %를 봤나」를 값 곁에 둔다. 임상 정상치 같은 절대 기준은 넣지 않는다(rom.js 머리 주석).
- 카운트별 요약은 템포에 매여 있다. 박자를 다시 맞추면 저장된 요약이 틀린 값이 된다. 원본 짝 파일에서 다시 만들거나, 요약에 어느 템포로 만들었는지를 적어 어긋나면 알린다.
- 클립 이름이 바뀌거나(겹침 " (2)"), 자르기(`/api/clips/trim`)로 새 파일이 생기거나, 클립을 휴지통으로 보내면 짝 파일이 고아가 되거나 엉뚱한 영상에 붙는다. 서버의 클립 조작마다 짝 파일도 함께 다룬다. 경로 규칙은 server.py와 domain/clips.js 두 곳에 같은 모양으로 적혀 있으니 한쪽만 고치지 않는다.
- 관절점을 store나 안무 파일에 넣으면 스냅샷과 저장이 수만 개 숫자만큼 불어난다. 원본은 파일 밖, 요약만 안에 둔다는 경계를 시험으로 못박는다.
- 영상 목록 항목에 요약 필드를 더하면 저장 포맷이 바뀌는 동작 변경이다. 구조 커밋과 섞지 않는다. 요약이 없는 파일은 바이트가 그대로여야 한다. RM-29가 다룰 최상위 `media` 이름 겹침도 이때 함께 본다.

##### 판의 옛 설명

> 자세 분석 결과를 클립 옆과 프로젝트에 남겨 테이크끼리 비교한다. 계산·모델·오버레이는 섰고 결과를 남길 자리가 없다.
