# RM-51 고른 블록에서 한글 첫 자로 연 이름이 자모로 깨짐

고른 블록에서 한글 자모로 이름 입력을 열면 지금은 빈 입력을 열고 글쇠를 브라우저에 맡긴다(openNaming 의 isImeKey 길). 그런데 실제 macOS 입력기는 body 에서 받은 첫 자모를 조합 없이 맺어 「ㅎㅏㄴ」이 된다. 그래서 첫 자모를 이름의 첫 자로 지키고, 맨 앞에 떨어진 자모 줄을 순수 함수로 음절로 잇는다. RM-50(「ㅅㅡ윙」)과 뿌리가 같은 자리(openNaming · askName)라 한 번에 고친다.

크기 M · 2026-11-03 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> RM-15 마무리에서 실제 macOS 한글 2벌식 IME(OS 글쇠 → 시험용 크롬)로 잼: ? 블록을 고르고 ㅎ·ㅏ·ㄴ 을 치면 이름이 「한」이 아니라 「ㅎㅏㄴ」으로 붙는다(1회 측정, 1/1). 이벤트 기록 — 첫 keydown 은 BODY 에서 key 'ㅎ' keyCode 71 isComposing=false 로 와서 openNaming 이 빈 입력을 열지만(isImeKey 길, preventDefault 안 함) 브라우저는 그 ㅎ 을 조합이 아닌 맺은 글자로 넣고, ㅏ 는 새 조합으로 시작해 ㅎ 과 합쳐지지 않는다. main.js 의 주석(막지 않으면 브라우저가 방금 포커스한 입력에서 조합한다)이 실제 IME 에서는 맞지 않는다. 이미 열린 입력에서 치면 「한」이 바르게 조합된다(1/1). 결정 Q49 의 전제(한글은 겹치지 않아 바로 열린다)가 깨지는 자리 — 고치는 길(첫 자모를 값으로 옮겨 조합을 잇게 · 한글 글쇠는 열기만 하고 첫 자를 버림 · Enter·F2 로만)은 사람이 고른다.

## 요구

- 고른 블록에서 한글 첫 자모로 바로 친 이름이 실제 입력기에서 한 음절로 맺힌다 — ㅎ·ㅏ·ㄴ 은 「한」, RM-50 의 ㅅㅡㅇㅜㅣㅇ 은 「스윙」
- 첫 자모를 버리지 않고 이름의 첫 자로 쓴다 — Q49 의 「고르고 바로 친다」를 한글에서도 지킨다
- 영문 · 숫자 첫 글자, Enter · F2 로 연 입력, 단축키(B · K · N · Space · ? · S) 우선은 지금 그대로 둔다
- 음절 잇기는 첫 자모로 연 입력의 맨 앞 자모 줄에만 한다 — 사람이 일부러 친 자모(예: Enter 로 열고 친 「ㅋㅋ」)나 가운데 자모는 건드리지 않는다
- 실제 입력기에서 틀린 것으로 드러난 main.js 의 주석(막지 않으면 브라우저가 방금 포커스한 입력에서 조합한다)과 버그 기록 · 원칙을 바로잡는다

## 결정 사항

- 한글 첫 자모로 연 이름 입력을 어떻게 고치나 — 지금은 빈 입력을 열고 글쇠를 브라우저에 맡기는데, 실제 입력기는 첫 자모를 맺어 「ㅎㅏㄴ」이 된다(1/1 측정)
  - 첫 자모를 값으로 넣고, 맨 앞에 떨어진 자모 줄을 조합이 끝날 때 · 닫힐 때 음절로 잇는다 — 고르고 바로 치는 가벼움(Q49)이 한글에서도 그대로다. 쳐 나가는 동안 잠깐 「ㅎㅏ」가 보이다가 조합이 끝나면 「하」로 붙는다. 잇기는 순수 함수라 단위 시험으로 잰다
  - 한글 글쇠는 빈 입력을 열기만 하고 첫 자모는 버린다 — 가장 작은 고침이다. 대신 ㅎ 을 한 번 더 쳐야 해서 처음 쓰는 사람에겐 첫 자가 먹힌 것처럼 보인다
  - 한글 글쇠로는 열지 않고 Enter · F2 로만 연다 — 조합 걱정이 없다. 대신 Q49 의 답(한글은 바로 열린다)을 바꾸는 일이라 그 결정도 고쳐 적어야 한다
  - **고른 답**: 첫 자모를 값으로 넣고, 맨 앞에 떨어진 자모 줄을 조합이 끝날 때 · 닫힐 때 음절로 잇는다
- RM-50(한글 바로 치기 — 「ㅅㅡ윙」)을 이 항목에 합치나 — 두 항목 모두 body 에서 받은 첫 자모를 입력기가 맺는 같은 원인이고 같은 함수(openNaming · askName)를 고친다
  - 합친다 — RM-51 의 고침으로 RM-50 도 닫는다 — 한 PR · 한 실제 입력기 확인으로 끝난다. RM-50 은 이 PR 로 고쳐진 것으로 적는다
  - 따로 둔다 — 같은 두 파일을 두 PR 이 고쳐 겹친다. 뒤의 PR 은 앞의 것에 다시 맞춘다
  - **고른 답**: 합친다 — RM-51 의 고침으로 RM-50 도 닫는다

## 조심할 것

- 만든 글쇠 이벤트 시험은 입력기 길을 재지 못한다. 요구 0 · 1 은 실제 macOS 2벌식 입력기로 재야만 고친 것이 된다(재현 1/1 → 고친 뒤 몇 번 중 몇 번 맞았는지 적는다)
- 조합 중(isComposing)에 값을 바꾸면 입력기 조합이 끊긴다. 다듬기는 compositionend 와 닫힐 때만 한다
- 입력기마다 첫 자모를 맺는 꼴이 다를 수 있다(ㅎㅏㄴ · ㅎ안 · 하ㄴ). 잇기 함수가 세 꼴을 모두 받아야 한다. Safari · 다른 입력기(3벌식)는 따로 재 봐야 한다
- 첫 자모를 값으로 넣고 기본 동작을 막지 않으면 자모가 두 번 들어갈 수 있다. 막은 뒤 입력기가 그 글쇠를 어떻게 다루는지 실제로 본다
- 추천 목록은 조합 중 값(ㅎㅏ)으로 찾으므로 조합이 끝나기 전에는 추천이 잠깐 비어 보일 수 있다
