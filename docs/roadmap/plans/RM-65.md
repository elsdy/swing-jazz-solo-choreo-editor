# RM-65 문서 창이 인라인 코드 속 꺾쇠 · 따옴표를 두 번 이스케이프한다

문서 창 렌더러 `inline` 은 줄 전체를 먼저 이스케이프한다. 그 뒤 백틱 속 글을 떼어 두었다가 되돌려 놓을 때 한 번 더 이스케이프해서, 인라인 코드 속 < > " ' & 가 &lt; &gt; &quot; 글자 그대로 보인다(개발 원칙 문서에서 꺾쇠 · 따옴표가 든 백틱 줄이 25줄). 되돌려 놓을 때 다시 이스케이프하지 않도록 고치고, 이 꼴을 단위 시험으로 막는다. 판의 다른 항목과 겹치지 않는다.

크기 S · 2026-11-03 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

## 요구

- 문서 창에서 백틱 인라인 코드 속 < > " ' & 는 원래 글자로 보인다(&lt; 같은 개체 이름이 글자로 새지 않는다)
- 원시 HTML 은 여전히 글자로 이스케이프된다 — 인라인 코드 속 <script> 같은 글도 태그로 살아나지 않는다
- 인라인 코드 안의 ** · ~~ · * · [](…) 는 지금처럼 꾸밈이나 링크로 바뀌지 않는다
- 링크 주소에 & 가 들어도 href 가 &amp;amp; 로 두 번 이스케이프되지 않는다(같은 차례 결함)
- 지금 개발 원칙 문서를 렌더한 결과에 이중 이스케이프 흔적(&amp;lt; · &amp;gt; · &amp;quot; · &amp;#39; · &amp;amp;)이 없다

## 확인 시나리오

병합 뒤 눈으로 볼 사람 확인 줄이 생기면 브라우저 노드가 main 커밋의 임시 보드(예시 판 — 프로젝트 {pid}, 이 항목은 {item})에서 이 걸음을 따라 하며 영상을 찍는다(B667). 할 것: open(열기) · click(누르기) · type(적기) · wait(기다리기) · see(보임 확인).

| 걸음 | 할 것 | 대상 | 값 | 기대 |
|---|---|---|---|---|
| 1 | open | #/p/{pid}/{item} | — | 앱이 뜬다 |
| 2 | click | text=문서 | — | 문서 창이 열린다 |
| 3 | click | text=개발 원칙 | — | 개발 원칙 문서가 그려진다 |
| 4 | see | .docs-body code | < | 인라인 코드 속 꺾쇠가 < 로 보이고 &lt; 글자는 보이지 않는다 |

## 조심할 것

- href 의 두 번째 이스케이프를 걷을 때, 링크 안전 검사 정규식이 이스케이프된 글(&amp; 이 든 것)을 보고 있다는 점을 놓치지 않는다. 검사는 지금처럼 이스케이프된 href 에 걸고 넣기만 그대로 한다
- 제목 id(`slugify`)와 짧은 앵커는 이스케이프 전 글로 만들어지므로 손대지 않는다. 앵커가 바뀌면 checkDocs 의 도움말 ? 앵커 시험이 붉어진다
- 코드블록(```) 쪽은 escapeHtml 을 한 번만 하므로 바르다. 같은 고침을 거기에 끼워 넣지 않는다
- 문서 창은 개발 문서만이 아니라 도움말(튜토리얼 · 기능)도 그리므로, 고친 뒤 꺾쇠가 든 도움말 줄도 바로 보이는지 함께 본다
