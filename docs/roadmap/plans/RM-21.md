# RM-21 ★ 카운트 시트 내보내기 — 종이·텍스트·읽기 전용 HTML

안무표를 세 가지 꼴로 내보낸다. A4 인쇄(PDF 포함), 마디 하나를 한 줄로 적어 클립보드에 담는 텍스트, `file://` 로 더블클릭하면 열리는 읽기 전용 HTML 한 장이다. 지금은 남에게 줄 수 있는 것이 화면 캡처와 다시 불러오기용 JSON 뿐이다. 판의 RM-17(디자인 토큰) · RM-10(라벨 표) · RM-23(파트)과 자리가 닿지만 그 코드를 부르지 않으므로 모두 점선으로 둔다.

크기 M · 2026-10-13 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 안무표를 남에게 건넬 수 있는 꼴 세 가지로 내보낸다. 첫째는 A4 한 장으로 인쇄하는 것(브라우저 인쇄로 PDF도 된다), 둘째는 `8x3 · 1 Swing Out · 5 Kick Ball Change`처럼 마디 하나를 한 줄에 적는 텍스트, 셋째는 앱 없이도 열리는 읽기 전용 HTML 한 장이다. 지금은 강사가 학생에게 안무를 주려면 화면을 캡처하는 수밖에 없고, 앱이 내보낼 수 있는 것도 다시 불러오기 위한 JSON 하나뿐이다.

## 요구

- 인쇄하면 편집 도구·영상 패널·동작 목록이 빠지고 격자(행=마디, 칸=카운트)·동작 이름만 A4 너비에 맞춰 나온다. 행 중간에서 쪽이 넘어가지 않는다
- 텍스트 시트는 intro 와 각 마디를 한 줄씩 `8x3 · 1 Swing Out · 5 Kick Ball Change` 꼴로 적는다. 행 라벨은 미리보기 표가 쓰는 cellLabel 의 행 부분과 같은 글자다
- 텍스트 시트를 다시 읽는 순수 함수를 둔다. 글이 안무 계획 꼴(bar·count·length·name)로 바뀌고 normalizePlan 을 그대로 지난다. 그래서 이름은 느슨하게 맞추고, 없는 이름은 새 동작으로 표시하고, 이상한 줄은 이유와 함께 버림 목록에 넣는다
- 안무표 → 글 → 안무표 왕복에서 배치가 같게 돌아온다. 겹친 블록(subRow)·마디를 넘는 블록·intro 가 빠지지 않는다
- 읽기 전용 HTML 은 한 파일 안에 스타일과 미리 그린 표가 다 들어 있다. 모듈 import·fetch·외부 script 가 없어서 `file://` 로도 열린다
- HTML 에 넣는 제목·동작 이름·카테고리 글자는 모두 이스케이프한다. 받은 쪽에서 태그나 스크립트가 실행되지 않는다
- 영상이 유튜브이고 마커가 있으면, 읽기 전용 HTML 의 마커마다 그 시각으로 가는 링크가 붙는다. 로컬 영상이면 이름과 시각만 적는다
- 클립보드 쓰기·텍스트/HTML 내려받기·인쇄 호출은 어댑터에 두고 유스케이스에 주입한다. 계층 검사가 통과한다
- 파일 메뉴에 내보내기 버튼 셋을 새로 둔다. 라벨은 기능 설명서·튜토리얼에 함께 적고, 버튼마다 명령 등록부의 툴팁이 있다

## 순서

- choreoPlan 에서 행 라벨(intro / 8xN)을 rowLabel 로 떼어 내고 cellLabel 이 그것을 쓰게 한다(구조만 바꾼다 — tests/unit/domain.test.mjs 의 choreoPlan 시험이 그대로 통과해야 한다)
- countSheet.js 를 쓴다. 쓰기는 배치를 행·칸·층 차례로 늘어놓아 한 줄씩 만들고, 읽기는 줄을 { moves:[{bar,count,length,name}] } 로 바꾼다. 문법(길이·층 표기)은 결정대로 정한다. tests/unit/countSheet.test.mjs 에 줄 꼴·왕복·normalizePlan 경유 시험을 함께 둔다
- sheetHtml.js 를 쓴다. 이스케이프 함수, 격자 표, 텍스트 시트, 유튜브 마커 링크를 하나의 HTML 문자열로 만들고 스크립트는 넣지 않는다. 이스케이프·외부 참조 없음·마커 링크 시험을 더한다
- FileGateway 계약에 downloadText·copyText·print 를 더하고 browserFileIO 에 구현한다(downloadJson 과 같은 a 클릭·즉시 revoke 꼴)
- sheetCommands.js 에 내보내기 셋을 두고 fileIO 를 주입받는다. 가짜 fileIO 로 유스케이스 시험을 더하고 `node tools/check-arch.mjs` 로 계층을 본다
- index.html 파일 메뉴 패널에 버튼 셋(data-command)을 두고 명령 등록부·runCommand 에 배선한다. 누르면 createFileMenu 가 메뉴를 닫는다. tests/unit/commandButtons.test.mjs 를 돌린다
- index.html 에 @media print 한 벌을 둔다. 앱바·사이드바·영상 패널·편집 버튼을 숨기고, 격자를 한 장 너비에 맞추고, 행에 break-inside: avoid, 루틴 구분은 색 말고 테두리·글자로 한다. Chrome·Safari 인쇄 미리보기로 본다
- 만든 HTML 을 실제로 내려받아 더블클릭(`file://`)으로 열어 본다
- 기능 설명서·튜토리얼·이력에 새 라벨과 사용법을 적고 `node tools/check-docs.mjs` 를 돌린다

## 결정 사항

- 붙여 넣어 배치하기(글 → 안무표)의 창까지 이번에 넣을까
  - 읽는 순수 함수와 왕복 시험만 이번에, 붙여넣기 창·미리보기는 다음 걸음 — 강사가 줄 한 장이 빨리 나오고 크기가 M 안에 든다. 문법은 왕복 시험으로 이번에 굳어서 나중에 창을 붙여도 바뀌지 않는다
  - 붙여넣기 창·미리보기·새 동작 등록까지 함께 — 로드맵 문구대로 다 들어간다. 다만 「말로 채우기」 미리보기 창을 넓혀야 해서 L 에 가까워진다
  - **고른 답**: 읽는 순수 함수와 왕복 시험만 이번에, 붙여넣기 창·미리보기는 다음 걸음
  - **근거**: 💰 절약 검토자 — 요구 3은 읽는 순수 함수까지만 적었고 붙여넣기 창은 요구에 없다. · 관점 범위
- 한 줄 문법에서 길이·겹친 층을 어떻게 적을까
  - 기본은 짧게(`1 Swing Out · 5 Kick`), 다음 동작까지로 길이가 안 맞거나 겹칠 때만 `[6]` · 층 표기를 더한다 — 대부분의 줄이 로드맵 예시처럼 깔끔하고 왕복도 정확하다. 규칙이 둘이라 시험 견본이 는다
  - 늘 길이를 대괄호로 붙인다(`1 Swing Out [4]`) — 규칙이 하나라 왕복이 가장 단순하다. 줄이 무거워져 단톡방에서 읽기는 덜 편하다
  - 시작 칸만 적는다 — 가장 읽기 쉽다. 하지만 빈 칸·겹침·마디를 넘는 블록이 되살아나지 않아 왕복 요구를 버려야 한다
  - **고른 답**: 기본은 짧게(`1 Swing Out · 5 Kick`), 다음 동작까지로 길이가 안 맞거나 겹칠 때만 `[6]` · 층 표기를 더한다
  - **근거**: 💰 절약 검토자 — 요구 2의 짧은 줄 예시와 요구 4의 왕복(겹침·마디 넘김)을 둘 다 만족한다. · 관점 범위
- 읽기 전용 HTML 에서 영상을 어디까지 다룰까
  - 유튜브일 때만 마커별 시각 링크, 로컬 영상은 이름·시각만 — 파일이 가볍고 서버가 필요 없다. 받은 사람이 링크를 눌러 그 자리를 본다
  - 영상은 넣지 않고 안무표와 시트만 — 가장 단순하다. 마커가 시트에서 빠진다
  - **고른 답**: 유튜브일 때만 마커별 시각 링크, 로컬 영상은 이름·시각만
  - **근거**: 💰 절약 검토자 — 요구 7이 유튜브 마커 시각 링크와 로컬 영상의 이름·시각만 적기를 명시한다. · 관점 범위

## 조심할 것

- 텍스트 문법은 한 번 남에게 나가면 되돌리기 어렵다. 키보드 복사/붙여넣기도 이 문법을 쓸 것이라 겹침·길이·intro 표기를 왕복 시험으로 먼저 굳힌다
- 읽기 전용 HTML 에 모듈 import·fetch 가 끼면 `file://` 에서 빈 화면이 된다. 스크립트 없이 미리 그린 표로 만들고 실제로 더블클릭해 연다
- 동작 이름·제목은 사용자가 적은 값이다. HTML 에 넣을 때 이스케이프를 빠뜨리면 받는 사람 쪽에서 실행된다
- 마디가 많으면 A4 한 장을 넘는다. 행 중간에서 끊지 않고 여러 장으로 넘기는 것을 기준으로 둔다(글자를 줄여 억지로 한 장에 넣지 않는다)
- 흑백 인쇄에서 루틴 색 구분이 사라진다. 인쇄 스타일은 색 대신 테두리·글자로 가른다. RM-17 이 나중에 들어오면 토큰으로 옮겨야 할 수 있다
- 유튜브 영상 id 를 뽑는 함수가 이미 링크·영상 쪽에 있을 것이다. 새로 짓지 말고 그것을 찾아 쓴다(이번에 읽지 못한 자리)

## 다시 다듬기 전의 계획서

### RM-21 ★ 카운트 시트 내보내기 — 종이·텍스트·읽기 전용 HTML

#### 풀어 본 설명 — 2026-09-29

안무표를 남에게 건넬 수 있는 꼴 세 가지로 내보낸다. 첫째는 A4 한 장으로 인쇄하는 것(브라우저 인쇄로 PDF도 된다), 둘째는 `8x3 · 1 Swing Out · 5 Kick Ball Change`처럼 마디 하나를 한 줄에 적는 텍스트, 셋째는 앱 없이도 열리는 읽기 전용 HTML 한 장이다. 지금은 강사가 학생에게 안무를 주려면 화면을 캡처하는 수밖에 없고, 앱이 내보낼 수 있는 것도 다시 불러오기 위한 JSON 하나뿐이다.

##### 무엇

안무표 위 도구 모음에 「내보내기」 자리를 새로 두고 세 가지를 고르게 한다. ① 인쇄하면 편집 버튼·영상 패널·동작 목록이 빠지고 격자(행은 마디, 칸은 카운트)와 동작 이름, 비고만 남은 채 A4 한 장에 맞춰 나온다. 브라우저 인쇄 창에서 PDF로 저장하면 PDF가 된다. ② 텍스트 시트는 intro와 각 마디를 한 줄씩 `8x3 · 1 Swing Out · 5 Kick Ball Change`처럼 적어 클립보드에 담는다. 메신저·메모장·스프레드시트에 바로 붙일 수 있다. 같은 문법의 글을 거꾸로 붙여 넣으면 배치가 되고, 목록에 없는 동작 이름은 동작 목록에 저절로 등록된다. ③ 읽기 전용 HTML은 파일 하나 안에 스타일과 데이터가 다 들어 있다. 받은 사람이 더블클릭만 하면 안무표와 텍스트 시트를 볼 수 있다. 영상 마커가 있고 영상이 유튜브이면 마커마다 그 시각으로 바로 가는 링크가 붙는다. 이 세 가지 모두 서버·계정 없이 브라우저만으로 된다.

##### 왜

이 편집기는 지금 혼자 만들고 혼자 보는 도구에 머문다. 로드맵이 겨누는 네 번째 문장인 「남에게 줄 수 있다」가 비어 있다. 강사가 수업 뒤 학생에게 줄 종이 한 장, 단톡방에 붙일 몇 줄, 앱을 깔지 않은 사람에게 보낼 파일을 지금은 만들 수 없다. 화면 캡처는 긴 안무가 잘리고 글자가 작다. 게다가 받은 사람이 그 내용을 다시 쓸 수 없다. 로드맵은 이 기능을 「강사가 돈을 내는 이유」로 보고, M3 이정표(학생이 앱 없이 한 장을 받는다)의 첫 추천 기능으로 두었다.

##### 어떻게

- 안무표 → 텍스트 줄, 텍스트 줄 → 놓을 항목 두 방향을 순수 함수로 도메인에 새로 둔다. 행 라벨(intro / 8x3)은 보드·영상 패널이 쓰는 문자열과 같아야 한다.
- 텍스트를 읽는 쪽은 새 배치 경로를 만들지 않는다. 글을 이미 있는 안무 계획 꼴(마디·카운트·길이·이름)로 바꾸고, 「말로 채우기」가 쓰는 정규화(이름 느슨히 맞추기, 없는 동작은 새 동작으로 표시, 이상한 줄은 이유와 함께 버림 목록에)에 태운다. 그러면 놓기 전에 미리보기도 그대로 얻는다.
- 왕복 시험을 둔다. 안무표 → 글 → 안무표가 같은 배치로 돌아오는지, 겹친 블록·마디를 넘는 블록·intro·비고가 빠지지 않는지 단위 시험으로 잰다.
- 인쇄는 print 미디어 CSS 한 벌로 한다. 편집 도구를 숨기고, 격자를 한 장 너비에 맞추고, 행 중간에서 쪽이 넘어가지 않게 한다. 새 도구·라이브러리는 쓰지 않는다.
- 읽기 전용 HTML은 스타일과 안무 데이터, 작은 그리기 스크립트를 한 파일 안에 넣어 만든다. 받은 쪽에서 `file://`로 열리므로 ES 모듈 import와 fetch를 쓰지 않는다. 내려받기는 이미 있는 파일 내려받기 어댑터를 넓혀서 한다.
- 클립보드 쓰기·읽기와 인쇄 호출은 브라우저 전역을 만지므로 어댑터에 둔다. 유스케이스는 그것을 주입받는다.
- 버튼 라벨이 새로 생기므로 튜토리얼과 기능 설명서를 함께 고친다.

##### 갈리는 대목

- 붙여 넣어 배치하기(글 → 안무표)를 이번 항목에 함께 넣을까
  - 함께 넣는다 (로드맵 문구대로) — 문법이 처음부터 왕복 시험으로 굳는다. RM-13(키보드 복사/붙여넣기)이 이 문법을 바로 가져다 쓴다. 대신 붙여넣기 창·미리보기·새 동작 등록까지 붙어 크기가 M을 넘기 쉽다.
  - 내보내기 셋을 먼저 내고, 붙여넣기는 다음 걸음으로 — 강사가 줄 한 장이 빨리 나온다. 다만 문법은 이번에 「읽을 수 있는 꼴」로 못 박고 시험도 함께 둬야, 나중에 읽는 쪽을 붙일 때 바꾸지 않는다.
- 한 줄 문법에서 겹친 블록과 마디를 넘는 블록을 어떻게 적을까
  - 시작 칸만 적고 길이는 다음 동작까지로 본다 (`1 Swing Out · 5 Kick`) — 사람이 읽기 가장 쉽고 로드맵 예시와 같다. 하지만 빈 칸, 겹친 두 층, 다음 마디로 이어지는 블록은 그대로 되살아나지 않는다.
  - 길이를 대괄호로 붙인다 (`1 Swing Out [8] · 5 Kick [4]`) — 왕복이 정확해진다. 비고란이 이미 쓰는 `[6]` 표기와도 결이 맞는다. 줄은 조금 무거워진다.
  - 기본은 짧게 쓰고, 모자랄 때만 길이·층 표기를 더한다 — 대부분의 줄은 깔끔하게 남고 왕복도 된다. 대신 규칙이 둘이라 시험 견본이 늘어난다.
- 읽기 전용 HTML에서 영상을 어디까지 다룰까
  - 유튜브 영상일 때만 마커별 시각 링크를 단다 — 파일이 가볍고 서버도 필요 없다. 로컬 영상 클립은 받은 사람에게 없으므로 이름과 시각만 적는다.
  - 영상은 넣지 않고 안무표와 시트만 담는다 — 가장 단순하다. 이 경우 공유 링크·클라우드를 정하는 결정(Q8)의 재료가 줄어든다.

##### 조심할 것

- 텍스트 문법은 한 번 남에게 나가면 되돌리기 어렵다. RM-13의 클립보드 붙여넣기도 이 문법을 기다리고 있으니, 겹침·길이·intro·비고를 어떻게 적을지 시험으로 먼저 굳힌다.
- 읽기 전용 HTML은 받은 쪽에서 `file://`로 열린다. 모듈 import·fetch를 쓰면 빈 화면이 된다. 모든 것을 한 파일 안에 넣고 실제로 더블클릭해 열어 본다.
- 동작 이름·비고·제목을 HTML에 넣을 때는 반드시 이스케이프한다. 남에게 보내는 파일이라 이름에 든 태그나 스크립트가 받은 사람 쪽에서 실행되면 안 된다.
- 마디가 많으면 A4 한 장을 넘는다. 줄이 행 중간에서 끊기지 않게 하고, 넘칠 때 글자를 줄일지 여러 장으로 나눌지 기준을 정해 둔다.
- 인쇄 스타일이 지금 흩어진 색·글자 크기를 그대로 따라가면 흑백 인쇄에서 루틴 색 구분이 사라진다. RM-17(디자인 토큰) 전에 하면 나중에 다시 손봐야 할 수 있다.
- 새 라벨이 생기므로 기능 설명서·튜토리얼을 함께 고친다. RM-10(라벨 문자열 표)이 먼저 들어오면 그 표에 올린다.
