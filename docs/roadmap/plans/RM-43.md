# RM-43 밝은 테마(솜사탕)에서 서랍 제목 글자가 안 보임

보고에 적힌 박힌 밝은 글자색(#dbe4ef)은 RM-17 디자인 토큰 작업에서 이미 걷혔다. 지금 서랍 제목(index.html 362줄)과 영상 파일 이름 알약(1903줄)은 var(--text) 를 쓰고, 솜사탕 테마는 --text 를 짙은 #452f52 로 바꾼다. 그래서 이 항목은 새로 고칠 것이 거의 없다. 할 일은 브라우저에서 고쳐졌는지 확인하고, 밝은 테마에서 글자 대비가 다시 무너지지 않게 토큰 대비를 재는 시험을 두는 것이다. RM-56 · RM-59(밝은 테마의 블록 팝업 제목)와 같은 갈래이니, 대비 시험은 그 두 항목도 함께 쓸 수 있는 꼴로 만든다.

크기 S · 2026-11-03 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 솜사탕 테마에서 왼쪽 서랍의 summary(「파일 — 최근 프로젝트 · 동작 · 카테고리」 · 「루틴 목록」 · 「카테고리 관리」 · 「목록에 없는 동작 만들기」)와 영상 칸 파일 이름 알약이 거의 보이지 않는다 — index.html:331 의 '.drawer > summary { color: #dbe4ef }' 처럼 어두운 테마용 밝은 글자색을 박아 두어, 밝은 바탕(테마 변수 무시)에서 rgb(219,228,239) on 밝은 분홍. 같은 박힌 색이 1806 · 1942 · 1957 · 1975 · 2456 · 3772 줄에도 있다. RM-25 마무리의 브라우저 확인(2026-11-03, 1440px · 390px)에서 봤다 — RM-25 의 지난 판 줄은 테마 변수를 써서 읽힌다

## 요구

- 솜사탕 테마에서 왼쪽 서랍의 summary 넷(파일 · 루틴 목록 · 카테고리 관리 · 목록에 없는 동작 만들기)의 글자가 밝은 바탕 위에서 읽힌다
- 솜사탕 테마에서 영상 칸 파일 이름 알약의 글자가 읽힌다
- 테마마다 글자 토큰(--text · --muted)과 바탕 토큰(--bg · --bg-2 · --surface)의 대비가 기준(본문 4.5:1, 보조 글자 3:1) 아래로 떨어지면 시험이 붉어진다
- 서랍 제목과 파일 이름 알약의 글자색이 박힌 값이 아니라 글자 토큰을 쓴다

## 순서

- node --test tests/unit/themeContrast.test.mjs 로 새 시험을 돌린다. 솜사탕 --text 를 #dbe4ef 로 바꾼 견본에서 붉고, 실제 파일에서 초록인지 본다

## 결정 사항

- 대비 시험이 지금 테마 값에서 붉으면 어떻게 할까 — 솜사탕 --muted(#8b7aa1)는 밝은 바탕 위에서 3:1 언저리일 수 있다(추론함, 아직 재지 않았다)
  - 기준을 넘게 토큰 값을 조금 짙게 고친다 — 보조 글자가 조금 짙어진다. 색을 바꾸는 일이라 동작을 바꾸는 커밋으로 따로 낸다
  - 보조 글자 기준은 재기만 하고 붉히지 않는다 — 화면은 그대로 두고, 본문 --text 만 4.5 로 막는다. 보조 글자가 흐린 채로 남는다
  - **고른 답**: 기준을 넘게 토큰 값을 조금 짙게 고친다
- 같은 갈래인 RM-56 · RM-59(밝은 테마의 블록 팝업 제목)를 이 항목에 합칠까
  - 합치지 않고 대비 시험만 두 항목이 다시 쓴다 — 이 항목은 S 로 끝난다. 팝업 제목은 그 두 항목이 각자 고친다
  - 팝업 제목까지 이 항목에서 고친다 — 밝은 테마의 글자 문제를 한 PR 로 닫는다. RM-56 · RM-59 와 손댈 자리가 겹쳐 크기가 M 이 된다
  - **고른 답**: 합치지 않고 대비 시험만 두 항목이 다시 쓴다

## 확인 시나리오

병합 뒤 눈으로 볼 사람 확인 줄이 생기면 브라우저 노드가 main 커밋의 임시 보드(예시 판 — 프로젝트 {pid}, 이 항목은 {item})에서 이 걸음을 따라 하며 영상을 찍는다(B667). 할 것: open(열기) · click(누르기) · type(적기) · wait(기다리기) · see(보임 확인).

| 걸음 | 할 것 | 대상 | 값 | 기대 |
|---|---|---|---|---|
| 1 | open | #/p/{pid} | — | 앱이 열린다 |
| 2 | click | text=솜사탕 | — | 밝은 파스텔 테마로 바뀐다 |
| 3 | see | .drawer > summary | 루틴 목록 | 서랍 제목이 밝은 바탕 위에서 짙은 보라 글자로 또렷하게 읽힌다 |
| 4 | see | .drawer-plus > summary | 목록에 없는 동작 만들기 | 새 동작 서랍 제목도 읽힌다 |
| 5 | see | .video-file-name | — | 영상을 고른 뒤 파일 이름 알약의 글자가 분홍 알약 위에서 읽힌다 |

## 조심할 것

- 토큰의 대비만 재면 한계가 있다. 규칙이 반투명 겹침(rgba)이나 --t-* 그러데이션 위에 글자를 얹으면 토큰 대비가 좋아도 실제로는 흐릴 수 있으니 verify 의 눈 확인을 빼지 않는다
- index.html 의 CSS 를 글자로 읽는 시험이라 테마 블록의 꼴(:root[data-theme="…"] { … })이 바뀌면 함께 고쳐야 한다. check-principles 가 이미 블록을 읽는 함수를 쓰니 그것을 다시 쓸 수 있는지 먼저 본다
- 보고 글의 줄 번호(331 · 1806 · …)는 RM-17 이전 것이라 지금 index.html 과 맞지 않는다. 옛 줄을 따라가지 말고 클래스 이름으로 찾는다
