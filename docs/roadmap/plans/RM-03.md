# RM-03 초기화·전체 불러오기 뒤 남는 선택을 지운다

## 풀어 본 설명 — 2026-09-29

안무표에서 블록 몇 개를 고른 채 「전체 초기화(링크 포함)」·「전체 불러오기」·「안무표만 비우기」를 누르면, 블록은 사라져도 고른 목록은 그대로 남는다. 그래서 도구 모음에 「루틴으로 편성 (2)」가 계속 떠 있고, 눌러도 편성할 블록이 없어 아무 일도 없다. 이 세 동작이 끝날 때 고른 목록도 함께 비워, 버튼이 사라지는 것이 맞는 모습이 되게 한다.

### 무엇

안무표에서 블록을 누르면 고른 블록이 되고, 도구 모음에 「루틴으로 편성 (N)」 버튼이 N개로 뜬다. 이 항목이 끝나면 세 동작 뒤에는 고른 목록이 빈다. 「전체 초기화(링크 포함)」로 새 문서를 열 때, 파일이나 최근 목록에서 「전체 불러오기」로 다른 안무를 열 때, 「안무표만 비우기」로 블록만 지울 때가 그 셋이다. 셋 다 끝나면 「루틴으로 편성 (N)」 버튼이 사라지고 고른 표시도 남지 않는다. 영상 패널의 「고른 대기 블록 수」도 이 목록을 읽으므로 함께 0이 된다. 되돌리기(Undo)는 이미 고른 목록을 비우고, 블록 하나를 지울 때도 그 블록만 목록에서 뺀다. 이번 일은 그 규칙을 빠진 세 자리에도 맞추는 것이다. 새 버튼이나 새 화면은 없다.

### 왜

사라진 블록을 가리키는 선택이 남으면, 화면은 「두 개를 골랐으니 루틴으로 묶을 수 있다」고 말하는데 실제로는 묶을 것이 없다. 사용자는 버튼을 눌러 보고, 아무 일이 없으니 앱이 고장 났다고 여긴다. 원본 index.html 에서부터 있던 결함이다. 옮겨 오는 동안에는 일부러 고치지 않고 「일부러 두고 온 것」 문서의 「이어서 고칠 것 2번」에 적어 두었다. 사라진 선택은 지운다는 데 이견이 없고 정할 규칙도 없어 크기가 S다. 다만 골든(배치 알고리즘 기록)은 선택 상태를 담지 않는다. 그래서 고쳐도 깨지는 골든이 없고, 반대로 다시 망가져도 잡아 줄 안전망이 없다. 단위 시험을 함께 심어야 하는 까닭이다.

### 어떻게

- 동작 변경 커밋 하나로 낸다. 골든은 그대로 통과해야 한다(선택은 골든 밖이다).
- 전체 초기화: 보드를 비우는 명령이 선택을 손대지 않는다고 주석에 적혀 있다. 여기서 선택을 빈 목록으로 바꾸고, 다시 그릴 것에 「선택」과 「도구 모음」을 싣는다.
- 안무표만 비우기: 이미 「선택·도구 모음을 다시 그려라」고 알리지만, 정작 고른 목록은 비우지 않는다. 그래서 다시 그려도 (2)가 그대로다. 실제로 목록을 비우게 고친다.
- 전체 불러오기: 문서 필드를 한꺼번에 쓰는 자리에서 Undo 복원과 같은 방식으로 선택을 빈 목록으로 함께 쓴다. 다시 그릴 것에도 「선택」을 더한다. 파일에서 여는 길과 최근 목록에서 여는 길이 이 한 함수를 지나므로 둘 다 고쳐진다.
- 단위 시험: 블록 두 개를 놓고 둘 다 고른 뒤 세 동작을 각각 부른다. 그다음 고른 목록이 비었는지, 다시 그릴 것에 선택과 도구 모음이 있는지 확인한다. 대조군으로 부분 불러오기는 기존 선택을 지우지 않는지(fork 에 따라)도 본다.
- 문서: 「일부러 두고 온 것」 표의 해당 줄과 「이어서 고칠 것 2번」을 고친 것으로 옮긴다. 버그 기록에 증상·원인·수정·재발 방지를 적고, 로드맵 문서·추적 JSON 의 RM-03 을 끝으로 내린다.

### 손댈 자리

- 보드 명령 — 전체 초기화(clearBoard)·안무표만 비우기(clearPlacements)
- 프로젝트 명령 — 전체 불러오기의 적용 절차(applyProjectData)
- 문서 필드 한꺼번에 쓰기(writeDoc)의 곁값 자리 — Undo 복원이 이미 선택을 비우는 방식
- 도구 모음의 「루틴으로 편성 (N)」 버튼·영상 패널의 고른 대기 블록 수(읽기만, 고치지 않음)
- 단위 시험 — 유스케이스 시험 파일 새로
- 문서 — 일부러 두고 온 것·버그 기록·로드맵·추적 JSON

### 갈리는 대목

- 고치는 방식 — 세 자리에서 각각 비울까, 「없는 블록을 가리키는 선택은 걸러 낸다」를 한 자리에 둘까
  - 세 자리에서 각각 비운다 (추천, 계획대로) — 범위가 로드맵 설명 그대로라 S로 끝난다. 다만 나중에 블록을 없애는 새 길이 생기면 같은 결함이 또 난다. 키보드 Delete(RM-13)나 분할·병합·마디 삭제(RM-16)가 그런 길이다. 시험이 세 길만 지킨다.
  - 블록이 바뀐 뒤 선택을 늘 남은 블록으로 걸러 내는 공통 자리를 둔다 — 앞으로 생길 삭제 길까지 한꺼번에 막아 선택을 편집 단위로 키우는 RM-14 의 밑돌이 된다. 하지만 블록이 바뀌는 모든 명령의 흐름을 건드려 크기가 S를 넘는다. 또 지금 블록 하나 지우기가 따로 하는 정리와 겹친다.
- 부분 불러오기(병합)도 선택을 비울까
  - 건드리지 않는다 (추천) — 부분 불러오기는 기존 블록을 남긴 채 더하므로 고른 블록이 여전히 있다. 선택을 지우면 오히려 사용자가 고른 것을 말없이 잃는다.
  - 불러오기는 다 같이 비운다 — 규칙이 「불러오면 선택은 빈다」 하나로 단순해진다. 대신 병합 뒤에 고른 것을 다시 골라야 한다.

### 조심할 것

- 「안무표만 비우기」는 선택을 다시 그리라고 알리기만 하고 목록은 비우지 않는다. 겉보기에 이미 고쳐진 것처럼 읽히니 시험으로 실제 목록이 비었는지를 확인한다.
- 골든이 선택을 보지 않아 회귀를 못 잡는다. 단위 시험이 유일한 안전망이다. 브라우저에서 두 개 고르기 → 세 동작 → 버튼이 사라짐도 손으로 한 번 본다.
- 전체 초기화는 링크·영상 비우기와 Undo 기록이 한데 묶여 있다. 선택 비우기를 더할 때 다시 그릴 것 합치기의 순서를 흐트러뜨리지 않는다(렌더는 layout → boards → selection 순서가 계약이다).
- 형식이 틀려 「잘못된 프로젝트 파일 형식입니다.」가 뜬 불러오기에서는 아무것도 바뀌지 않아야 하므로, 선택도 비우지 않는다.
- 동작 변경이므로 구조 정리와 한 커밋에 섞지 않는다. 지금 이 브랜치(copy-repack)는 RM-02 작업 중이니 main 에서 새 브랜치로 딴다.

### 판의 옛 설명

> 전체 초기화·전체 불러오기·안무표만 비우기 뒤에 사라진 배치를 가리키는 선택을 비운다. 눌러도 아무 일 없는 「루틴으로 편성 (2)」가 떠 있지 않게.
