# RM-47 비고 열이 Chrome 인쇄엔 빠지고 Safari 인쇄엔 찍힌다

Chrome 은 인쇄 쪽 너비(약 717px)를 좁은 화면으로 읽는다. 그래서 index.html 의 좁은 화면 규칙(body[data-notes=off] 의 비고 숨김)에 걸려 인쇄에서 비고 열이 빠지고, Safari 는 같은 안무표에서 비고 열을 찍는다. 비고 숨김 규칙을 화면 전용(@media screen)으로 묶어 인쇄에서는 두 브라우저 모두 비고 열을 늘 찍게 맞춘다. RM-21 계획서 요구 ①(「격자 · 동작 이름, 비고만 남은 채」)과 기능 설명서 512줄(「격자와 비고만 흰 종이에」)이 이미 비고를 넣는다고 적고 있어서다. 같은 @media print 근처를 고치는 RM-44 · RM-45 · RM-46 과는 줄이 겹치기만 하고 서로 부르는 것은 없다. 비고 폭(--noteW)을 렌더마다 재는

## 다시 다듬기 전의 설명

> 같은 안무표가 브라우저마다 다르게 인쇄된다. Chrome 은 인쇄 쪽 너비(약 717px)가 좁은 화면용 미디어 규칙(body[data-notes=off] 의 비고 숨김)에 걸려 비고가 빠지고, WebKit 은 화면 너비로 미디어를 재서 비고 열이 찍힌다. 요구 1 은 「격자 · 동작 이름만」이므로 @media print 에서 비고를 명시적으로 숨길지(또는 늘 넣을지) 정해 한쪽으로 맞춘다.

## 요구

- 인쇄에서는 화면 폭이나 비고 토글(data-notes)과 상관없이 비고 머리 칸과 비고 칸이 찍히고, 격자의 비고 열 폭(--noteCol)이 0 으로 접히지 않는다 — Chrome 과 Safari 가 같은 결과를 낸다
- 화면에서는 1040px 아래 폭의 비고 토글(📝 버튼으로 켜고 끄기)이 지금처럼 동작한다 — 숨김 규칙을 지우지 않고 화면 전용으로만 묶는다
- 실제 Chrome 인쇄(printToPDF)와 Safari(WebKit) 인쇄에서 같은 안무표의 비고 열이 둘 다 찍힌다

## 결정 사항

- 인쇄에 비고 열을 넣을까, 뺄까 — 항목 설명은 RM-21 요구 1 을 「격자 · 동작 이름만」으로 읽었는데, RM-21 계획서 요구 ①과 기능 설명서는 「격자와 동작 이름, 비고」로 적고 있어 어느 쪽으로 맞출지 정해야 한다
  - 늘 넣는다 — 화면 토글과 상관없이 비고 열이 찍힌다 — RM-21 계획서 · 기능 설명서와 맞아서 문서는 한 줄만 더하면 된다. 비고 숨김 규칙을 @media screen 으로 묶기만 하면 된다. 비고가 빈 안무표에서는 빈 열이 종이 폭을 조금 먹는다
  - 늘 뺀다 — 인쇄에는 격자와 동작 이름만 — @media print 에 비고 숨김과 --noteCol: 0 을 따로 두고, 기능 설명서 · 튜토리얼과 RM-21 계획서의 「비고」를 고쳐야 한다. 비고에 적은 연습 메모가 종이에 남지 않는다
  - 화면 토글을 따른다 — 비고를 켜 두었으면 찍고, 꺼 두었으면 뺀다 — 넓은 화면에는 토글 단추가 없어 늘 켜진 것으로 쳐야 하고, 인쇄용 규칙에 data-notes 갈래를 하나 더 둬야 한다. 같은 안무표라도 인쇄한 기기에 따라 결과가 갈릴 수 있다
  - **고른 답**: 늘 넣는다 — 화면 토글과 상관없이 비고 열이 찍힌다

## 조심할 것

- Chrome 은 인쇄 쪽 너비 약 717px 를 화면 폭으로 읽어 1040px · 720px 아래 규칙을 모두 인쇄에 먹인다. 비고 말고 다른 좁은 화면 규칙(손가락 크기 · 시트 사이드바 같은 것)도 인쇄에 섞여 들어갈 수 있다 — 이 항목은 비고 열만 맞추고, 따로 어긋나는 것이 보이면 판에 버그로 올린다
- 비고 열이 찍히면 종이에서 격자가 쓸 폭이 줄어든다. RM-45(인쇄 칸 너비를 종이 기준으로 다시 셈)가 비고 폭(--noteW)까지 빼고 칸 너비를 세야 하므로, RM-45 계획을 세울 때 이 결정을 알린다
- --noteW 는 렌더마다 화면 기준으로 잰 px 값이다(RM-42 가 그 재기를 다룬다). 인쇄에서도 그 값을 그대로 쓰므로 비고가 긴 안무표는 열이 넓게 찍힐 수 있다
- RM-44 · RM-46 이 같은 index.html 의 @media print 블록을 고친다. 이 항목은 블록 바깥(1040px 아래 블록)을 주로 고치고 블록 안에는 주석 한 줄만 더하지만, 병합할 때 줄 충돌을 본다
- 기존 print: 시험의 정규식(@media print \{ … \n {4}\})은 블록 끝을 들여쓰기 4칸으로 찾는다. 새로 감싸는 @media screen 은 들여쓰기를 6칸 이상으로 두어 그 정규식을 헷갈리게 하지 않는다
