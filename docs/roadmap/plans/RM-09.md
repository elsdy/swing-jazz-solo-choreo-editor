# RM-09 명령 등록부 — 라벨·단축키·실행의 주인 하나

되돌리기 · 재생 · 끊기 · 영상 열기 · 프로젝트 이름처럼 같은 일을 하는 입구가 여러 곳에 따로 있어 라벨 · 툴팁 · 글쇠가 서로 어긋난다. 그래서 명령마다 id · 라벨 · 툴팁 · 기본 글쇠 · 「지금 할 수 있나」를 도메인 표 한 벌에 적고, 버튼 · 글쇠 · 엄지 줄이 모두 그 표를 따르게 한다. 그 위에 Ctrl+K 팔레트와 `?` 일람을 얹는다. 판의 RM-36(엄지 줄)과 파일이 겹친다. RM-10(라벨 문자열 표) · RM-13(키보드 편집) · RM-14(선택 액션 바) · RM-18(아이콘 열)이 이 표 위에 서고, RM-15 와는 `?` 글쇠가 부딪친다. RM-05 의 D-14 대조와 RM-06 의 라벨 긁기는 이 표를 읽도록 바뀐다.

크기 L · 2026-10-01 에 판에서 다시 다듬었다

## 다시 다듬기 전의 설명

> 지금은 같은 명령(영상 열기 · 되돌리기 · 프로젝트 이름 등)이 화면 여러 곳에 따로 만들어져 있다. 그래서 라벨 · 툴팁 · 단축키가 제각각 어긋난다. 명령마다 이름 · 라벨 · 툴팁 · 단축키 · 실행을 한 표에 적고 모든 버튼과 글쇠가 그 표를 따르게 한다. 그 위에 Ctrl+K 명령 팔레트와 `?` 단축키 일람을 얹는다.

## 요구

- 도메인 층에 순수 데이터로 된 명령 표 하나를 둔다(id · 라벨 · 툴팁 · 기본 글쇠 · 고정 여부 · 어느 보드에서 유효한가). 지금 단축키 표의 여섯 동작(capture · skip · play · stop · undo · redo)은 id 와 기본 글쇠를 바꾸지 않고 이 표에 흡수한다
- 브라우저에 저장된 사용자 글쇠(`{id: 글쇠[]}`)는 등록부로 옮긴 뒤에도 그대로 읽힌다. 정규화 · 충돌 규칙(한 글쇠는 한 명령) · 고정 명령 보호도 지금과 같다
- 같은 일을 하는 입구는 라벨 · 툴팁을 명령 id 로 표에서 받는다. 메인 · 루틴 편집기의 Undo/Redo, 엄지 줄의 재생 · 끊기 · 건너뛰기 · 그만, 영상 파일 열기, 프로젝트 이름이 그렇다. 표로 옮기는 구조 커밋에서는 화면 글자가 한 자도 바뀌지 않는다
- 글쇠 처리는 표를 순회한다. Ctrl/Cmd+Z · Ctrl+Y 하드코딩도 표로 들어온다. 다음 넷은 지금과 같게 둔다 — 글자를 치는 중에는 홑글쇠를 듣지 않는 가드, 재생기가 포커스를 쥐면 Space 를 비켜 주는 규칙, Escape 의 차례(받아 적기 끝내기 → 고른 동작 풀기), 메인 보드 기본값(보존 결함 #11)
- 표의 명령마다 조립부에 실행이 이어져 있는지 검사가 맞춰 센다. 빠진 실행은 부팅 경고가 아니라 검사에서 붉게 잡힌다(D-14 를 등록부 기준으로 바꾼다)
- 명령마다 「지금 할 수 있나」를 판정하는 조건 하나를 둔다(되돌릴 것이 있나, 영상이 열렸나, BPM 이 정해졌나). 버튼 비활성과 팔레트의 회색 표시가 같은 판정을 쓴다
- 할 수 없는 명령을 글쇠나 팔레트로 부르면 RM-04 의 토스트 채널로 까닭을 알린다(브라우저 alert 를 부르지 않는다)
- Ctrl+K 로 명령 팔레트가 뜬다. 라벨 몇 글자로 후보를 고르고 Enter 로 실행하며, 못 하는 명령은 회색으로 뒤에 둔다. Esc 로 닫는다
- `?` 로 단축키 일람 한 장이 뜬다. 설정에서 바꾼 글쇠가 그대로 나온다
- ⚙ 설정의 `단축키` 갈래는 등록부의 글쇠 열을 읽어 그리고, 고친 값도 등록부 규칙으로 담는다
- 계층 규칙을 지킨다. 표는 도메인에 순수하게, 실행 연결은 조립부에만 둔다. 팔레트 · 일람(ui)과 글쇠 듣기(input)는 서로 import 하지 않고 주입받는다
- 구조 커밋 동안 골든 151개가 그대로 통과한다

## 손댈 자리

- 명령 표(도메인, 새 파일) — 단축키 표를 흡수하고 글쇠 풀이 · 할 수 있나 · 팔레트 찾기 · 일람 줄을 순수 함수로
- 단축키 표 — 지금의 내보내기 이름은 등록부를 읽는 얇은 겉으로 남겨 호출부를 한 번에 깨지 않는다
- 글쇠 듣기 bindHotkeys — Undo/Redo 하드코딩과 HOTKEY_COMMANDS 다리를 걷고 표를 순회한다
- 도구 모음 · 루틴 편집기의 Undo/Redo 버튼 — 라벨 · 툴팁 · 비활성을 표에서
- 엄지 줄의 재생 · 끊기 · 건너뛰기 · 그만 줄 — 라벨 · 툴팁을 표에서
- 영상 패널의 `📁 영상 파일 열기` 와 그 안내 문구, 파일 메뉴의 프로젝트 이름
- ⚙ 설정의 `단축키` 갈래
- 조립부 — 명령 id 와 실행을 잇는 자리 하나와 「할 수 있나」에 쓸 상태 읽기
- 새 화면 둘: 명령 팔레트(Ctrl+K), 단축키 일람(`?`)
- 검사기 D-14 규칙과 문서 라벨 대조의 출처
- 문서: 기능 설명서의 단축키 · 되돌리기 절, 튜토리얼의 되돌리기 절, 아키텍처, 원칙 D-14

## 순서

- RM-04~08 이 병합된 main 최신에서 브랜치를 딴다. 지금 작업 트리(stale-selection)는 그 병합 전 모습이다. 토스트 뷰 · check-principles · notice 시험이 없으므로 여기서 시작하지 않는다
- 화면의 버튼 · 글쇠 · 엄지 줄 · 팝업을 훑어 명령 목록과 입구가 여럿인 곳을 계획서에 표로 남긴다
- 구조 커밋 1: 도메인에 명령 표를 세운다. 단축키 표의 여섯 id 를 그대로 옮기고, 단축키 모듈의 내보내기는 표를 읽는 겉으로 둔다. 기존 단축키 시험 넷과 골든이 그대로인지 본다
- 구조 커밋 2: 글쇠 풀이를 순수 함수로 빼고 bindHotkeys 가 그것을 순회하게 한다. Undo/Redo 를 표로 옮기되 입력칸 가드 · Space 비키기 · Escape 차례 · 메인 보드 기본값은 그대로 둔다. 실행은 조립부의 runCommand 한 자리가 id 로 잇는다
- 구조 커밋 3: 검사기 D-14 를 「등록부 id ↔ 조립부 실행」 대조로 바꾸고 controls 의 부팅 경고를 등록부 기준으로 맞춘다
- 구조 커밋 4~: 입구를 한 곳씩 옮긴다(Undo/Redo 두 벌 → 엄지 줄 → 영상 열기 → 프로젝트 이름). 마크업에는 명령 id 를 달고 라벨 · 툴팁은 표에서 받는다. 커밋마다 화면 글자가 같은지 입구 대조 시험과 골든으로 확인한다
- 「할 수 있나」 판정을 표에 붙이고 도구 모음 · 루틴 편집기의 비활성 갱신이 그것을 쓰게 한다
- 동작 변경 커밋: 할 수 없는 명령의 실행을 토스트로 알린다
- 동작 변경 커밋: 어긋나 있던 라벨 · 툴팁을 하나로 맞춘다(예: 엄지 줄 `⏯` 의 title 과 단축키 라벨 `재생 · 일시정지`). 같은 커밋에서 기능 설명서 · 튜토리얼 인용을 고치고, 라벨 대조 검사의 출처를 등록부로 넓힌다
- ⚙ 설정 `단축키` 갈래가 등록부의 글쇠 열을 읽게 한다(바꿀 수 있는 범위는 질문 2의 답대로)
- 새 화면: 명령 팔레트(Ctrl+K)와 단축키 일람(`?`)을 ui 에 만들고 조립부가 실행 · 표를 주입한다(PR 단위는 질문 1의 답대로)
- 단위 시험 · 골든 · check-arch · check-docs · check-principles 를 모두 돌린다. /pre-pr-docs 로 아키텍처 · 원칙 D-14 · 로드맵 · 이력을 현행화한다

## 결정 사항

- 한 PR 로 낼까, 등록부와 새 화면을 쪼갤까
  - 등록부 먼저, 팔레트 · 일람은 뒤 PR (추천) — 첫 PR 은 구조 커밋 위주라 골든 그대로를 가리기 쉽다. RM-10 · RM-13 · RM-14 가 등록부만 들어와도 출발할 수 있다. 대신 Ctrl+K · `?` 는 한 번 더 기다린다
  - 셋을 한 PR 로 — 「입구가 하나」가 한 번에 보인다. 대신 PR 이 크고, 라벨 · 문서 고침이 한꺼번에 몰려 회귀를 가리기 어렵다
  - **고른 답**: 등록부 먼저, 팔레트 · 일람은 뒤 PR (추천)
- 사용자가 글쇠를 바꿀 수 있는 명령의 범위
  - 지금처럼 받아 적기 · 건너뛰기 · 재생만 (추천) — 설정 화면과 충돌 규칙이 그대로다. 나머지 명령은 기본 글쇠만 갖거나 팔레트로만 부른다. RM-13 의 편집 글쇠가 들어올 때 다시 정한다
  - 등록부의 고정 아닌 모든 명령 — 손에 맞추기 좋다. 대신 설정 화면이 길어지고 충돌 검사 범위가 넓어진다
  - **고른 답**: 지금처럼 받아 적기 · 건너뛰기 · 재생만 (추천)
- 팔레트 · 일람을 여는 글쇠
  - Ctrl/Cmd+K 와 Shift+/(`?`), 둘 다 고정 · 입력칸 가드 (추천) — 익은 관례다. 글자를 치는 중에는 듣지 않으므로 RM-15 의 이름 입력과 부딪치지 않는다. 브라우저가 Ctrl+K 를 먼저 가져가는 환경에서는 팔레트를 버튼으로도 연다
  - 둘 다 설정에서 바꿀 수 있게 — 충돌을 사용자가 피할 수 있다. 대신 바꿀 수 있는 명령이 둘 늘고, 일람을 여는 글쇠를 잊으면 일람으로 찾을 수도 없다
  - **고른 답**: Ctrl/Cmd+K 와 Shift+/(`?`), 둘 다 고정 · 입력칸 가드 (추천)

## 조심할 것

- 지금 작업 트리는 RM-04~08 병합 전이다. notify 가 alert 한 종류뿐이고 토스트 뷰 · check-principles 가 없다. 반드시 main 최신에서 시작한다
- 구조 커밋과 라벨 · 동작 변경 커밋을 섞지 않는다. 입구를 표로 옮기는 동안 화면 글자가 한 자라도 바뀌면 입구 대조 시험이 붉어져야 한다
- 저장된 사용자 글쇠의 id(capture · skip · play)를 바꾸면 옛 설정이 조용히 기본값으로 돌아간다. id 는 그대로 둔다
- Ctrl+Z 가 입력칸에서도 보드를 되돌리는 것과 루틴 편집기가 열려도 메인을 되돌리는 것은 보존 결함 #11 이다. 표로 옮기며 슬쩍 고치지 않는다. 고치려면 따로 동작 변경 커밋과 deviations 갱신으로 낸다
- Escape 는 뜻이 셋이다(받아 적기 끝내기 · 고른 동작 풀기 · 열린 메뉴 · 팔레트 닫기). 팔레트가 열려 있으면 팔레트가 먼저 삼키는 차례를 지킨다
- 실행 연결이 이름으로 이어지면 이름이 빠져도 조용하다(togglePlay 사흘 사고, D-14). 표 · 실행 연결 · 검사 셋이 같은 id 목록을 보게 한다

## 다시 다듬기 전의 계획서

### RM-09 명령 등록부 — 라벨·단축키·실행의 주인 하나

#### 풀어 본 설명 — 2026-09-29

지금은 같은 명령(영상 열기 · 되돌리기 · 프로젝트 이름 등)이 화면 여러 곳에 따로 만들어져 있다. 그래서 라벨 · 툴팁 · 단축키가 제각각 어긋난다. 명령마다 이름 · 라벨 · 툴팁 · 단축키 · 실행을 한 표에 적고 모든 버튼과 글쇠가 그 표를 따르게 한다. 그 위에 Ctrl+K 명령 팔레트와 `?` 단축키 일람을 얹는다.

##### 무엇

사용자가 보는 결과는 셋이다. 첫째, 같은 일을 하는 버튼은 어디에 있든 라벨 · 툴팁 · 단축키 표시가 똑같아진다. 영상 열기 5곳, 프로젝트 이름 3곳, 클립 목록 2벌, 메인 표와 루틴 편집기의 Undo 2벌이 한 명령을 가리키게 된다. 둘째, Ctrl+K 를 누르면 검색창이 뜬다. 명령 이름을 몇 글자 치면 후보가 나오고, Enter 로 그 명령을 실행한다. 버튼이 어디 숨어 있는지 몰라도 된다. 셋째, `?` 를 누르면 지금 쓸 수 있는 단축키 목록이 한 장으로 뜬다. 목록은 설정에서 바꾼 글쇠도 그대로 반영한다. 지금 단축키 표(받아 적기 · 건너뛰기 · 재생 · 그만 · 되돌리기 · 다시 하기, 6개)는 이 등록부의 한 열로 흡수된다.

##### 왜

지금은 명령 하나를 고치려면 흩어진 자리를 다 찾아다녀야 한다. 되돌리기만 해도 버튼 두 개가 따로 있고, 글쇠 처리는 입력 계층에 따로 박혀 있다. 그러다 보니 한 곳만 고쳐 라벨이 서로 달라지고, 문서가 옛 라벨을 인용한 채 병합되는 일이 반복됐다(`동작 팔레트` → `동작 목록`). 버튼이 89개라 무엇이 어디 있는지 배우기 어렵다. 단축키가 무엇인지도 설정 화면 깊숙이 들어가야 보인다. 로드맵은 M1 안의 순서를 「명령 등록부 → 포인터 통일 → 직접 조작 문법 → 토큰 · 아이콘」으로 못 박았다. 등록부가 없으면 정보 구조 · 라벨 문자열 · 문서 검사가 전부 다시 흔들리기 때문이다.

##### 어떻게

- 먼저 화면의 버튼 · 글쇠 · 팝업 메뉴를 전부 훑어 명령 목록을 만든다. 같은 일인데 입구가 여럿인 곳을 표시한다.
- 도메인 층에 순수 데이터로 된 명령 표를 둔다(id · 라벨 · 툴팁 · 기본 글쇠 · 어느 보드 · 어느 모드에서 유효한가). 지금의 단축키 표는 이 표의 한 열이 된다.
- 실행 함수는 표에 직접 넣지 않는다. 조립 층(app)이 id 와 유스케이스 커맨드를 이어 준다. 계층 규칙상 도메인은 유스케이스를 알 수 없기 때문이다.
- 명령마다 「지금 할 수 있나」(되돌릴 것이 있나, 영상이 열렸나)를 판정하는 조건을 함께 둔다. 버튼 비활성과 팔레트의 회색 표시가 같은 판정을 쓴다.
- 버튼은 라벨 · 툴팁을 HTML 에 직접 쓰지 않고 명령 id 로 표에서 받는다. 한 곳씩 옮기는 구조 커밋으로 내고, 골든은 그대로 통과해야 한다.
- 글쇠 처리도 표를 순회하게 바꾼다. 지금은 Undo/Redo 만 따로 박혀 있는데, 이것까지 표로 들어온다. 글자를 치는 중에는 듣지 않는 가드와 활성 보드 라우팅은 그대로 둔다.
- 실행 결과(실패 · 되돌릴 수 있음)는 RM-04 가 만든 알림 채널로 알린다.
- 마지막 걸음으로 명령 팔레트(Ctrl+K)와 단축키 일람(`?`)을 표 위에 얹는다. 둘 다 표를 읽기만 하는 화면이다.
- 튜토리얼 · 기능 설명서의 라벨 인용을 새 라벨에 맞춰 고친다. RM-05 의 대조 검사(D-14)와 RM-06 의 문자열 긁기는 이 표를 읽도록 바꾸거나 걷어낸다.

##### 조심할 것

- 구조를 옮기는 커밋과 라벨 · 동작을 바꾸는 커밋을 섞지 않는다. 버튼을 표로 옮기는 동안은 화면 글자가 한 자도 바뀌지 않아야 한다.
- 라벨이 바뀌면 튜토리얼 · 기능 설명서가 통째로 틀린 문서가 된다. RM-06 이 먼저 들어와 있으면 누락을 잡는다.
- Escape 는 한 글쇠에 뜻이 셋이다(받아 적기 끝내기 · 고른 동작 풀기 · 열린 메뉴 닫기). 각 메뉴가 따로 듣고 삼키는 지금 순서를 표로 옮기다가 깨뜨리기 쉽다.
- 저장된 사용자 단축키(`{id: 글쇠}`)의 id 를 바꾸면 옛 설정이 조용히 기본값으로 돌아간다. id 는 그대로 두거나 옮김 규칙을 둔다.
- 계층 규칙: 표는 도메인(순수), 실행 연결은 app 에만 둔다. ui 와 input 은 서로 import 하지 않으므로 팔레트는 주입받아 실행한다.
- 루틴 편집기의 Undo 는 다른 보드를 되돌린다. 같은 명령에 「어느 보드」 인자를 붙이는 식으로 합쳐야지, 둘을 한 버튼으로 뭉개면 안 된다.

##### 판의 옛 설명

> 라벨·툴팁·단축키·실행을 한 표에 두고 모든 버튼이 그것을 참조한다. 같은 명령이 다섯 곳에 흩어진 것이 모이고, 명령 팔레트와 단축키 일람이 그 위에 선다.
