# RM-32 영어 UI

## 풀어 본 설명 — 2026-09-29

앱의 버튼·메뉴·안내·오류 문구를 영어로도 내고, 설정에서 언어를 고르게 한다. 스윙 커뮤니티는 나라를 넘나들고 동작 이름(Swing Out, Tuck Turn 같은)은 이미 영어인데, 화면 글자는 한국어 한 벌이라 영어권 댄서·강사는 쓸 수 없다. RM-10 이 글자를 표 하나로 모은 뒤, 그 표에 영어 한 벌을 옆에 놓는 일이다.

### 무엇

설정 화면(⚙ 설정)에 「언어」 고르기가 생기고, 영어를 고르면 도구 모음·파일 메뉴·동작 목록·영상 패널(① 영상 고르기부터 ⑥ 자세까지)·블록 팝업·루틴 편집기·확인 버튼(`정말요?` → `Sure?`)·토스트와 오류 문장까지 영어로 바뀐다. 고른 언어는 이 브라우저의 취향으로 기억된다(기둥 C 의 「설정은 테마·단축키·언어」). 사용자가 적은 것 — 동작 이름, 카테고리, 루틴 이름, 마디 메모 — 는 번역하지 않는다. 그것은 사용자의 자료다. 날짜 표시(저장 목록·휴지통)도 고른 언어의 꼴을 따르고, 문서의 `<html lang>` 도 함께 바뀌어 화면 읽기 도구와 맞춤법 검사가 제 언어로 돈다.

### 왜

지금 화면 글자는 `index.html` 의 정적 버튼, `src/ui` 의 여러 파일, 유스케이스가 돌려주는 알림 문장, 서버의 오류 문장까지 여러 겹에 한국어로 박혀 있다. 동작 이름과 카테고리 키는 이미 영어이고 스윙 수업·워크숍·영상 자료는 영어권에서 더 많이 돈다. 한국어 한 벌이면 앱을 남에게 권할 수 없고, 외국 강사와 안무표를 주고받을 때도 받는 쪽이 화면을 읽지 못한다. 로드맵은 이 일을 마지막 이정표(M4 「기록이 쌓인다」)에 두었다 — 시장 언어(Q3)를 정한 뒤, 글자의 주인이 하나가 된(RM-10) 뒤에 해야 한 번에 끝나기 때문이다.

### 어떻게

- RM-10 이 만든 라벨 문자열 표(한국어 한 벌, 키로 찾는 꼴)에 같은 키로 영어 한 벌을 옆에 놓는다. 영어 칸이 빈 키는 한국어로 떨어지고, 시험이 빈 칸의 수를 센다.
- RM-10 이 라벨·툴팁·플레이스홀더만 모았다면, 남은 안내 문장·오류·토스트·확인 문구를 이 항목에서 표로 마저 옮긴다. 먼저 글자를 한 자도 바꾸지 않는 구조 커밋으로 옮기고(골든 그대로), 영어를 더하는 것은 따로 낸다.
- 숫자·이름이 끼는 문장(「N개를 놓았습니다」 같은)은 글자 조각이 아니라 인자를 받는 함수로 담는다. 한국어 조사(을/를)와 영어 복수형(1 move / 2 moves)이 같은 틀로 안 풀리기 때문이다.
- 설정 화면에 언어 고르기를 두고, 고른 값은 브라우저 저장소에 둔다. 바꾸면 화면 전체를 다시 그린다 — 안무표 파일에는 아무것도 적지 않는다.
- `index.html` 의 정적 버튼은 표의 키를 달고 부팅 때 고른 언어로 채운다(RM-10 이 정한 방식을 그대로 따른다).
- 날짜 표시는 고른 언어를 넘겨 그 꼴로 찍는다.
- RM-06 의 라벨 인용 검사는 한국어 문서를 한국어 칸과 대조하도록 기준을 다시 세운다(RM-06 계획서가 「RM-32 뒤에는 기준을 다시 세워야 한다」고 적어 두었다).
- 기능 설명서·튜토리얼에 「언어」 설정을 적고, 영어로 바꾸는 법을 한 줄 더한다.

### 갈리는 대목

- 어디까지 영어로 내나
  - 앱 화면만 — L 크기 안에 든다. 대신 서버 관리 화면(/admin)과 서버가 돌려주는 오류 문장(서버 쪽 한국어 문구가 수백 줄), 문서 허브의 문서는 한국어로 남아, 영어 사용자가 오류를 만나면 한국어를 본다.
  - 앱 + 서버 관리 화면·서버 오류 — 영어 사용자가 설치부터 오류까지 한국어를 안 만난다. 대신 서버는 `src/` 를 import 하지 않으므로 표를 따로 한 벌 두거나, 서버는 오류 코드만 주고 앱이 문장을 고르게 바꿔야 한다.
  - 문서(튜토리얼·기능 설명서)까지 — 처음 오는 영어권 사용자가 배울 길이 생긴다. 대신 문서가 두 벌이 되어, 라벨을 바꿀 때마다 네 문서를 고쳐야 하고 크기가 L 을 넘는다. 따로 항목으로 떼는 편이 낫다.
- 처음 켰을 때 무슨 언어로 뜨나
  - 브라우저 언어를 따라 자동 — 영어권 사용자는 아무것도 안 해도 영어로 본다. 대신 한국 사용자 중 브라우저가 영어인 사람은 갑자기 영어 화면을 보게 되고, 지금 쓰는 사람의 화면이 업데이트 한 번에 바뀔 수 있다.
  - 늘 한국어로 시작, 설정에서 바꿈 — 지금 쓰는 사람에게는 아무것도 안 바뀐다. 대신 영어권 사용자가 설정의 한국어 글자를 읽고 언어 고르기를 찾아야 한다 — 언어 고르기 자리만은 두 말로 적어 둘 만하다.
- 음성 인식(목소리로 동작 이름 붙이기·말로 짜기)의 언어를 화면 언어에 묶나
  - 화면 언어를 따른다 — 고를 것이 하나라 단순하다. 대신 영어 화면을 쓰는 한국 사용자가 한국어로 말하면 알아듣지 못한다.
  - 따로 고른다 — 동작 이름은 영어로 말하고 화면은 한국어로 보는 식이 된다 — 동작 이름이 이미 영어라 실제로 쓸모가 있다. 대신 설정이 하나 는다.

### 조심할 것

- 시장 언어(결정 Q3)가 아직 정해지지 않았다. 판은 RM-26 을 시작할 때 다시 보기로 했고, 영어권을 먼저 노리지 않기로 하면 이 항목은 더 뒤로 간다. 착수 전에 Q3 의 답을 먼저 받는다.
- 기본 카테고리·동작 이름처럼 앱이 처음 채워 주는 값은 한 번 파일에 들어가면 사용자의 자료다. 언어를 바꿀 때 이것을 번역하면 저장된 안무표가 바뀐 것처럼 보이고, 번역하지 않으면 새 사용자만 영어를 본다 — 처음 채울 때만 고른 언어로 채우는 쪽이 안전하다.
- 골든은 알림 문장과 순서를 기록한다. 문장을 표로 옮기는 커밋은 한 자도 바꾸지 않아야 골든이 그대로 통과한다. 옮기기와 번역을 한 커밋에 섞지 않는다.
- 영어 라벨은 한국어보다 길다. 영상 패널·도구 모음·엄지 바처럼 폭이 빠듯한 자리가 넘치거나 줄바꿈된다. 두 언어로 화면을 한 번씩 눈으로 본다.
- 문장 함수의 키 이름을 바꾸면 단축키 설정에 저장된 명령 id 와 섞이지 않게 조심한다(RM-09·RM-10 의 같은 주의).
- RM-04(알림 세 급)·RM-19(상시 안내 걷기)·RM-26(코치마크)이 문구를 새로 만들거나 옮긴다. 이 항목보다 먼저 들어가면 새 문구가 처음부터 표에 들어가는지 봐야 하고, 뒤에 들어가면 그 항목들이 영어 칸도 채워야 한다.

### 판의 옛 설명

> 화면을 영어로도 낸다. 스윙 커뮤니티는 국제적이고 동작 이름은 이미 영어다.
