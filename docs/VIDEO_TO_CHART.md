# 영상에서 안무표로 — 간격·기준·범위

영상을 연 다음에 무엇을 어떤 순서로 하는가. 지금 그 순서가 엉켜 있고, 엉킨 까닭과 푸는 방법을 적는다.
[편집 흐름](EDITING_FLOWS.md)이 "안무표를 **무엇으로** 채우나"라면 이 문서는 "영상을 연 뒤 **무엇부터** 하나"다.

## 세 가지가 한 자리에 섞여 있다

```
   지금 「② 박자 맞추기」 안에 든 것

   ┌──────────────────────────────────────────┐
   │ 여기가 [8x1] 의 [1] 카운트  [지금 여기]   │ ← 기준
   │   같은 버튼을 두 번 누르면 bpm 도 나온다   │ ← 기준 + 간격을 한 번에
   │                                          │
   │ ▸ 고급                                    │
   │    탭 템포                                │ ← 간격만
   │    BPM 직접 입력                          │ ← 간격만
   │    보정점                                 │ ← 간격의 흔들림
   └──────────────────────────────────────────┘

            범위는 어디에도 없다
```

서로 다른 세 가지가 한 단계에 눌려 있고, 셋째는 자리조차 없다.

| | 무엇인가 | 누구의 성질인가 | 언제 다시 정하나 | 지금 어디 |
| --- | --- | --- | --- | --- |
| **간격** | 1카운트가 몇 초인가 (bpm · 1카운트=몇 박) | **곡**의 성질 | 곡이 바뀔 때만 | ② 안, 일부는 `고급` 뒤 |
| **기준** | 이 영상의 몇 초가 어느 카운트인가 (anchorSec·anchorCount) | **영상**의 성질 | 테이크마다 | ② 안 |
| **범위** | 이 영상이 안무표의 어디부터 어디까지를 덮는가 | **영상**의 성질 | 테이크마다 | **없다** |

간격이 곡의 성질이라는 것은 이미 코드가 알고 있다 — 새 영상을 더하면 bpm 은 물려받고 앵커는 안 물려받는다
(2026-09-12, [로드맵](ROADMAP.md)의 결정 기록). 그런데 **화면은 그 구분을 보여 주지 않는다.**

## 범위가 없어서 생기는 일

```
   영상: 2분 26초짜리, A파트만 찍었다
   안무표: 8x8 (64카운트)

   지금 ─────────────────────────────
     8x1 ████████
     8x2 ████████
     8x3 ████████   세로선이 여기까지 왔다가
     8x4 ████████   ↓
     8x5 ████████   영상이 끝나도 도구는 아무 말이 없다
     8x6 ████████   "여기는 안 찍혔다" 를 말할 길이 없다
     8x7 ████████
     8x8 ████████
```

- 마커를 찍기 전에는 목록의 커버리지 막대가 `마커 없음` 이다 — 영상은 분명 무언가를 덮고 있는데.
- 「어느 테이크가 뒷부분을 담고 있나」를 눈으로 훑을 수 없다.
- 세로선이 영상 길이를 넘어가도 그대로 간다.

## 새 순서

```
   영상을 연다
      │
      ├─ ① 간격   이 곡의 1카운트가 몇 초인가
      │            소리에서 자동으로 재고, 틀리면 탭·직접 입력으로 고친다
      │            └ 곡이 같으면 다음 테이크에서 그대로 물려받는다
      │
      ├─ ② 기준   이 영상의 몇 초가 8x1 의 1카운트인가
      │            「지금 여기」 한 번
      │
      ├─ ③ 범위   이 영상이 표의 어디부터 어디까지인가
      │            ①②와 영상 길이로 **자동 계산**, 손으로 좁힐 수 있다
      │            └ 여기서 비로소 "이 영상은 A파트만" 이 도구의 사실이 된다
      │
      ├─ ④ 받아 적기 · ⑤ 자르기 · ⑥ 마커 · ⑦ 자세 분석
      │
      └─ 안무표 위에도 같은 사실이 보인다
```

```
   패널                      안무표
   ┌────────────────┐        마디  1 2 3 4 5 6 7 8
   │ ① 간격          │        8x1  ░░░░░░░░   ◀ 이 영상이
   │   178 bpm      │        8x2  ░░░░░░░░     담고 있는 곳
   │   1카운트 = 1박 │        8x3  ░░░░░░░░
   │                │        8x4  ░░░░░░░░
   │ ② 기준          │        8x5
   │   8x1 = 0:03.2 │        8x6              ◀ 밖은 비어 보인다
   │                │        8x7
   │ ③ 범위          │        8x8
   │   8x1 ~ 8x4    │
   └────────────────┘
```

### 왜 이 순서인가

앞이 뒤의 재료다.

```
   간격 ──┐
          ├──▶ 카운트 ↔ 초 변환이 성립한다 ──┐
   기준 ──┘                                  ├──▶ 범위를 계산할 수 있다
                        영상 길이 ───────────┘
                                                      │
                                  받아 적기 · 마커 ◀──┘
                                  (구간을 카운트로 접으려면 셋 다 필요하다)
```

지금은 ①과 ②가 한 버튼(`지금 여기` 두 번)으로 동시에 정해진다. 편해 보이지만 **두 번째 테이크에서 무너진다** —
간격은 이미 아는데 그 버튼은 간격부터 다시 재기 때문이다. 갈라 두면 두 번째 영상에서는 ②만 한 번 누르면 된다.

## 계획 — 네 단계

각 단계는 PR 하나다. 순서는 의존이 정한다 — 규칙이 먼저고 화면이 나중이다.

| 단계 | 무엇이 달라지나 | 요구 | 되돌리기 |
| --- | --- | --- | --- |
| 1 | 범위가 생긴다(계산값 + 손으로 고침) | 3 | ⚠ 저장 포맷이 바뀐다 |
| 2 | 소리에서 BPM 을 재 준다 | 2 | 쉽다(끄면 그만) |
| 3 | 단계가 셋으로 갈리고 안무표에 음영이 뜬다 | 1 · 4 | 쉽다 |
| 4 | 문서가 새 순서를 말한다 | 1 | 쉽다 |

### 1단계 — 범위

**무엇을.** 영상마다 「8x1의 1카운트 ~ 8x4의 8카운트를 덮는다」가 생긴다. 기본은 계산값이고, 「여기부터 여기까지」로 좁힐 수 있다.

**어디를** (안쪽부터)

- `domain/tempo.js` — `autoRange(tempo, durationSec, cols)`. 영상 길이를 **인자로 받는다**(도메인은 재생기를 모른다).
- `domain/project/media.js` — 클립에 `range: {fromCount, toCount}` 를 더한다. ⚠ **손으로 고쳤을 때만 파일에 쓴다** — 없으면 자동이라는 뜻이라, 안 건드린 사람의 저장 파일은 바이트가 그대로다.
- `domain/project/schema.js` — `CLIP_FIELDS` 에 `range` 한 칸. 키 순서가 곧 바이트다.
- `usecases/videoCommands.js` — `setClipRange` · `clearClipRange`(자동으로 되돌리기), `clipRange(store, durationSec)` 읽기.
- `ui/videoPanel.js` — 범위 줄과 「여기부터 여기까지」 고르개.

**어떻게 확인하나.** 단위 테스트 — 계산값이 (0초→첫 카운트, 길이→마지막 카운트)와 맞는가 · 손으로 고친 값이 왕복하는가 · 안 고친 클립은 `range` 키가 파일에 없는가 · 옛 파일이 그대로 열리는가. 화면에서는 8초짜리와 3분짜리 영상으로 막대 길이가 다르게 서는지 본다.

**⚠ 되돌리기.** 저장 포맷이 바뀐다. 새 앱으로 저장한 파일을 옛 앱에서 열면 `range` 가 조용히 버려진다(normalize 가 모르는 키를 버린다) — 범위만 잃고 나머지는 멀쩡하다.

### 2단계 — 소리에서 간격 재기

**무엇을.** 파일 영상을 열면 몇 초 안에 `BPM 178 · 확신 높음` 이 뜨고, 누르면 들어간다. 틀리면 탭·직접 입력은 그대로 있다.

**어디를**

- `domain/beatDetect.js`(신설) — `detectTempo(samples, sampleRate)` → `{bpm, confidence, candidates[]}`. **순수 함수다** — `Float32Array` 와 표본율만 받는다. 브라우저 API 는 한 글자도 없다.
- `adapters/audio/webAudioDecode.js`(신설) — 파일을 `decodeAudioData` 로 풀어 모노 `Float32Array` 로 만든다. 이 계층만 `AudioContext` 를 안다.
- `usecases/videoCommands.js` — `applyDetectedTempo`(bpm 만 넣고 **1카운트=몇 박은 건드리지 않는다**).
- `ui/videoPanel.js` — ① 간격 줄의 제안과 버튼.

**어떻게 확인하나.** 합성 신호로 못박는다 — 정확히 120bpm 클릭 트랙을 만들어 넣으면 120 이 나오는가, 소리 없는 신호는 `confidence 0` 인가. 그다음 실제 수업 영상 두 편으로 잰 값과 탭으로 잰 값을 나란히 놓는다.

**⚠ 정직하게 적을 것 둘.**

- **배수는 원리적으로 못 가른다.** 89 · 178 · 356 은 같은 비트열에 다 맞는다. 그래서 후보를 두엇 보이고, 자동으로 하나를 밀어 넣지 않는다.
- **박(beat)을 재지 카운트를 재지 않는다.** 스윙에서 1카운트가 2박인 안무가 있으므로 `beatsPerCount` 는 사람 몫으로 남긴다.
- 유튜브는 iframe 이라 소리를 읽을 수 없다 — 그쪽은 지금처럼 손으로 잰다. 화면이 그 사실을 말해야 한다.

### 3단계 — 순서와 화면

**무엇을.** 패널이 `① 간격` · `② 기준` · `③ 범위` 로 갈리고, 안무표에서 **영상이 담지 않은 마디가 비어 보인다.**

**어디를**

- `index.html` — 단계 마크업을 셋으로 가르고 번호를 다시 매긴다(받아 적기 ④ … 자세 분석 ⑦).
- `ui/videoPanel.js` — `renderTempo` 를 `renderInterval` · `renderAnchor` · `renderRange` 셋으로.
- `ui/boardView.js` — 범위 밖 마디에 클래스 하나. 채널 A(렌더)다 — 재생 헤드처럼 매 프레임 도는 값이 아니다.
- `app/render.js` — 범위가 바뀌면 보드가 더러워진다.

**어떻게 확인하나.** 범위를 좁히면 그 밖의 마디가 즉시 흐려지는가. 영상을 갈아타면 음영이 그 영상의 것으로 바뀌는가. 좁은 화면에서 세 단계가 접힌 채로 열리는가.

**⚠ 문서 세 곳이 함께 바뀐다.** 단계 번호를 인용한 곳이 [튜토리얼](TUTORIAL.md) · [기능 설명서](FEATURES.md) · [개발 이력](HISTORY.md)에 있다. 번호를 바꾼 커밋은 그 셋을 같이 고친다(저장소 규칙).

### 4단계 — 문서

튜토리얼의 영상 절차를 새 순서로 다시 쓰고, 기능 설명서에 `범위` 항목을 더한다. 이 문서의 「계획」 절은 그때 「한 일」로 바뀐다.

## 안 하는 것

- **자동으로 기준(앵커)까지 잡아 주기.** 비트를 찾아도 「그 비트가 8x1의 1카운트」인지는 안무를 봐야 안다. 사람이 한 번 누르는 편이 정직하고 빠르다.
- **유튜브의 소리 분석.** iframe 안의 소리는 읽을 수 없다. 우회하는 길(프록시·다운로드)은 이 도구가 갈 길이 아니다.
- **범위를 여러 토막으로.** 한 영상이 「8x1~8x4 와 8x9~8x12」를 덮는 경우가 있지만, 그것은 마커가 이미 하는 일이다. 범위는 **한 구간**으로 둔다.
- **박자 흔들림 자동 보정.** 보정점은 지금처럼 사람이 찍는다.

## 이 문서를 읽고 나서

1단계(범위)가 나머지의 재료다. 거기부터 시작하는 것을 권한다 — 저장 포맷이 바뀌는 유일한 단계라, 뒤로 미룰수록 그 위에 지어진 것이 많아진다.

다른 갈래의 작업은 [로드맵](ROADMAP.md)에, 안무표를 채우는 길 전체는 [편집 흐름](EDITING_FLOWS.md)에 있다.
