# 로드맵

이 문서는 앞으로 무엇을 만들 것인지와, 그것을 받아들이기 위해 지금 어떤 자리를 비워 두었는지를 적는다. 새 기능을 시작하기 전에 여기서 전제와 미결정 사항을 확인한다. 완료된 것은 [개발 이력](HISTORY.md)으로 옮긴다. **앞으로의 차례는 「상용화까지 — 퓨처 워크 로드맵」 절이 정한다**(2026-09-22) — 이 문서를 이어 쓸 때는 그 절부터 본다.

## 큰 그림

안무 편집기는 지금 "격자에 동작을 배치하는 도구"다. 앞으로는 **연습 도구**가 된다 — 안무 옆에 영상을 두고, 카운트와 재생 위치를 맞춰 보고, 연습이 쌓이는 동안 무엇이 나아졌는지 되돌아본다.

그 방향이 구조에 건 요구는 셋이다.

- 안무 격자의 좌표와 영상의 시각이 **한 축 위에서** 만나야 한다.
- ~~영상 시퀀스를 다루는 엔진은 **다른 프로젝트에서 통째로 들어온다.**~~ 2026-09-09 에 그 프로젝트를 실제로 열어 보고 전제가 틀렸음을 확인했다(아래 백로그 2번). 가져올 수 있는 것은 ffmpeg 래퍼 297줄이고, 그것도 서버를 도입해야 쓸 수 있다.
- 프로젝트가 시간축을 갖는다 — 한 안무의 여러 버전과 연습 기록이 함께 저장된다.

## 상용화까지 — 퓨처 워크 로드맵 (2026-09-22)

이 절은 **살아 있는 계획**이다. 아래 「구현 완료」·「백로그」·「결정 기록」이 지금까지의 기록이라면, 여기는 지금부터의 순서다. 앞으로 계획을 더 적을 때는 이 절에 적고, 끝난 것은 「구현 완료」와 [개발 이력](HISTORY.md)으로 옮긴다.

사용자의 말에서 출발했다 — "이 툴 특유의 촌스러움, 편집할 때 직관적이지 않은 것, 약간의 에러들을 생각하면 메뉴도 전반적으로 정리되어야 하고 기능도 더 추가되어야 한다. 진짜 상용화 가능한 수준으로 올리려면 뭘 개선해야 하는가." 그 말을 일곱 갈래(겉모습·편집·정보 구조·견고함·시장·온보딩·데이터)로 나눠 코드·문서·화면을 훑었고, 88개의 발견을 근거 줄 번호와 함께 모았다. 이 절은 그 발견을 **결정 → 기둥 → 이정표** 세 층으로 접은 것이다. 발견 자체는 여기 다 적지 않았다 — 항목마다 "왜"에 대표 근거만 남기고, 나머지는 [버그 기록](BUG_REPORTS.md)·[일부러 두고 온 것](deviations.md)·[편집 흐름](EDITING_FLOWS.md)이 이미 들고 있다.

### 지금 어디에 서 있나

이 도구는 **개인 도구로서는 드물게 잘 지어졌고, 상용 도구로서는 아직 문 앞이다.** 두 문장이 동시에 참이다.

잘 지어진 쪽부터. 영상의 초와 안무표의 카운트를 한 축에 놓는 것(재생 헤드 세로선·블록 클릭 점프·박자 두 번 찍기)은 조사한 안무 도구·코칭 영상 도구·음악 연습 앱 어디에도 없다. 영상을 보며 `K` 하나로 이름 없는 블록을 놓고, 말로 이름을 붙이고, LLM 이 표기를 고쳐 끼우는 **받아 적기**는 사람이 하는 순서(자리 먼저, 이름 나중)를 도구가 따르게 한 설계다. 영상이 컴퓨터 밖으로 나가지 않고 데이터가 열린 JSON 인 **로컬 우선**, 단위 시험 253개·골든 150개·계층 검사·문서 검사가 몇 초에 도는 **안전망**, 앱 안에서 읽히는 문서와 결정 기록의 **문화** — 상용 도구가 가장 자주 깨뜨리는 약속(옛 파일이 그대로 열린다, 실수를 되돌린다, 왜 그렇게 만들었는지 안다)을 이미 지키고 있다.

문 앞인 쪽은 숫자로 적는다. 느낌이 아니라 잰 값이어야 다음에 다시 잴 수 있다.

| 무엇 | 잰 값 | 상용 기준으로 무슨 뜻인가 |
|---|---|---|
| 화면의 버튼 | **89개**, 그중 45개가 영상 패널 하나에 | 배울 것이 89개다. 자주 쓰는 것은 열 개가 안 된다 |

| 작업 문서 | `_작업중` **한 칸**, 1.2초 덮어쓰기 | 두 탭·두 기기가 서로 지운다. 실측: 이름 붙은 안무가 저장본 없이 초안에만 살아 있었다 |
| 서버 저장 | 제자리 덮어쓰기, 이전 판 없음, 휴지통 없음 | 쓰다 죽으면 반쪽 파일. 삭제 두 번 누름이 영구 삭제 |
| 내보내기 | **JSON 하나** (인쇄 CSS 0, 이미지 0, 텍스트 0) | 학생에게 줄 종이 한 장을 못 만든다 |
| 입구 | `git clone` + `python3 server.py` | 돈을 내는 사람은 터미널을 열지 않는다 |

### 상용화의 정의 — 네 문장

"상용화 가능한 수준"을 기능 목록으로 정하면 끝이 없다. 대신 **저자가 아닌 사람** 하나를 세워 놓고 네 문장으로 정한다. 아래 이정표의 완료 기준은 전부 이 넷에서 나온다.

1. **설치 없이 10분 안에 첫 안무표를 만든다.** 유튜브 링크 하나 들고 온 댄서가 터미널·문서 없이 표를 채우고 영상과 맞춰 본다.
2. **내 안무를 잃지 않는다.** 저장을 잊어도, 새로고침해도, 실수로 지워도, 어제 것으로 돌아갈 수 있다.
3. **눈이 편하고 손이 예측된다.** 어떤 화면을 찍어도 한 벌의 도구로 보이고, 잡으면 움직이고 두 번 누르면 열린다 — 배우지 않아도.
4. **남에게 줄 수 있다.** 학생·팀원이 이 앱 없이 볼 수 있는 한 장을 낸다.

### 0단계 — 먼저 정해야 하는 것 다섯

일곱 갈래 감사가 **같은 질문**으로 수렴했다. 이 답 없이 짠 설계는 답이 나오는 순간 다시 짜야 하므로, 코드보다 먼저 정한다. 각각에 권고를 적었다 — 근거가 바뀌면 권고도 바뀐다.

**① 배포 형태.** 지금은 세 형태(정적 호스팅 · 로컬 서버 · LAN 노출)가 각각 반쪽이다 — 정적은 영상 보관·LLM 이 없고, 로컬은 폰이 못 붙고, LAN 은 인증이 없다. 공유·동기화·백업·초안 충돌·알림·브라우저 지원의 설계가 전부 이 답에 달려 있다.
권고: **로컬 우선을 정체성으로 못 박고, 데스크톱 패키지로 간다.** `server.py` 와 ffmpeg 을 품은 설치형 앱(맥·윈도우) 하나가 주 입구이고, 폰은 같은 와이파이의 PC 서버에 붙는 「보기·연습」 화면이다. 「빌드 도구 없음」은 *저장소의 앱 코드*에만 적용하는 것으로 범위를 다시 적는다 — 포장 단계에서만 도구를 쓰고, 앱은 지금처럼 브라우저가 그대로 읽는 ES 모듈이다. 호스팅 웹앱은 「클라우드 저장 안 함」 결정을 뒤집어야 하고 계정·결제·동기화 인프라가 딸려 오므로, 공유 기능이 실제로 쓰이는지를 근거 조건으로 「정하기를 미룬 것」에 둔다.

**② 첫 대상과 수익 모델.** 혼자 배우는 댄서(지금 가장 잘 됨, 지불 의사 낮음, 인프라 거의 불필요) · 강사(지불 의사 높음, 공유·판본·학생 뷰 필요) · 스튜디오(계정·권한·동기화까지). 셋을 동시에 겨냥하면 가장 무거운 인프라를 가장 먼저 치른다.
권고: **혼자 배우는 댄서 + 소규모 강사(공유 뷰까지)** 를 1차 대상으로, 모델은 **계정 없는 1회 구매(또는 연 갱신 라이선스)**. 로컬 우선과 맞고 서버가 필요 없다. 스튜디오·구독은 공유 뷰의 사용량이 근거를 만들면 다시 본다.

**③ 시장 언어.** 동작 이름·카테고리 키는 이미 영어인데 UI 는 한국어 하나이고 문구가 마크업·`ui/*.js`·문서 세 겹에 박혀 있다. 스윙 커뮤니티는 국제적이다.
권고: **문자열의 주인을 하나로 만드는 일(기둥 C)을 지금 하고, 영어는 그 위에 두 번째로 얹는다.** 정하지 않은 채 문구를 늘리면 개명·문서 대조·번역 비용이 함께 는다.

**④ 라이선스.** README 는 GPL-3.0 이라 하고 저장소의 `LICENSE` 파일은 GPL **v2** 원문이다 — 먼저 맞춘다. GPL 로 팔 수는 있지만 구매자가 소스를 재배포할 수 있어 1회 구매 모델의 가격 방어가 약하고, 단독 저작자인 지금은 재라이선스가 가능하지만 외부 기여가 한 건이라도 들어오면 CLA 없이는 어려워진다.
권고: **외부 기여를 받기 전에 정한다.** 후보는 듀얼 라이선스(소스 공개 + 상용), 독점 전환, 공개 유지 중 하나이고, 이 결정은 ②와 같은 회의에서 한다.

**⑤ 원본 동작 보존 원칙의 졸업.** 재구성(2026-09-07) 때 세운 "원본 `index.html` 과 한 줄도 다르면 안 된다"와 "골든은 결함까지 기록한다"는 원칙이 지금도 편집 UX 의 기준이다. 기둥 B 의 개선은 거의 전부 동작 변경이라, 지금 원칙으로는 손질 하나마다 골든 재기록·`intentionalChanges`·deviations 갱신이 붙어 작은 개선이 무거운 커밋이 된다.
권고: **이정표 M1 시작을 그 원칙의 졸업일로 삼는다.** 그날부터 골든은 「현재 동작의 기록」이 아니라 「정한 규칙의 명세」이고, 결함 시나리오는 의도한 기대값으로 다시 적는다. `boardController` 의 "통일하지 마라" 류 경고는 그 커밋과 함께 걷는다. 「동작 변경과 구조 변경을 섞지 않는다」는 그대로다 — 바뀌는 것은 *무엇이 기준인가*이지 *어떻게 바꾸는가*가 아니다.

### 다섯 기둥

기둥은 종류이고 이정표는 차례다. 기둥마다 한 문장의 목표, 할 일, 끝났다고 말할 수 있는 기준을 적는다. 할 일의 근거는 감사에서 왔고 대표 하나만 달았다.

#### 기둥 A — 겉모습: 한 벌의 도구로 보인다

목표: **어떤 화면을 찍어도 같은 손이 만든 것으로 보인다.** "미래지향"이 아니라 **조용하고 정확한** 톤이다 — 격자는 이미 그렇다. 나머지가 격자를 따라간다.

- **디자인 토큰 한 벌.** 색 8개(배경 2·면 2·글자 2·강조 1·경고 1)에 상태색 셋, 글자 4단(11·12·13·15), 간격 4단(4·8·12·16), 모서리 3단(6·10·999), 그림자 2단. 지금 26개 토큰 밖에서 적힌 hex 75가지·rgba 214가지를 이 안으로 접는다. 테마는 이 토큰만 바꾸는 것으로 정의를 고친다(지금은 `:root[data-theme]` 표면 규칙이 색 밖의 것까지 다시 적는다).
- **아이콘 한 벌.** 이모지 29개를 인라인 SVG `<symbol>` 스프라이트(의존성 0, `index.html` 안)로 바꾼다. 텍스트 라벨이 주인이고 아이콘은 보조다. 눈이 먼저 가는 자리(채우기 줄·엄지 바·작업 차례 띠)부터.
- **발광·유리를 뜻 있는 자리로만.** 발광 31곳을 「지금 있는 자리」·「듣는 중」·「경고」 셋으로 줄인다. `backdrop-filter` 8곳은 떠 있는 것(팝업·설정)에만.
- **기본 테마를 완성하고, neon·rose·candy 는 「분위기」로 강등.** 상용 첫인상은 기본 테마가 만든다. 세 테마는 토큰만 갈아 끼우는 것으로 남고, 기본과 다른 표면 규칙을 갖지 않는다.
- **상시 안내 문장 14곳을 걷는다.** 툴팁과 「처음 한 번」 안내(코치마크)로 옮기고 평소에는 비운다. 하는 일이 라벨에 적혀 있으면 문장이 필요 없다.
- **모션은 뜻 있는 것만.** `btnInvite` 류 "눌러 달라"는 깜빡임은 첫 실행 코치마크에서만. 상태 전환(듣는 중·받는 중)과 되돌리기 토스트에는 짧고 같은 곡선 하나.
- **빈 화면의 질.** 빈 안무표는 네 동사 나열 대신 한 걸음("예제를 열어 보거나, 영상을 넣으세요")과 예제 하나(기둥 E).

끝났다고 말할 수 있을 때: `index.html` 스타일에서 토큰 밖 색이 0, 글자 크기 5가지 이하, 이모지 라벨 0, `.helper` 상시 노출 0, `!important` 0. 그리고 다섯 화면(첫 화면·받는 중·설정·문서·폰)을 나란히 찍었을 때 한 벌로 보인다 — 이건 사람이 본다.

#### 기둥 B — 편집: 잡으면 움직이고, 두 번 누르면 열린다

목표: **타임라인 편집기의 문법 하나를 마우스·터치·키보드가 똑같이 따른다.** 배우지 않아도 되는 조작이 기본이고, 더블클릭·Alt·우클릭은 그 위의 가속 경로다.

- **직접 조작 문법.** 몸통 드래그 = 이동(임계 이동 전까지는 클릭), 양쪽 가장자리 = 트리밍(왼쪽은 시작점 이동 — 지금은 없다), 몸통 더블클릭 = 이름/동작 정하기, 삭제는 Delete·선택 액션 바·팝업으로만 열고 지운 뒤 「지웠습니다 · 되돌리기」 토스트. 손잡이 장식은 hover·선택 때만. (근거: `boardController.js` dblclick → `removeGroup` 확인 없음, 1c 블록 50px 에 손잡이 둘 60px)
- **포인터 이벤트 하나로 마우스·터치 통일.** 갈림은 창 폭이 아니라 `pointerType`·`(pointer: coarse)`. 터치 그리기의 행 넘김·복사·루틴 블록 가드가 마우스와 같아진다. 이것이 ⑤ 졸업의 첫 커밋이다.
- **선택을 편집 단위로.** Shift+클릭 범위, 빈 칸 드래그 마퀴, 선택 묶음 드래그 이동, 선택 액션 바(이름·복제·분할·삭제·이 대목 재생). 지금 선택의 소비자는 둘뿐이다.
- **키보드.** 화살표 한 칸·Shift+화살표 한 마디·Delete·Ctrl+C/V/D·Ctrl+A·Ctrl+S. 입력창 가드와 활성 보드 라우팅 플래그는 이미 있다 — 켠다.
- **인라인 이름 편집.** 선택된 블록에서 타이핑을 시작하면 그 자리에 입력이 뜨고 동작 목록·최근 이름이 자동완성된다. Enter 확정, 없으면 그 자리에서 등록, **Tab 으로 다음 `?` 블록**. 지금 세 단계(선택 → 20px `✎` → 팝업)가 한 단계가 된다.
- **분할·병합·행 편집.** 재생 헤드에서 자르기(`S`), 인접 같은 이름 병합, 행 라벨 우클릭으로 마디 삽입·삭제·복제·이동. 전부 도메인 전이 하나씩이라 골든 150은 그대로다.
- **「미리보기 = 결과」 불변식.** 잘리면 잘린 숫자와 경고색, 아니면 행을 늘린다. 행 줄이기는 블록이 있으면 막는다. 다섯 놓기 경로의 미리보기를 공용 헬퍼 하나로.
- **층(겹침) 규칙의 마지막 문장.** "겹침이 사라지면 층은 즉시 위로 당겨진다"인지 "층은 사용자가 정한 것"인지 한 문장을 먼저 정하고(D-1), 그다음 미리보기에 「아래층으로 내려감」 표시와 `COPY_POLICY.repack` 통일. 네 번 뒤집힌 자리라 순서를 지킨다.
- **모드 셋을 하나로.** 빈 칸을 끌면 언제나 「자리 잡고 동작 고르기」이고, 골라 둔 카드는 그 팝업의 기본값일 뿐이다. `+ 빠른 배치` 버튼은 그때 사라진다. 기본 카운트는 스윙 관습(2) 또는 마지막 길이.

끝났다고 말할 수 있을 때: [일부러 두고 온 것](deviations.md)의 「터치와 마우스의 불일치」 표가 비고, FEATURES 의 제스처 표에 '없다' 칸이 없고, 처음 보는 사람이 설명 없이 블록을 옮기고·늘이고·이름 붙이고·지운다(다섯 명에게 시켜 본다).

#### 기둥 C — 정보 구조: 무엇이 어디 있는지가 배울 만하다

목표: **세 층(앱 → 무엇으로 채울까 → 안무표 자체)을 뼈대로 지키되, 같은 일은 한 자리, 같은 것은 한 이름.** 이 층 구분은 2026-09-20~22 에 이미 맞는 방향으로 움직였다 — 끝까지 간다.

- **명령 등록부 하나.** id·라벨·툴팁·단축키·실행을 한 표에 두고 채우기 줄·엄지 바·배지·팝업·팔레트가 그것을 참조한다. 영상 열기 5곳·프로젝트 이름 3곳·클립 목록 2벌·Undo 2벌이 이 표로 모인다. 문자열 표(③)와 단축키 표(`hotkeys.js`)가 여기 흡수된다.
- **용어집 한 장.** 안무표·영상·동작·루틴·구간·마커·마디·카운트·박자. 지우기(되돌릴 수 있음)와 삭제(되돌릴 수 없음)를 가른다. `Undo/Redo` → 되돌리기/다시 하기, `[ In 지금 여기` → 시작점. 라벨·툴팁·오류·문서가 이 한 장을 따른다.
- **영상 패널을 「차례」와 「도구」로 가른다.** ①②③(고르기·박자·받아 적기)만 번호와 완료 표시를 갖고, ④⑤⑥(구간·마커·자세)은 도구 탭이다. 유튜브 URL 은 `① 영상 고르기` 안으로 — 지금은 층이 다른 `🔗 링크` 안에 숨어 있다. 박자 맞추기는 첫 경로 하나(탭 → 확인 → 첫 박)로 좁히고 두 점·보정점은 「세로선이 어긋날 때」 아래로.
- **설정은 이 브라우저의 취향만.** 테마·단축키·언어. 서버에 속한 것(보관 자리·LLM·모델)은 `서버 ↗` 하나로, 모델 내려받기는 `⑥` 을 처음 켤 때 그 자리에서, 작업 차례 로그는 개발 갈래로.
- **파일 층을 파일 메뉴 하나로.** 최근 열기를 파일 메뉴 안으로, 동작·카테고리 저장/열기는 「내 동작 사전」의 내보내기/가져오기로 접고, 사이드바의 `파일` 서랍은 없앤다.
- **상태줄 하나 + 토스트.** 받는 중·듣는 중·저장됨·되돌릴 수 있음이 한 자리에 선다. `alert`/`prompt` 는 복구 불가능한 실패에만 남기고 성공은 토스트, 이름은 인라인.
- **파괴적 조작 규칙 한 벌.** 되돌릴 수 없는 것은 메뉴 안 + `정말요?`, 되돌릴 수 있는 것은 그 자리 + 토스트. `✕` 는 닫기에만. 루틴 편집기의 `초기화` 가 이 규칙을 따른다.
- **Ctrl+K 명령 팔레트와 `?` 단축키 일람.** 명령 등록부 위에 얹는다. 빈 칸·행 머리에 컨텍스트 메뉴.
- **루틴 편집기는 별도 툴바가 아니라 편집 모드.** 상태줄에 「루틴 편집 중 — 완료」, Undo·빠른 배치는 메인 것을 그대로 쓴다. 스크롤 잠금 두 버튼은 엄지 바에 흡수.

끝났다고 말할 수 있을 때: 정적 버튼이 89개에서 절반 아래로, 라벨 문자열의 주인이 파일 하나, `check-docs` 가 문서의 백틱 인용을 그 파일과 대조해 통과, 같은 일의 입구가 화면에 하나.

#### 기둥 D — 견고함과 데이터: 잃지 않는다, 되돌린다, 설명 없이 실패하지 않는다

목표: **데이터 신뢰의 세 기준을 코드가 지킨다.** 이 기둥의 절반은 표준 라이브러리 안에서 며칠이면 되는 일이고, 그 며칠이 상용화의 첫 신뢰를 산다.

- **원자적 쓰기 · 롤링 스냅샷 · 휴지통.** 임시 파일에 쓰고 `os.replace`, 덮어쓰기 전 직전 판을 `.history/` 에 N개, 삭제는 `.trash/` 로 이동 후 앱에서 복구. (근거: `server.py` `_put_project` 가 `write_bytes` 로 제자리 덮어쓰기, `_delete_project` 는 `unlink`) **(완료 2026-09-22 — 서버 API 넷과 파일 서랍의 `휴지통 · 복구` 줄. 이력을 고르는 화면은 M2 의 안전망 판본에서)**
- **이름이 붙는 순간 그 이름의 파일로 자동 저장.** `프로젝트 저장` 은 「파일로 내보내기」로 격하. 지금은 자동 담기가 「저장했다」는 착각을 준다 — 실측에서 이름 붙은 안무가 초안 한 칸에만 살아 있었다. **(완료 2026-09-22 — 한 번 저장하거나 폴더에서 열면 그 파일에 «묶이고» 자동 담기가 거기로 간다. 파일 메뉴 맨 위 줄이 어디에 담기는지 적는다. 라벨을 `내보내기` 로 바꾸는 것은 기둥 C 의 용어집과 함께 — 라벨 하나를 문서 둘과 함께 고치는 일이라 그 묶음에 넣는다)**
- **초안을 프로젝트별·기기별 칸으로.** 페이로드에 시각·기기 토큰을 실어 더 새 것을 덮으려 하면 거절, 같은 브라우저 탭 사이는 `storage` 이벤트로 「다른 탭에서 편집 중」. **(완료 2026-09-22 — 칸이 프로젝트별로 갈라졌고(위 항목), 담기마다 «내가 아는 판»(mtimeNs)을 함께 보내 지금 파일이 다르면 서버가 409 로 거절한다. 거절당한 쪽은 담기를 멈추고 파일 메뉴가 빨갛게 고를 것을 적는다. 기기 토큰과 `storage` 이벤트는 만들지 않았다 — 두 탭도 같은 파일을 쓰므로 이 한 장치가 둘 다 잡는다)**
- **미래 스키마 거부 → v2 쓰기.** 도메인은 준비됐고(`migrations.js` 원칙 3) 유스케이스가 문을 열어 뒀다(`readProjectData` 가 날값 통과). 거부를 **먼저** 배포하고, v2 쓰기 전환은 그 뒤 동작 변경 커밋으로. **(거부 완료 2026-09-22 — 파일·최근 목록·작업 문서 네 경로 전부. 작업 문서였으면 담기까지 멈추고 화면이 그 사실을 적는다. v2 쓰기 전환은 남았다)** 프로젝트에 이름과 독립된 id 를 실제로 발급하고 영상 폴더를 그 id 로 — 이름 바꾸기가 「새 파일 하나 더」인 것을 끝낸다.
- **필드 등록표 하나.** `{key, normalize, serialize, isEmpty, dirty}` 를 `schema.js` 한 표로 두고 history·normalize·serialize 가 순회한다. 「DOC_FIELDS 전부가 저장→열기→Undo 왕복에서 살아남는다」를 자동 생성 시험 하나로. 필드 하나에 손으로 훑을 자리 다섯이 하나가 된다.
- **알림 세 급.** 막는 오류 → 모달, 알아야 할 실패 → 토스트, 참고 → 상태줄. 조용한 catch 27곳은 「실패를 상태로 기록」으로. 서버 오류 문구는 한국어 코드+문구로.
- **정적 경로의 localStorage 를 IndexedDB 로.** 포트는 이미 Promise 계약으로 예비돼 있다. 최근 목록은 메타만, 본문은 따로.
- **지원 매트릭스.** OS × 브라우저 × 서버 유무 × 기능 표 하나를 문서와 설정에 같이 두고, 부팅 때 「이 브라우저에서 안 되는 것」을 한 번 모아 보인다. 폰의 확대 차단(`user-scalable=no`)은 입력 요소 16px 로 바꾸고 걷는다(U-10).
- **화면·터치 계층의 시험, 두 단.** ① DOM 없이 도는 부분(히트 판정 산술·포인터 상태기계·팝업 위치)을 분리해 `node:test` 로 — 의존성 0 안에서 된다. ② 실제 브라우저 회귀는 개발 전용 도구(Playwright 류)가 필요하다 — ①-배포 형태 결정에서 「개발 도구는 devDependency 로 허용」을 함께 정한다.
- **`check-principles`.** grep 으로 잡히는 원칙(U-11 빈 속성·U-12 `display` 가 `[hidden]` 을 이김·D-5 `Number(x) || fallback`·R-6 `className =` 통대입)을 검사기로 옮긴다. 원칙 26개를 사람이 리뷰마다 기억하지 않게.

- **배포 형태(①)의 실물.** 설치형 앱 하나. 서버는 포트가 쓰이면 물러나며 알리고(`--open` 으로 브라우저를 연다), 폰 접속은 QR 한 장.
- **예제 안무 하나를 열어 둔다.** 표준 루틴(Shim Sham 류) 8마디, 공개 영상 링크, 박자 포함. 받아 적기·박자·파트·반복이 첫 5분에 시연되고 강사에게는 교재가 된다. 스타터 팩(재즈 스텝 사전 + 루틴 2~3개)은 정적 파일로 동봉해 서버 없이도 열리게.
- **첫 실행 코치마크 3장.** 채우기 줄 → 동작 목록 → 영상. 준비되지 않은 입구(키 없음·서버 없음)는 비활성 + 이유. 채우기 줄의 첫 버튼이 첫 사용자에겐 막다른 길(`✨ 말로 채우기` 는 키가 있어야)인 것을 순서로 고친다.
- **맥락 도움말 `?`.** 단계·팝업·파일 메뉴마다 `?` 가 그 절의 앵커로 연다(`docsHub.open` 이 앵커를 받는다). 문서 허브는 「도움말」(튜토리얼·기능·바뀐 것)과 「개발」(숨김)로 가른다.
- **문서가 화면을 따라오게.** 튜토리얼·기능 설명서의 첫 절이 2026-09-20·21 개편을 못 따라왔다 — 라벨 인용을 명령 등록부와 대조하는 검사를 `check-docs` 에 더한다. 첫 절과 「새로고침하면 비워진다」(이제 거짓) 문장은 이번 PR 의 문서 패스에서 바로 고친다.
- **권한 요청은 한 줄 뒤에.** 마이크·폴더를 요청하기 직전에 목적과 데이터 행선지(음성은 구글 서버로)를 한 줄로.

끝났다고 말할 수 있을 때: 다섯 명에게 설치 파일과 유튜브 링크만 주고 지켜본다 — 셋 이상이 10분 안에 영상과 맞춘 안무표를 만들고, 문서를 열지 않는다.

### 추천 기능 다섯

기능을 더하는 기준은 하나다 — **이 도구의 정체성(영상 ↔ 카운트 한 축, 로컬 우선)을 강화하고, 위 네 문장 중 하나를 직접 채우는가.** 다섯을 골랐고, 고르지 않은 것도 아래 적었다.

**1. 카운트 시트 내보내기 — 종이 한 장, 이미지, 읽기 전용 HTML** (네 번째 문장 「남에게 줄 수 있다」)
안무표를 그대로 A4 한 장으로 내는 인쇄 CSS(브라우저 인쇄로 PDF 까지), 마디당 한 줄의 **텍스트 카운트 시트**(`8x3 · 1 Swing Out · 5 Kick Ball Change`) 클립보드 복사, 그리고 **자기완결 읽기 전용 HTML 한 장** — 안무표 + 시트 + 마커가 있으면 영상 타임스탬프 링크. 서버·계정 없이 브라우저만으로 된다. 텍스트 문법은 **가져오기와 같은 문법**으로 정해 메모장·스프레드시트에서 붙여 넣으면 배치가 되게 한다(없는 동작은 목록에 자동 등록). 강사가 돈을 내는 이유가 이것이고, 지금은 사진 캡처 말고 길이 없다.

**2. 마디 반복 연습기 — 카운트 단위 A-B 반복 · 배속 · 미러 · 카운트 소리** (첫째·셋째 문장)
반복 구간을 초가 아니라 **마디·블록·파트**로 잡는다("8x3 만 반복", "이 블록만 0.7배로"). 유튜브(IFrame API 의 `setPlaybackRate`·`seekTo`)와 파일이 같은 조작 줄을 쓰고, 좌우 반전은 CSS 한 줄이다. Web Audio 로 BPM 에 맞춘 클릭/카운트 보이스("1-2-3-4 5-6-7-8")를 재생 헤드와 같은 축에 올린다 — 영상이 있으면 그 위에, 없으면 표만으로. 학습 앱과 음악 연습 앱 전부가 배속·반복을 갖는데, 우리만 **카운트 축이 있어** 반복의 단위가 마디가 된다. `placementToSpan` 이 재료다.

**3. 파트(섹션) — 곡 구조를 1급으로** (셋째·넷째 문장, [편집 흐름](EDITING_FLOWS.md) 3단계의 승격)
마디 위의 묶음(intro · A · A · B · A · 코러스 2…)을 저장 포맷에 두고, 접기·통째 이동·복제·되풀이("B 파트 한 번 더")를 행 단위 편집(기둥 B) 위에 얹는다. 프레이즈 색은 이 위의 표시가 된다. 스윙 안무는 코러스·파트로 외우고 가르치므로 상용 기준에서는 선택이 아니라 기본이고, 2번의 반복 단위와 1번의 시트 구획이 여기서 나온다. 「시작하기 전에 정할 것」 — 마커와 합칠지 따로 둘지 — 를 먼저 정한다.

**4. `?` 정리함 — 이름 없는 블록 몰아서 붙이기와 되풀이 인식** (첫째·셋째 문장, [편집 흐름](EDITING_FLOWS.md) 2단계)
받아 적기가 만든 `?` 블록만 모아 한 화면에서 차례로 채우는 정리함. 블록을 고르면 영상이 그 대목을 반복 재생하고(2번), 인라인 입력(기둥 B)에 말로 이름 붙이기·LLM 표기 교정이 그대로 붙는다. **되풀이 인식** — 길이와 위치 패턴이 같은 `?` 를 "아까 그것"으로 묶어 한 번 이름 붙이면 전부 붙게 한다. 받아 적기(1단계)가 반쪽으로 남아 있는 까닭이 이것이다 — `?` 가 영영 `?` 로 남으면 영상을 다시 봐야 한다.

**5. 판본과 연습 기록 — 시간축** (둘째 문장, 「큰 그림」의 셋째 요구, 백로그 1 의 재정의)
두 층이다. 아래층은 **안전망 판본** — 저장할 때마다 직전 판이 남고(기둥 D), 「어제 것으로」가 한 번 누름이다. 위층은 **이름 붙인 판본**(A안·B안·공연본)과 **연습 기록** — 테이크마다 날짜·속도·메모, 나중에 자세 분석의 잰 값(가동 범위)이 여기 한 줄로 붙는다. "얼마나 나아졌는지"의 자동 계산(판본 사이의 안무 차이)과 사람이 남기는 것을 가른다. 프로젝트 = 한 안무 + 영상 여러 벌(날짜 축)이라는 개념이 이미 있으므로 그 옆에 판본 축을 세우는 일이다.

고르지 않은 것과 그 까닭 — **클라우드 동기화·공유 링크**는 ① 배포 형태와 공유 뷰의 사용량이 근거를 만든 뒤(「정하기를 미룬 것」). **자세 분석 비교 화면**은 5번의 연습 기록이 결과를 담을 자리를 만든 뒤 — 그전까지 자세 분석·LLM 채우기는 「실험」 라벨을 달아 기대치를 관리한다. **다인 실시간 편집**은 하지 않는다. **스타터 팩·예제**는 기능이 아니라 온보딩(기둥 E)이다.

### 차례 — 이정표 다섯

의존 관계로 줄을 세웠다. 각 이정표는 완료 기준이 검사 가능해야 하고, 끝나면 「구현 완료」로 옮긴다. 기간은 적지 않는다 — 혼자 하는 일이라 순서가 기간보다 중요하고, 순서는 바뀌지 않는다.

| 이정표 | 이름 | 무엇을 | 끝났다는 기준 |
|---|---|---|---|
| **M0** | 정한다 | 0단계 결정 다섯. `LICENSE` 파일과 README 를 맞춘다. 원자적 쓰기·휴지통(기둥 D 첫 항목)은 결정을 기다리지 않고 **지금** 한다 — 며칠짜리이고 오늘 데이터를 지킨다 **(원자적 쓰기·이력·휴지통 완료 2026-09-22 · 결정 다섯 계획)** | 결정 다섯이 「결정 기록」에 한 항목씩. 서버가 반쪽 파일을 남기지 않는다 |
| **M1** | 손에 맞는다 | 기둥 B 전부 + 기둥 A 의 토큰·아이콘·안내 문장 + 기둥 C 의 명령 등록부·용어집·상태줄. ⑤ 졸업. 추천 기능 4(`?` 정리함) | 기둥 A·B·C 의 「끝났다고 말할 수 있을 때」. 다섯 명 손 검증 |
| **M2** | 잃지 않는다 | 기둥 D 나머지(자동 저장·초안 칸·스키마 v2·필드 등록표·알림·IndexedDB·시험 두 단). 추천 기능 5 의 아래층(안전망 판본) | 기둥 D 의 기준. 「다시 열면 달라진다」 부류가 자동 시험으로 막힘 |
| **M3** | 남에게 준다 | 기둥 E 전부 + 추천 기능 1(카운트 시트)·2(반복 연습기)·3(파트). 설치형 앱 첫 판 | 다섯 명 10분 검증. 학생이 앱 없이 한 장을 받는다. 첫 외부 사용자 |
| **M4** | 기록이 쌓인다 | 추천 기능 5 의 위층(이름 붙인 판본·연습 기록), 자세 분석 결과가 기록에 붙는 화면, 영어 UI | 「큰 그림」의 세 요구가 전부 충족 — 한 축·엔진 없이도·시간축 |

M1 이 가장 크고 M0 이 가장 급하다. M1 안의 순서는 **명령 등록부 → 포인터 통일 → 직접 조작 문법 → 토큰·아이콘** 이다 — 등록부가 없으면 IA 와 문자열과 문서 검사가 전부 다시 흔들리고, 포인터 통일 없이 제스처를 손보면 두 벌을 고치게 된다.

### 이 로드맵 안에서 하지 않을 것

- **프레임워크 도입.** 여전히 아니다. 저장소 하나와 갱신 기술자 하나로 충분하다는 결론은 이 감사에서도 흔들리지 않았다 — 문제는 구조가 아니라 표면과 문법이다.
- **"미래지향" 테마를 기본으로.** 상용 첫인상은 조용해야 한다. 발광은 분위기 테마의 것이다.
- **클라우드 동기화를 공유보다 먼저.** 공유 뷰(추천 1)가 쓰이는 것을 보고 정한다.
- **다인 실시간 편집.** 대상 사용자에 없다.
- **자세 분석·LLM 을 간판으로.** 결과가 저장·비교되기 전까지는 실험이다. 간판은 받아 적기 + 카운트 격자 + 마디 반복이다.
- **통계로 화면을 움직이는 것.** 「배운 것으로 화면을 움직이지 않는다」(2026-09-21)는 그대로다.

### 이 절을 이어 쓰는 법

- 항목의 상태는 세 가지다 — **계획**(적혀만 있음) · **진행**(브랜치가 있음) · **완료**(「구현 완료」로 옮김). 상태를 항목 끝에 괄호로 단다.
- 새 항목은 **어느 기둥의 어느 문장을 채우는지**를 한 줄로 적고 들어온다. 어느 문장도 채우지 않으면 여기 있을 자리가 아니다.
- 결정을 뒤집을 때는 지우지 않고 「결정 기록」에 뒤집은 항목을 하나 더 적는다 — 2026-09-22 의 반올림·내림 왕복이 그렇게 남아 있다.
- 잰 값 표는 이정표를 넘을 때마다 다시 잰다. 같은 명령으로 재야 비교가 된다(글자 크기·색·이모지·버튼 수·helper 수·단축키 수·미시험 줄 수·결함 건수).
- 다음에 다시 볼 날: **2026-10-05** 에 「정하기를 미룬 것」의 작업 차례 판정과 함께, M0 의 결정 다섯이 났는지 본다.

## 구현 완료

### 받아 적기 흐름과 데이터 안전망 (2026-09-23)

`capture-flow-and-safety`. 사용자 관점의 변화는 [개발 이력](HISTORY.md)에 있고, 여기에는 **로드맵이 걸었던 것**만 적는다.

- **[편집 흐름](EDITING_FLOWS.md) 1단계(받아 적기)가 손에 붙었다.** `▮ 끊기` 하나로 끝나고, 끊은 자리가 두 카운트 격자에 붙으며, 마이크로 이름을 말하면 그 구간에 붙는다. **2단계(나중에 이름 붙이기)는 아직** — 블록 팝업의 `✎ 동작 정하기` 로 하나씩 채우는 것까지이고, `?` 블록만 모아 놓는 화면은 「상용화까지」의 추천 기능 4번이다.
- **「기둥 D — 견고함과 데이터」의 「잃지 않는다」가 닫혔다** — 원자적 쓰기 · 직전 판 이력 · 휴지통 · 이름 붙은 파일 자동 저장 · 미래 스키마 거절 · 두 탭 충돌 감지. 남은 것은 필드 등록표 · 알림 세 급 · IndexedDB 이전 · 지원 매트릭스 · ui/input 시험 · `check-principles` 다.
- **백로그 1(연습 버전)의 밑절반이 앞당겨졌다.** 「안전망 판본」(저장마다 직전 판)은 섰고, 사람이 이름 붙이는 판본과 연습 기록은 그대로 남아 있다(M4).
- **백로그 4의 마찰 하나가 남은 채다** — 「동작을 한 번 옮길 때마다 보드 전체를 다시 그린다」. 규모를 재는 일이 「기둥 D」에 있다.

### 설정 갈래와 검색 (2026-09-19)

설정이 넷을 넘어가면서 한 줄로 이어 놓은 화면이 읽히지 않게 됐다. 갈래(`전체` · `보관 자리` · `모델`)로 묶고, 갈래를 몰라도 닿도록 검색을 붙였다.

- 갈래 목록의 주인은 `CATEGORIES` 하나이고 절은 `data-cat` 으로 자기 갈래를 밝힌다 — 설정 하나를 더하는 일이 `<section data-cat="…">` 한 줄로 끝난다.
- 검색은 절의 글자와 `data-keywords` 를 함께 훑는다. 지금 값(경로·모델 이름)도 글자라 함께 걸린다.

이번에 내린 설계 결정:

- **절의 `hidden` 을 정하는 자리를 하나로 모았다(`applyFilter`).** 전에는 렌더 함수가 `section.hidden` 에 직접 대입했는데, 거기에 갈래·검색이 겹치면 **마지막에 쓴 쪽이 이긴다.** 이제 "지금 쓸 수 있는가(`data-available`)"와 "갈래·검색에 걸리는가"가 곱해져 한 곳에서 정해진다. 보임 여부를 결정하는 축이 둘 이상이면 축마다 대입하지 말고 곱하는 함수를 하나 둔다.
- **검색은 갈래를 가리지 않는다.** 고른 갈래 안에서만 찾으면 "여기 없네" 가 "이 앱에 없네" 로 읽힌다. 대신 검색 중에는 옆단의 `전체` 가 켜진 것으로 보이고 갈래마다 걸린 개수가 붙는다.

### 영상 패널 (2026-09-09)

안무표 옆에 영상이 뜨고, 재생 위치가 안무표 위의 초록 세로선으로 선다. **켜야 보이는 기능**이라 켜지 않은 화면은 이 기능이 들어오기 전과 같다.

- 이미 있는 `YouTube URL 입력...` 칸이 그대로 소스다. 새 입력창을 만들지 않았다.
- **(2026-09-09 추가)** `📁 영상 파일 열기` 로 내 컴퓨터의 영상 파일도 띄운다. 파일이 유튜브보다 우선하고 `✕ 파일 놓기` 로 돌아간다. 저장 파일에는 파일명만 남아, 다시 열면 같은 파일을 다시 고르라고 안내한다.
- **(2026-09-09 추가)** **영상 보관.** 로컬 서버 `server.py`(파이썬 표준 라이브러리만)가 고른 영상을 `video-clip/<프로젝트>/<파일>` 로 보관하고 Range 로 스트리밍한다. 프로젝트 파일에는 상대 경로만 남아 다시 열면 자동으로 돌아온다. 서버가 없으면(정적 호스팅) `⚙ 설정` 의 `폴더 지정` 으로 브라우저가 직접 복사하는 방식(File System Access API, 크롬·엣지)으로 떨어진다. 보관 위치는 `--root`/`--subdir` 또는 설정에서 바꾼다.

- 재생 위치는 도메인 상태에 들어가지 않는다 — `Undo` 에 남지 않고 안무표를 다시 그리지도 않는다([아키텍처](ARCHITECTURE.md#휘발성-렌더-채널-재생-헤드는-dirty-를-타지-않는다)의 채널 B).
- 데스크톱은 안무표 오른쪽, 1040px 이하에서는 안무표 위. **DOM 은 움직이지 않고 CSS 만 바꾸므로** 창을 좁혀도 재생이 끊기지 않는다.
- `전체 초기화(링크 포함)` 이 영상 소스와 템포도 함께 지운다. 링크를 비우면서 영상만 남으면 링크바와 패널이 갈라지기 때문이다 — `Undo` 한 번이면 배치·링크와 함께 돌아온다.

이번 묶음에서 내린 설계 결정(다음에 같은 자리에서 재사용한다):

- **"지금 어느 블록인가"는 상태가 아니라 관측값이다.** 재생 위치의 함수이므로 store 에 넣지 않고 재생 헤드와 같은 휘발성 채널이 클래스만 토글한다. 다만 헤드가 같은 칸에 멈춘 채 블록이 다시 그려지는 경우가 있어, 렌더러가 "네 캐시가 낡았다"고만 알리는 `invalidate` 훅을 둔다.
- **동작마다 시각을 저장하지 않고 템포 지도를 둔다.** 배치별 시각은 격자 좌표와 시간이 두 진실이 되어 배치를 옮기면 어긋난다. 대신 앵커를 점 하나로 보고 보정점을 더해 구간별 선형으로 잇는다 — 카운트↔초 변환이 한 곳(`domain/tempo.js`)에 있어 헤드·점프·하이라이트가 전부 자동으로 따라온다. 보정점이 없으면 옛 선형식과 한 자리도 다르지 않다(테스트가 등호로 단언).
- **파일 소스는 파일명 + 보관 루트 기준 상대 경로만 저장한다.** blob URL 도 절대 경로도 파일에 넣지 않는다. 경로 모양(`<subdir>/<프로젝트>/<파일>`)을 서버 방식과 브라우저 폴더 방식이 똑같이 쓰므로 프로젝트 파일이 어느 쪽에서도 열린다.
- **LLM 은 서버가 부르고, 답은 스키마로 받아 두 번 검증한다.** 브라우저에 키를 둘 수 없고 로컬 LLM 은 CORS 에 막히므로 중계는 서버 몫이다. 모델에게는 구조화 출력(JSON 스키마)을 요구하고, 그래도 서버가 한 번(숫자·이름), 도메인이 또 한 번(격자 클램프·이름 매칭) 검증한다 — 모델의 답은 입력이지 명령이 아니다. "다듬기"를 한 단 따로 둔 이유는 음성 인식 오류와 줄임말을 사람이 고칠 자리를 만들기 위해서다.
- **서버는 파이썬 표준 라이브러리로만 만든다.** 로드맵이 서버를 미룬 이유가 pip 환경과 두 번째 런타임의 비용이었으므로, 그중 앞의 것은 내지 않는다. 서버와 앱 사이는 HTTP 뿐이고, 서버가 없으면 앱이 스스로 브라우저 방식으로 떨어진다 — 정적 호스팅이 여전히 유효하다.

### 적응형 작업 차례 — 2026-10-05 에 다시 본다

**질문.** 어떤 버튼 다음에 어떤 버튼을 눌렀는지 세어 두면, 그것으로 다음에 누를 것을 짚어 주거나
작업 차례 자체를 사람마다 다르게 구성할 수 있을까.

**지금 상태(2026-09-21).** 세는 것은 **이미 들어갔다**([기능 설명서](FEATURES.md)의 `⚙ 설정 → 작업 차례`).
단계 버튼 여섯과 조작 줄 다섯이 한 표에 들어가고, 같은 출발점에서 5번 넘게 갔으며 1등이 절반을
넘을 때만 단계 줄에 점선 `다음` 표식이 하나 붙는다. **그 표로 화면이 움직이지는 않는다.**

**미룬 까닭.** 표본이 모자라서다. 걸러 내고 나면 남는 것이 거의 없다 —

| | 한 세션에서 | 표에 들어가는 수 |
|---|---|---|
| `끊기` 연타 | 200번쯤 | 0번 (같은 버튼 연속은 세지 않는다) |
| `① → ② → ③` | 1번 | 1번 |

그래서 `다음` 표식 하나가 뜨려면 **프로젝트를 다섯 개쯤** 해야 한다. 그동안 그 길이 `①→②→③`
이라는 것은 이미 알고 있고 화살표로 박아 두었다 — 통계로 배워 봐야 같은 답이다. 값이 있는 것은
**벗어나는 길**(예: "② 다음에 늘 ⑤ 마커부터")뿐이고, 그것이 있는지 없는지는 세어 봐야 안다.

**무엇을 보고 정하나.** 2026-10-05 에 `⚙ 설정 → 작업 차례` 의 표를 연다.

- 예상 밖의 길이 **다섯 번 넘게** 굵게 나왔다 → 그 길을 **화살표 줄에 고정으로** 넣는다(런타임에
  화면이 바뀌는 것이 아니라, 다음 판의 설계가 데이터를 반영하는 방식이다).
- 표가 `①→②→③` 만 되풀이한다 → 배울 것이 없다는 뜻이다. **기록을 끈다**(키와 도메인 모듈은
  지우고, 설정의 절도 뺀다).
- 표가 거의 비어 있다 → 더 모은다. 날짜를 한 번 더 미루되, 두 번째 연장은 없다.

**만들지 않기로 한 것.** 통계로 버튼의 **자리·순서를 바꾸는 것**. 손이 기억하는 과녁이 움직이면
그것은 적응이 아니라 과녁이 흔들리는 것이다 — 2026-09-21 에 고친 더블클릭 버그가 정확히 그 부류였다
([개발 원칙](PRINCIPLES.md)). 이 선은 위 결과와 무관하게 유지한다.

## 백로그

순서는 의존 관계로 정했다. 위에서부터 하나씩 한다. **2026-09-22 부터 순서의 주인은 위 「상용화까지 — 퓨처 워크 로드맵」이다** — 아래 네 항목은 그 이정표 안에 자리를 갖는다(1 → M2·M4, 2 → 백로그 유지, 3 → M4, 4 → M1·M3). 여기는 각 항목의 세부와 대기 조건을 적어 둔 곳으로 남긴다.

### 1. 연습 버전 (다음 작업)

같은 안무의 여러 판본과, 연습할 때마다 남기는 기록을 저장한다.

- "얼마나 나아졌는지"는 자동으로 계산되는 것(버전 사이의 안무 차이)과 사람이 남기는 것(속도, 성공 여부, 메모)으로 나뉜다.

**대기 조건**: 아래 미결정 사항의 "버전마다 다른 영상을 쓰는가"가 정해져야 저장 포맷을 확정할 수 있다.

### 2. 영상을 잘라 내보내기 (옛 "시퀀스 엔진 이식")

안무표에서 고른 구간을 영상 파일로 잘라 낸다. 원래 "서버가 필요해질 수 있는 유일한 자리"였는데, 2026-09-09 에 영상 보관을 위해 `server.py`(표준 라이브러리만)가 먼저 생겼다. 자르기를 붙인다면 그 서버에 ffmpeg 호출을 얹는 것이 자연스럽다 — 다만 그 순간부터 ffmpeg 설치가 전제가 된다.

**2026-09-10 에 절반이 됐다.** 영상 패널의 `구간 자르기` 가 In/Out 으로 잡은 구간을 `POST /api/clips/trim` 으로 보내면 서버가 ffmpeg 으로 다시 인코딩한 MP4 를 보관 폴더에 만들고 앱이 그 파일로 갈아 끼운다(템포·마커의 시각도 함께 당긴다). ffmpeg 은 **선택 의존성**으로 두었다 — 없으면 이 버튼만 꺼진다(`/api/health` 의 `ffmpeg`). 그리고 영상 구간 ↔ 안무표 구간 **마커**(`media.markers`, `domain/markers.js`)가 생겨 "이 영상 토막이 이 마디"를 기록하고 박자에 반영할 수 있다. 남은 절반은 반대 방향 — **안무표에서 고른 구간**(마디·블록)을 템포로 초 구간으로 바꿔 잘라 내보내는 것 — 인데, 마커의 카운트 구간과 `domain/tempo.placementToSpan` 이 이미 그 재료다.

원래 이 항목은 "영상 시퀀스를 편집하는 엔진을 다른 프로젝트에서 통째로 들고 온다"였다. 2026-09-09에 그 프로젝트(`LLM-Movie-Maker`)를 실제로 열어 보고 전제가 틀렸음을 확인했으므로, 조사 결과를 남겨 다음에 이 결정을 다시 할 때 처음부터 뒤지지 않게 한다.

#### 확인한 사실

`LLM-Movie-Maker`는 **Python + FastAPI 서버**다(`.py` 94개). 영상 처리의 실체는 `ffmpeg`을 자식 프로세스로 띄우는 코드이고, 하는 일도 다르다 — 프롬프트로 클립을 만들어 마지막 프레임으로 체이닝해 붙이는 **생성** 도구다. 브라우저에는 프로세스도 파일시스템도 없으므로 **그대로 옮겨 심을 수 없다.**

다만 서버를 두기로 한다면 재사용성은 좋다.

| 가져올 것 | 재사용성 | 근거 |
|---|---|---|
| `app/media.py` (297줄) | **그대로** | 프로젝트 import가 0개다. `asyncio`·`subprocess`·`pathlib`뿐이라 job·clip·DB 개념을 모른다 |
| `ports.py`의 `Media`/`AsyncMedia` | **그대로** | 이미 포트 뒤에 있다. 이 앱의 `SequenceEnginePort`와 같은 모양 |
| `domain/timing.py` | 개념만 | `TimeGrid`·`Snap` — "고른 값과 실제로 만들어질 값을 함께 든다". [포트 계약](PORTS.md)의 `Tempo`가 같은 문제를 안고 있다 |
| `app/video.py` | 안 됨 | 외부 생성 모델 서버 호출. 안무와 무관 |
| `app/pipeline.py` | 안 됨 | 클립 생성 잡 오케스트레이션 |

두 가지를 함께 적어 둔다. **첫째, 정작 필요한 자르기 함수가 없다** — 있는 것은 `extract_frame_at`·`concat_clips`·`mux_tracks`·`encode_clips`로 전부 만들어 붙이는 쪽이고 `trim`/`subclip`은 없다. 다만 `-accurate_seek -ss` 패턴이 이미 있어 함수 하나를 같은 자리에 더하는 정도다. **둘째, 값의 대부분이 코드가 아니라 주석에 박힌 하드윈 지식이다** — "끝을 넘겨 찍으면 ffmpeg은 빈 파일을 남기는 게 아니라 오류로 죽는다" 같은 것들이 297줄보다 값지다.

#### 그래서 무엇을 하나

**"재사용할 수 있다"가 "서버로 바꿀 이유"는 아니다.** 가져올 수 있는 것은 ffmpeg 래퍼 297줄인데 서버를 도입하며 치르는 값이 훨씬 크다 — 클론해서 정적 서버 하나면 끝나던 것이 Python 환경 + ffmpeg 설치 + 프로세스 관리가 되고, `tools/check-arch.mjs`가 지키는 계층 규칙 바깥에 두 번째 런타임이 생긴다.

순서를 이렇게 잡는다.

1. ~~**영상 패널을 먼저 만든다.**~~ 2026-09-09 에 됐다(위 `구현 완료`). 서버 없이 됐고, 이제 그다음 무엇이 아쉬운지를 실제로 써 보고 판단할 수 있다.
2. 아쉬운 것이 **구간 반복·속도 조절**이면 브라우저만으로 된다(`playbackRate`, `currentTime` 루프). 서버 불필요.
3. 아쉬운 것이 **잘라서 파일로 내보내기**면 그때 비로소 갈림길이다 — `WebCodecs`로 브라우저에서 갈지, `media.py`를 가져와 서버로 갈지.

**대기 조건**: 3단계에 실제로 도달할 것. 지금은 아직 없는 문제다.

### 3. 영상에서 관절 가동 범위 재기 (계산부는 있고 모델이 없다)

영상 속 사람의 관절 각도를 재서 동작마다 **가동 범위**(가장 많이 굽힌 각 ~ 가장 많이 편 각)를 남긴다. 목적은
자세 교정이 아니라 **기록**이다 — 같은 동작의 지난 테이크와 오늘 테이크를 견줘 "무릎이 20° 더 열렸다" 를
말할 수 있으면, 위 1번의 연습 기록이 사람이 적는 별점 말고 잰 값 하나를 더 갖게 된다.

**2026-09-11 기준으로 계산·모델·추정기까지 서 있고, 안무표에 붙는 화면만 없다.**

| 파일 | 하는 일 |
|---|---|
| `src/ports/pose.js` | 자세 추정기 계약. 배치 분석(`analyze`)이고 던지지 않는다. **모델의 점 인덱스를 경계 밖으로 내보내지 않는다** — 어댑터가 `leftElbow` 같은 이름으로 옮겨 넣으므로 모델을 갈아 끼워도 아래 계산이 안 바뀐다 |
| `src/domain/pose.js` | 점 → 관절 각도 10개 + 상체 기울기. 각도는 **관절 안쪽 각(180° = 곧게 편 상태)** 으로 규약을 한 번만 정한다 |
| `src/domain/poseTracks.js` | 누가 누구인지 잇는다. 한 사람이면 자동, 여럿이면 앵커를 찍고, 스쳐 지나 헷갈린 구간은 `ambiguous` 로 드러낸다 |
| `src/domain/rom.js` | 구간·카운트별 가동 범위 요약, 좌우 대칭, 테이크 사이 비교. 못 본 프레임을 분모에 남겨 `coverage` 로 알린다 |

| `server.py` + `src/adapters/modelServer.js` | 모델을 어디에 받아 둘지(`⚙ 설정` 의 `자세 분석 모델`)와 받기 |

| `tests/pose-check.html` + `tools/make-pose-clip.py` | 관절 위치를 미리 정해서 그린 합성 영상으로 분석이 맞는지 보는 검사 페이지. world 좌표를 돌려 보는 **3D 보기**도 여기 있다 |

**2026-09-11 에 실물로 확인한 것.**

- 정답을 아는 합성 영상에서 **넣은 가동 범위와 잰 가동 범위가 소수점까지 같다**(왼 팔꿈치 110.0°, 왼 무릎 55.0°,
  오른쪽 둘은 0.0°). 한 사람짜리라 앵커 없이 궤적이 저절로 섰다.
- 실제 사람 사진에서는 관절 15개가 신뢰도 0.96 이상으로 잡히고 미터 좌표(world)로 들어온다.
- **합성 뼈대는 MediaPipe 가 사람으로 보지 않는다**(0명). 실제 사람으로 학습된 모델이라 선 그림에는 아무도 없다고
  답한다 — 그래서 합성 영상은 "우리 계산이 맞는가" 만 보고, "모델이 도는가" 는 실제 사진으로 따로 본다.
- 속도는 480x640 기준 초당 50장 안팎이었다(full 모델, 브라우저).

**⚠ 이 검사가 잡은 결함 — 정규 좌표는 각도를 일그러뜨린다.** 화면 좌표는 가로를 폭으로 세로를 높이로 나눈 값이라
480x640 영상에서 가로가 0.75배로 눌려 있다. 그 좌표로 각을 재면 넣은 110.0° 가 **93.9°** 로 나왔다. 프레임마다
`aspect`(폭/높이)를 좌표와 함께 실어 보내고 각을 잴 때 되돌리는 것으로 고쳤다(`ports/pose.js` 경계 ②-a,
`domain/pose.spaceOf`). world 좌표에는 해당하지 않는다 — 이미 미터라서 눌린 축이 없다. 되돌린 좌표는 각도
계산에만 쓰고 오버레이·클릭 판정은 원래 좌표를 그대로 쓴다(안 그러면 화면 위치와 어긋난다).

**⚠ y 축 규약은 재야 한다(2026-09-12).** MediaPipe 는 화면 좌표도 world 좌표도 y 가 **아래로** 자란다
(실측: 코 -0.578, 발목 +0.447). 캔버스도 아래로 자라므로 그대로 그리면 맞는데, 처음에 뒤집도록 두어 사람이
물구나무로 그려졌다. 단위 테스트가 "코가 발목보다 위에 그려진다" 를 못박고 있다.

**⚠ 3D 는 정면만 믿을 수 있다(2026-09-12).** world 좌표를 세로축 둘레로 돌려 보면 0° 에서는 영상의 자세와 맞지만,
75° 쯤 돌리면 앞뒤로 벌린 다리가 거의 겹쳐 보인다 — 카메라 한 대에서 뽑은 깊이라 정보가 얇기 때문이다
(실제 사진에서 깊이 폭이 0.244m 에 그쳤다). "몸이 어느 쪽을 보는가" 정도는 읽히지만 옆모습의 각도는 못 믿는다.
각도·가동 범위를 world 로 재는 것은 그대로 유효하다 — 그건 관절 사이의 상대 위치라 절대 깊이만큼 민감하지 않다.

**메시는 2026-09-12 에 만들었다 — 다만 "평균 몸을 관절에 맞춰 늘린 것" 이다.** `domain/bodyMesh.js` 가 뼈마다 통을
씌우고 몸통을 어깨선~허리~엉덩이선으로 잇고 머리를 얹어 꼭짓점 232개·면 124개짜리 몸을 만들고,
`ui/meshView.js` 가 먼 면부터 칠해 가림을 푼다. 의존성은 하나도 늘지 않았다. 영상 위에 겹치기(화면 좌표)와
따로 떼어 돌려 보기(world 좌표)가 둘 다 된다.

⚠ **이것은 SMPL 같은 몸매 복원이 아니다.** 자세는 맞지만 몸집은 `RADII` 표의 평균값이라 그 사람의 체형·옷이
반영되지 않고 실루엣에 딱 달라붙지 않는다. 진짜 메시를 얻으려면 HMR 계열 모델(PyTorch·GPU)을 서버에 올려야 해서
"표준 라이브러리만" 이 깨진다 — 그 선택지는 남겨 두되 지금은 닫아 두었다. MediaPipe 는 점 33개만 내주고 GHUM
메시는 학습에만 쓰여 밖으로 나오지 않는다.

**2026-09-12 에 앱에 붙었다.** 영상 패널의 `자세 분석` 구획(`ui/poseView.js`)에서 돌리고, 영상 위 오버레이
(`ui/poseOverlay.js`, 채널 B)가 관절·메시를 겹쳐 그리며, 영상 위를 눌러 인물을 고른다. 상태는
`usecases/poseCommands.js` 가 `session.pose` 에 요약만 둔다 — 관절점은 `app/main.js` 의 모듈 변수다.

**남은 것은 하나다.** 결과를 어디에 남길지 — 마커·테이크(위 1번)와 붙는다. 지금 분석 결과는 **저장되지 않고**
영상을 바꾸면 사라진다. 원본 landmark 는 프로젝트 파일에 넣기에 너무 크므로 클립 옆 사이드카 파일로 두고,
요약(카운트별 각도·가동 범위)만 프로젝트에 싣는 쪽이 자연스럽다. 그것이 붙으면 위 1번의 "이 동작이 지난주보다
20도 더 열렸다" 가 완성된다.

⚠ 분석은 **영상 파일에만** 된다. 유튜브는 iframe 안에서 재생되어 픽셀을 읽을 수 없다 — 잘라내기와 같은 조건이다.

### 4. 안무 작성을 더 쉽게

**2026-09-12 에 구체화했다.** 이 도구로 안무표를 채우는 길 스무 가지를 전부 적고, 그중 무엇이 막혀 있는지와 어떻게 열지를 [편집 흐름](EDITING_FLOWS.md)에 따로 두었다. 요지는 하나다 — 영상을 보며 적을 때 **사람은 이름을 맨 나중에 붙이는데 도구는 맨 처음에 요구한다.** 블록을 놓는 유일한 길이 동작 목록의 항목을 가리키기 때문이다.

막힌 곳은 다섯이었다. ① 재생 위치에서 바로 블록을 놓을 수 없다 ② 이름 없이 자리를 잡을 수 없다 ③ 마커가 블록이 되지 않는다 ④ 마디 위의 묶음(파트)이 없다 ⑤ 잰 가동 범위가 화면에 안 나온다. **①②③ 은 2026-09-12 에 열렸다**(받아 적기 — 영상 패널의 `③` 단계와 단축키 `B`).

네 단계로 연다. ①받아 적기 → ②나중에 이름 붙이기 → ③파트 → ④기록과 비교.

**1단계는 끝났다(2026-09-12).** 막혀 있던 시나리오 셋(강습 영상 받아 적기, 공연에서 대목 뽑기, 내 촬영본 받아 적기)이 열렸다. 다음은 **2단계 — 나중에 이름 붙이기**다: 이름 없는 블록만 모아 한 화면에서 채우고, 되풀이되는 것을 "아까 그것"으로 묶고, 그때 동작 목록·카테고리에 등록한다. 지금은 고른 블록에 한 번에 한 이름을 붙이는 것까지만 된다.

아래는 그와 별개로 확인된 자잘한 마찰이다.

- 동작을 한 번 옮길 때마다 보드 전체를 다시 그린다.
- 루틴 색을 고를 수 없다. 여덟 색이 만든 순서대로 자동 배정되고 그 순번이 저장되지도 않아, 파일을 다시 열면 다른 루틴이 같은 색을 쓸 수 있다.
- `전체 초기화(링크 포함)` 이나 `전체 불러오기` 뒤에 선택 표시가 남아 `루틴으로 편성 (N)` 버튼이 계속 떠 있다. 눌러도 가리키는 배치가 없어 아무 일도 일어나지 않는다.
- 메인 `Undo` 직후에 무엇이든 하면 되돌리기 단계가 하나 더 쌓이고 다시 실행 대기열이 날아간다. 원인은 카테고리 정규화의 정렬이라 고치면 저장 파일의 키 순서가 달라진다.

링크 되돌리기와 리사이즈의 충돌 규칙은 여기서 빠졌다 — 둘 다 2026-09-07 에 닫혔고 위 `구현 완료` 에 있다. 대신 그 자리에 하나가 들어왔다: 복사만 층 재정렬을 부르지 않는 것이 이제 네 조작 중 유일한 예외가 되어 [다음에 고칠 후보](deviations.md#다음에-고칠-후보) 의 1번이다. 나머지 마찰의 전체 목록과 고칠 때 함께 해야 할 일은 [일부러 두고 온 것](deviations.md)에 있다.

## 결정 기록

### 마이크는 브라우저 것을 쓰고, 두 지연을 갈라 둔다 (2026-09-22)

"마이크를 써서 동작 이름을 대략적으로 정할 수 없을까? LLM 을 써도 될 것 같은데."

- **브라우저 내장(Web Speech)을 골랐다.** 녹음해 서버로 올려 Whisper 로 받아 적는 길과 재 보면,
  첫 글자 0.1~0.3초 대 없음, 확정 0.3~1초 대 1.5~3초다. 그런데 결정적인 것은 속도가 아니라
  **시각**이었다 — 말이 *끝난* 시각으로 구간을 고르면 그 사이 영상이 흘러 한 구간씩 밀린다.
  내장 API 는 **중간 결과가 처음 온 순간**을 말의 시작으로 쓸 수 있어 그게 풀리고, 덩어리로
  올리는 방식은 2초 덩어리 안 어디에서 말이 시작됐는지 알려주지 않아 짐작해야 한다.
  같은 날 격자로 고친 「한 칸 밀림」과 같은 부류의 버그를 새로 만들 까닭이 없다.
- **치르는 값을 적어 둔다.** 크롬은 음성을 **구글 서버로 보낸다**(끌 수 없다). 이 저장소가 LLM 키를
  서버에만 두고 VPN 주소로만 여는 것과 결이 다르므로, 화면이 켜기 전에 그 사실을 말한다.
  Whisper 길은 OpenAI 키를 따로 요구해서(Claude 에 음성 API 가 없다) 지금 제공자와도 어긋난다.
- **빠른 길과 느린 길을 갈랐다.** 말→글자만 실시간이면 된다. 글자→동작 목록은 규칙(`moveMatch`)이
  확신하면 즉시·공짜고, 아니면 **들은 대로 붙여 놓고** LLM 에 모아서 묻는다. 이름이 곧장 보이므로
  받아 적기가 LLM 을 기다리지 않고, 서버가 없어도 기능 자체는 산다.
- **규칙이 모르는 것을 억지로 맞추지 않는다.** 「쇼티조지」 안에 「조지」가 있다고 `조지` 로 붙이면
  LLM 이 `Shorty George` 로 고칠 기회를 뺏는다. 그래서 품기 보너스를 길이 비율에 강하게 묶고,
  확신이 안 서면 **모른다고 한다.** 틀린 이름은 영상을 다시 보기 전까지 들키지 않는다.
- **기계가 사람을 덮지 않는다.** LLM 이 고쳐 끼울 때 사람이 이미 손댄 블록은 건드리지 않고,
  `sure: false` 로 온 답은 버린다. 1초 뒤에 내 수정이 덮이면 그건 기능이 아니라 고장이다.
- **`domain/choreoPlan.matchMove` 와 합치지 않았다.** 그쪽은 LLM 이 이미 깔끔히 내놓은 이름을 잇는
  일이라 너그러워도 되고, 이쪽은 사람이 방금 입으로 낸 말이라 보수적이어야 한다. 한 함수로 합치면
  둘 중 하나는 반드시 틀린다.

### 안무의 박 단위를 변환이 알게 했다 — 두 카운트 격자 (2026-09-22)

같은 날 반올림으로 되돌린 직후(아래 항목) 사용자 보고가 하나 더 왔다: "뒤로 가니까 박자가 밀려서
첫 박을 침범한다. **모든 동작이 다 짝수박에 나온다, 절대 홀수박에 나올 리는 없다.** 홀수박으로
밀리는 것 같으면 가장 가까운 짝수박으로 밀어서 구간을 표시해 달라."

- **도메인 지식을 변환에 넣는 것과 상수 보정을 박는 것은 다르다.** 「두 카운트 단위로만 시작한다」는
  이 안무의 **규칙**이지 이 사람의 **버릇**이 아니다. 규칙은 변환이 알아도 되고, 알면 한 카운트
  어긋난 결과를 아예 만들지 않는다. 반면 "늘 0.3칸 늦다"는 버릇이라 변환에 넣으면 안 된다
  (제때 누른 표까지 당겨진다) — 그쪽은 여전히 `표 전체 옮기기` 다. 이 선은 2026-09-20 에 그었고
  지금도 그대로다.
- **격자의 위상은 카운트 0 에 맞춘다.** `② 박자 맞추기` 가 정한 기준 박자가 거기이므로, 그것이
  사용자가 "첫 박" 이라고 부르는 자리다. 격자를 따로 잡게 하면 정해야 할 것이 하나 더 는다.
- **격자를 키우면 놓을 수 없는 구간이 는다.** 두 경계가 같은 짝수 칸에 붙으면 아무것도 놓지 않는다
  — 두 카운트보다 짧은 동작이 없다는 전제가 이 값의 근거이자 대가다. `CAPTURE_GRID_COUNTS` 를
  1 로 두면 그전으로 돌아간다(6·3카운트 안무를 받는 날이 오면 그때 화면 스위치로 꺼낸다).
- **버린 거리를 줍는다.** 격자에 붙이면서 생기는 차이를 버리지 않고 모아 「손이 늦은 것인가,
  영상 속도가 다른 것인가」를 가린다(`domain/captureDrift.js`). 아래 항목이 그 이야기다.

### 속도가 달라진 것은 알리되 고치지는 않는다 (2026-09-22)

사용자가 먼저 "BPM 체크를 내부적으로" 하려다 스스로 접었다 — "예, BPM 체크는 할 수 없겠네.
속도가 바뀌었다는 부분을 인지할 수 있게 뭘 표시해 줄래?"

- **실은 잴 수 있다.** 경계가 두 카운트 격자에 놓인다는 전제가 생겼으므로, 격자에서 벗어난 거리가
  누를수록 한쪽으로 **커지는** 기울기가 곧 상대 템포 오차다(`bpm / (1 + 기울기)`). 그래서 추정값을
  같이 낸다 — 사람이 포기한 것을 도로 주워 온 셈이다.
- **그래도 고치지는 않는다.** BPM 을 저절로 바꾸면 **이미 놓인 블록이 통째로 어긋난다.** 받아 적는
  중에 그 일이 일어나면 사용자는 자기가 뭘 잘못 눌렀는지 알 길이 없다. 표시까지가 기계의 몫이고,
  바꿀지 말지는 `② 박자 맞추기` 에서 사람이 정한다.
- **두 가지를 갈라 말한다.** 치우침이 **고르면** 손(→ `표 전체 옮기기`), **커지면** 속도(→ BPM).
  둘을 뭉뚱그려 "안 맞습니다" 라고 하면 어느 버튼을 눌러야 할지 알 수 없다.
- **모자라면 침묵한다.** 표본 넷 미만, 카운트 축에서 4카운트도 안 벌어진 표본, 직선에서 0.35카운트
  넘게 흩어진 판에서는 아무 말도 하지 않는다 — 경계 하나가 엉뚱한 칸에 붙으면 기울기가 거짓말을
  한다. 「표본이 모자라면 아무 말도 하지 않는다」는 하루 전 작업 차례 기록에서 정한 것과 같은 선이다.
- **자리는 오른쪽 위 하나다.** 기준 박자 배지가 평소엔 숫자만, 어긋나면 꼬리말을 단다. 꼬리말은
  줄의 흐름 밖에 띄워 **배지 크기가 변하지 않게** 했다 — 옆의 `Undo` 가 밀리면 손이 기억한 과녁이
  움직인다.

### 받아 적기의 경계는 가장 가까운 칸으로 (2026-09-22, 2026-09-20 결정을 뒤집음)

`▮ 끊기` 로 찍은 시각을 카운트로 바꾸는 규칙을 **내림에서 반올림으로 되돌렸다.** 사용자 요청이다 —
"일곱 번째 박자와 여덟 번째 박자 사이에서 끊으면 여덟 번째에서 시작한다".

- **한 규칙으로 두 치우침을 다 받을 수 없다.** 내림은 **늦게 누른 것**을 한 칸까지 흡수하지만
  **미리 누른 것**은 전혀 못 받는다(8박을 겨누고 0.3칸 일찍 누르면 칸 7 로 떨어진다). 반올림은
  양쪽을 반 칸씩 받는다. 2026-09-20 에 내림을 고른 근거는 "사람은 보고 나서 누른다"였는데,
  **박이 오는 것을 알고 미리 누르는 쪽**을 계산에 넣지 않았다.
- **바꾸면서 잃은 것을 적어 둔다.** 반 칸을 넘겨 늦게 누르면 이제 다음 칸으로 간다 — 내림이
  흡수하던 값이다. 이 사실을 `domain/tempo.js` 의 주석과 단위 시험에 **잃은 쪽까지** 박아 두었다
  (다음에 또 뒤집기 전에 읽으라고).
- **변환에 상수 보정을 박지 않는다는 선은 그대로다.** 치우침이 일정하면 `표 전체 옮기기 ← 1카운트`
  로 결과를 보고 민다. 보정을 박으면 제때 누른 표까지 함께 당겨진다.
- **두 번 뒤집혔으므로 셋째 번은 근거를 재고 한다.** 「어느 쪽으로 몇 칸 틀렸나」를 세지 않은 채
  느낌으로 또 뒤집지 않는다.

### 배운 것으로 화면을 움직이지 않는다 (2026-09-21)

작업 차례를 기록하기로 하면서 함께 정한 것이다. 기록은 하되 **그 기록이 바꿀 수 있는 것은 표식 하나**다.

- **버튼의 자리·순서·개수는 통계와 무관하다.** 바꿀 수 있는 것은 점선 `다음` 표식을 어디에 붙일지뿐이다.
  같은 날 고친 버그가 "첫 클릭에 라벨이 밀려 더블클릭이 안 되던 것"이었다 — 손이 기억하는 과녁이
  움직이면 누를 수 없다. 통계로 그것을 하면 같은 버그를 기능이라고 부르는 셈이다.
- **표본이 모자라면 아무 말도 하지 않는다.** 5번 미만이거나 1등이 절반을 넘지 못하면(3:3 포함) 침묵이다.
  반반에 `다음` 을 붙이면 절반은 언제나 틀린 안내다. 한 번 눌러 본 길을 "늘 하는 일"로 내세우면
  처음 한 실수가 그대로 굳는다.
- **배운 것은 사람이 읽을 수 있어야 한다.** `⚙ 설정 → 작업 차례` 에서 표를 그대로 보여 주고 지울 수
  있게 했다. 기계가 배운 것을 사람이 못 보면 믿을지 말지 정할 수 없고, 못 믿는 추천은 없느니만 못하다.
- **규칙이 알려진 영역에서는 규칙이 희소한 통계를 이긴다.** 띠에 들어설 때 여는 단계는 지금도
  통계가 아니라 규칙이 정한다(영상이 없으면 ①, 박자가 없으면 ②, 둘 다면 ③).

사람이 정해야 했던 것과, 왜 그렇게 정했는지. 잰 값이 있으면 함께 적는다.

### 실시간 분석을 만들며 정한 것 (2026-09-13)

**정한 것.** 만들면서 정하기로 했던 갈래 셋의 답이다.

- **GPU 가 막힌 기기** — 기능을 끄지 않는다. CPU 로 돌되 **안내 줄이 그 사실을 적는다**
  (`이 기기는 CPU 로 돌고 있어 끊깁니다`)와 함께 실측 fps 를 숫자로 낸다. 끊기는 것을 감추고
  "왜 이렇지" 를 사용자에게 떠넘기는 것이 가장 나쁘다.
- **되감기 비용** — 그대로 받는다. 되감으면 그 자리에서 다시 찾는다. 캐시를 두는 안은 버렸다 —
  캐시가 맞는지 확인하는 값이 다시 찾는 값(27ms)과 비슷하다.
- **구간 요약** — 예상대로 **미리 훑는 길이 그대로 필요하다.** 한 장으로는 가동 범위를 못 재고,
  여러 사람 추적도 구간이 있어야 이어 붙는다. 둘은 대체가 아니라 나란히 선다.

**만들며 새로 정한 것 둘.**

- **같은 그림을 두 번 보지 않는다.** `requestVideoFrameCallback` 이 있으면 그것이 새 프레임을
  정확히 알려 주고, 없으면 `currentTime` 이 움직였는지로 가른다. 한 장에 27~178ms 가 드는데
  브라우저가 새 프레임을 안 내놓았으면 그 값이 통째로 버려진다.
- **낡은 한 장은 0.6초 뒤 지운다.** 오버레이의 기존 허용 오차(0.2초)를 실시간에 그대로 쓰면
  CPU(178ms)에서 문턱에 걸려 가장 필요한 순간에 화면이 깜빡인다. 대신 묻는 시각으로 돌려주되,
  정말 낡았으면 아예 안 그린다 — **멈춘 뼈대가 영상 위에 얼어붙는 것이 더 나쁘다.**

**잰 값.** GPU 로 한 장 27~36ms(첫 장만 681ms — 몸 푸는 시간). 실제 수업 영상 프레임으로
`detectNow` 를 직접 걸어 확인했다.

### 쌓인 사본을 지우고, 다음은 실시간 분석 (2026-09-13)

**정한 것.** ① 보관 폴더의 사본 8개(0.5GB)를 **목록을 보이고 확인받은 뒤** 지웠다 — 755MB → 251MB.
각 묶음에서 번호 없는 원본을 남겼다. ② 다음 한 덩이는 **재생하며 실시간 분석** 그대로 간다
(폰에서 나온 새 후보 둘 — 링크 일원화 · 1단계 범위 — 보다 앞이다).

**왜 ①을 사람이 확인했나.** 지우는 것은 되돌릴 수 없고, 무엇이 진짜인지 파일 이름만으로는
기계가 못 정한다. 실제로 **판단 규칙이 두 번 틀렸다** — 사용자 파일 이름 자체가 ` (1)`, ` (2)` 로
끝나서 서버가 붙인 번호와 구분되지 않았다. 목록을 눈으로 보지 않았다면 원본을 지우고 사본을
남길 뻔했다.

**여기서 나온 코드 수정.** 같은 착각을 앱의 `findStoredClip` 도 할 수 있었다 — 사본 번호를 `\d+` 로
받고 있었는데, 서버가 붙이는 번호는 **2 부터**다. `(?:[2-9]|\d{2,})` 로 좁혔다. 그대로 뒀다면
`안무 (1).mp4` 를 `안무.mp4` 의 사본으로 보고 엉뚱한 파일을 재사용했을 것이다.

**남긴 것.** 링크 일원화(`choreo_links` 가 브라우저 전역에 하나뿐이라 프로젝트를 바꿔도 이전 안무의
주소가 남는다)와 1단계 범위는 백로그에 그대로 둔다.

### /admin 은 보관 위치만 갖고, 서버 앞에서만 열린다 (2026-09-13)

**정한 것.** 셋이다. ① 관리 화면이 소유하는 것은 **보관 위치 하나**다 — 모델 폴더·모델 크기·LLM 은
앱의 `⚙ 설정` 이 갖는다. ② `/admin` 과 `PUT /api/config` 는 **로컬호스트에서만** 받는다.
③ 배경 에이전트가 승인 없이 낸 `9a47d77`(저장 위치를 저장소 밖으로)은 **그대로 둔다.**

**왜.** ①은 주인을 하나로 만드는 일이다. 경계를 세우면서 모델·LLM 까지 관리 화면에 넣었더니 같은 값을
두 화면이 고치게 됐다 — 어느 쪽이 맞는지 아무도 모르는 상태가 된다. 갈라 보니 기준이 분명했다:
**「어느 디스크에 쌓을지」는 서버의 살림이고, 「어느 모델을 쓸지·어느 LLM 을 부를지」는 기기에서 골라도
탈이 없다.** ②는 ①의 귀결이다. 서버의 살림이라면 서버 앞에 앉은 사람이 정한다.

**치르는 값.** 폰에서는 보관 위치를 바꿀 수 없다 — 노트북 앞으로 가야 한다. 폰에서 쓰려고 `--host` 로
열어 둔 것과 부딪히지만, 폰이 하는 일(영상 올리기·안무표 저장·받아 적기)은 전부 그대로 열려 있다.
막힌 것은 **살림을 바꾸는 것** 하나다.

**⚠ 판정의 한계.** TCP 연결의 상대 주소만 본다 — `X-Forwarded-For` 같은 헤더는 누구나 지어낼 수 있어
보지 않는다. 그래서 **앞단에 프록시를 두면 전부 로컬로 보인다.** 이 도구는 프록시 뒤에 두는 물건이 아니다.

**버린 것.** 「토큰을 찍어 요구」(폰에서도 바꿀 수 있지만 서버를 다시 켤 때마다 바뀌고, 개인 도구에
비밀을 하나 더 만든다) · 「지금 그대로」(같은 망 아무 기기가 보관 위치를 바꿀 수 있다).

**③에 대하여.** 검사 넷이 통과하고 이 기계의 동작이 바뀌지 않는다(옛 자리에 데이터가 있으면 그 자리를
계속 쓴다). 새로 클론한 자리에서만 새 기본값이 발동한다. 되돌리는 값이 두는 값보다 컸다.
다만 **승인 없이 커밋한 것 자체는 다시 있어서는 안 된다** — 배경 작업에는 조사만 시킨다.

### 보관 위치는 서버가 정한다 — 관리 화면을 따로 세웠다 (2026-09-13)

**정한 것.** 영상·안무표를 어느 디스크에 쌓을지 정하는 권한을 **앱에서 서버로 옮겼다.** 서버가 자기 관리
화면(`/admin`)을 내고, 안무 편집기는 `GET /api/config` 로 **읽기만** 한다.

**왜.** 바로 전날 저장장치 고르개를 앱의 `⚙ 설정` 에 넣었는데, 그것이 클라이언트·서버 경계를 넘는다는
지적이 나왔다. 맞는 지적이다 — **보관 위치는 서버의 살림이지 클라이언트의 화면 설정이 아니다.** 앱이
정하게 두면 브라우저마다 다른 답을 들고 같은 서버를 서로 다르게 설정하게 된다(폰과 PC 가 같은 서버를
보면서 실제로 갈렸다). 설정이 브라우저에 남는 것도 같은 문제의 다른 얼굴이다.

**어떻게 갈랐나.** 서버의 살림(보관 루트·하위 폴더·모델 폴더·LLM)은 `/admin` 이 소유하고, 앱은 그 값을
읽어 「지금 여기에 쌓입니다」를 보여 준 뒤 `서버 설정 열기 ↗` 로 보낸다. 앱에 남은 설정은 **서버가 없을
때의 브라우저 폴더 방식**뿐이다 — 그건 정말로 그 브라우저의 것이다.

**치르는 값.** 화면이 둘로 늘었다. 그리고 `/admin` 은 **서버에 닿을 수 있으면 누구나 연다** — `--host` 로
바깥에 열어 둔 서버라면 그 점을 감안해야 한다. 지금은 개인 도구라 여기까지 두고, 인증이 필요해지는
시점은 서버를 집 밖으로 낼 때다.

**버린 것.** 「앱에서 계속 바꾸기」(경계를 넘는다) · 「서버 CLI 로만 정하기」(폰에서 바꿀 길이 없어진다 —
`--root` 를 치려면 노트북 앞으로 가야 한다).

**함께 고친 것.** `Config.replace()` 를 세워 필드를 나열해 다시 짓던 자리 다섯을 없앴다. 그중 하나가
실제로 값을 떨어뜨리고 있었다(모델 폴더를 바꾸면 안무표 하위 폴더가 기본값으로 돌아갔다).

### 저장장치는 서버가 목록으로 내려 주고, 같은 영상은 두 번 올리지 않는다 (2026-09-13)

**정한 것.** 둘이다. ① `⚙ 설정` 이 **서버에 붙어 있는 저장장치를 줄로 내려** 누르면 고르게 한다
(`GET /api/volumes`). ② 이름과 바이트 크기가 같은 파일이 이미 보관되어 있으면 **올리지 않고 그것을 쓴다.**

**왜.** 폰에서 쓰기 시작하면서 드러난 것들이다. 경로 칸 하나로는 `/Volumes/OWC-Envoy-Ultra-4TB` 를
손가락으로 쳐야 했고, 같은 영상을 열 때마다 새로 올려 실측으로 한 폴더의 **754MB 중 530MB 가 사본**이었다
(100MB 짜리가 3벌, 47MB 짜리가 6벌). 5G 로 다시 올리는 값까지 들었다.

**치르는 값.** 내용을 해시하지 않으므로 **이름도 크기도 같고 내용만 다른 영상이면 옛것을 쓴다.**
100MB 를 다 읽어 해시하는 값이 다시 올리는 값과 크게 다르지 않아 그렇게 했다 — 그런 파일은 이름을
바꿔서 열면 된다.

**버린 것.** 「올릴 때마다 물어보기」(영상을 열 때마다 한 번 더 눌러야 한다) · 「지금처럼 늘 새로 올리기」
(판본은 남지만 자리를 먹는다) · 「경로를 손으로 치는 지금 방식만 두기」(폰에서 사실상 불가능하다).

**아직 안 한 것.** 이미 쌓인 사본 530MB 는 지우지 않았다 — 되돌릴 수 없는 일이고, 어느 것이 진짜인지
사람이 봐야 한다. 새로 쌓이지만 않게 했다.

### 목록의 삭제가 보관 폴더의 파일까지 지운다 (2026-09-13)

**정한 것.** 최근 프로젝트 목록의 `삭제` 가 브라우저 목록뿐 아니라 **보관 폴더의 `.json` 파일도 지운다**
(`DELETE /api/projects?name=N`). 확인은 저장소 관례대로 `정말요?` 두 번 누르기 하나뿐이고, 휴지통은 없다.

**왜.** 보관 폴더가 목록의 주인이 된 순간 「목록에서만 지우기」가 거짓말이 됐다 — 지워도 새로고침하면
도로 나타난다. 목록이 폴더라면 삭제도 폴더에 닿아야 한다.

**치르는 값.** 되돌릴 수 없다. 실수로 지우면 내려받기 폴더의 사본이 마지막 보루다. 버튼에 손끝을
올리면 무엇이 지워지는지 알리는 것으로 그쳤다 — 라벨은 세 목록이 같아야 한다.

**버린 것.** 「폴더 모드에서는 삭제 버튼을 감춘다」(안전하지만 목록에서 치울 길이 앱 안에 없어진다) ·
「지금 그대로」(지운 것이 되살아난다). **영상 클립에는 삭제를 만들지 않았다** — 수십 MB 를 되돌릴 길
없이 날리는 버튼은 값이 다르다.

### 다음 한 덩이는 재생하며 실시간 분석 (2026-09-13)

**정한 것.** 다음 작업은 **재생하면서 그 프레임을 그 자리에서 분석하는 것**이다. 위의
「자세 분석은 재생하며 실시간으로 돈다」에서 정한 구조를 실제로 만든다.

**왜.** 문서 둘이 서로 다른 것을 「다음」으로 적어 두고 있었다 — [영상에서 안무표로](VIDEO_TO_CHART.md)는
1단계 범위를, 이 문서의 결정 기록은 자세 수치 화면을 가리켰다. 사람이 실시간 쪽을 골랐다. GPU 실측
36.6fps 로 문턱을 넘은 것이 근거다.

**남은 것(만들면서 정한다).** GPU 가 막힌 기기(5.6fps)에서 어떻게 물러설지 · 되감을 때 다시 분석하는
비용을 어디까지 감수할지 · 가동 범위와 가속도 **요약은 여전히 구간을 미리 훑어야 한다**(한 프레임으로는
범위를 못 잰다).

**미룬 것.** 1단계 범위(저장 포맷이 바뀌는 유일한 단계라 미룰수록 그 위에 지어진 것이 늘어난다) ·
자세 수치 화면 · 「놓치면 다 회색으로」.

### 한 프로젝트는 한 안무, 그 안에 영상이 날짜로 쌓인다 (2026-09-20)

「프로젝트」가 앱바의 이름칸 하나였다. 한 안무를 여러 번 찍은 영상이 쌓이는 것이 이 도구의 실제 쓰임인데, 화면 어디에도 그 줄이 없었다.

**숙련도를 따로 매기지 않기로 했다.** 날짜가 축이면 목록이 그대로 진행 순서가 되고, 올릴 때마다 사람이 정해 줘야 하는 칸이 하나 줄어든다. 별점이나 `기준본` 표시는 필요해지면 그때 붙인다 — 지금 넣으면 안 쓰는 칸이 하나 늘 뿐이다.

저장 포맷에서 지킨 것: 날짜는 `YYYY-MM-DD` 문자열 하나만 받고(`Date` 로 바꾸면 시간대가 끼어들어 "9월 12일에 찍은 것"이 브라우저마다 11일로 보인다), 안 적으면 파일에 키가 생기지 않으며, 자리는 `name` 바로 뒤다(키 순서가 곧 저장 바이트).

### 담는 것과 저장하는 것은 같은 모양이어야 한다 (2026-09-20)

작업 중인 문서를 자동으로 담기 시작하면서 **새 포맷을 만들지 않았다.** `프로젝트 저장` 과 같은 `buildProjectFile` 을 쓰고, 되살리는 길도 파일을 여는 길(`applyProjectData`)과 같다. 두 모양이 갈리면 한쪽만 고치는 날이 오고, 그날 복원이 조용히 어긋난다.

담는 자리(서버/브라우저)는 **게터로 정한다.** 서버 여부는 probe 가 끝나야 정해지는데 값으로 받으면 서버가 있어도 영영 브라우저에 담긴다 — 실측으로 그랬다.

대신 새 함정이 하나 생겼다: 자동 생성물을 사람이 만든 것과 같은 폴더에 두면 목록에서 그것을 밀어낸다(→ [개발 원칙 D-13](PRINCIPLES.md#d-13)).

### 시선의 첫 자리는 「시작」에 내준다 (2026-09-20)

화면을 왼쪽에서 오른쪽, 위에서 아래로 훑었을 때 **자리마다 첫 번째 항목이 그 자리에서 제일 드문 일**이었다. 맨 윗줄의 첫 칸은 아무 일도 하지 않는 앱 이름과 빈 입력칸이었고, 사이드바의 첫 카드는 `솔로 동작 추가`(목록이 비어 있지 않은 한 가장 드문 일)였고, 안무표를 채우는 세 길의 입구는 서로 다른 세 자리에 흩어져 있었다. 자리를 나눈 모델 자체는 옳았는데(그건 그대로 두었다) **각 자리의 첫 항목이 틀렸다.**

그래서 셋을 옮겼다 — 시작하는 세 길을 사이드바 맨 위 한자리로, 맨 윗줄의 파일 조작 여섯 칸을 이름 하나와 `▾` 로, 사이드바 카드를 빈도 순으로. **새 기능은 하나도 만들지 않았다**: `어떻게 채울까` 의 세 버튼은 이미 있는 진입점과 같은 커맨드를 부른다. 길을 하나 더 만들면 고치려던 문제(입구가 흩어져 있다)가 그대로 돌아온다.

다음에 같은 판단을 할 때 쓸 수 있는 규칙 — **자리를 옮기기 전에 각 자리의 첫 항목이 그 자리에서 가장 잦은 일인지 먼저 센다.** 자리 모델이 틀린 경우보다 첫 항목이 틀린 경우가 훨씬 흔하고, 고치는 값도 훨씬 싸다.

### 되돌릴 수 없는 것은 메뉴 안으로 (2026-09-20)

`전체 초기화(링크 포함)` 가 맨 윗줄 오른쪽 끝, `✨ 말로 채우기` 바로 옆에 늘 떠 있었다. Fitts 를 근거로 "자주 쓰는 버튼 옆에 두지 않는다"까지는 지키고 있었지만, **아예 안 보이게 하는 편이 낫다**는 판단으로 한 걸음 더 갔다. 2단계 확인(`정말요?`)은 그대로 두었다 — 장치를 빼는 것이 아니라 거리를 더 두는 것이다.

### 자세 분석은 재생하며 실시간으로 돈다 (2026-09-13)

**정한 것.** 미리 분석해 두고 꺼내 쓰는 지금 구조 대신, **재생하면서 그 프레임을 그 자리에서 분석**한다.

**왜.** `delegate` 를 GPU 로 바꾸면서 속도가 실시간 문턱을 넘었다 — 실측(맥북, `pose_landmarker_full`,
1020x990, 두 사람) **CPU 178.3ms/프레임(5.6fps) → GPU 27.4ms(36.6fps)**, 6.5배. 어댑터 끝단은 26.9fps.
미리 분석하는 구조는 "분석 안 한 구간은 아무것도 안 보인다"와 "CG 가 초당 15번만 바뀐다"를 안고 가는데,
둘 다 사람이 영상을 훑는 동안 계속 걸리는 마찰이다.

**치르는 값.** 재생 내내 GPU 를 문다(발열·배터리). 되감으면 다시 분석한다. GPU 가 막힌 기기는
5.6fps 라 CG 가 끊긴다 — 그 기기에서 어떻게 물러설지는 만들면서 정한다.
**가동 범위·가속도 요약은 여전히 구간을 미리 훑어야 한다**(한 프레임으로는 범위를 못 잰다).

**버린 것.** 「지금대로 미리 분석」(기다림과 15fps 가 남는다) · 「둘 다 섞기」(코드가 두 갈래가 되고
어느 쪽으로 그렸는지를 화면이 말해야 한다 — 이번에 들이기엔 크다).

### 자세 수치를 화면에 낸다 (2026-09-13)

**왜.** `domain/rom.js` 와 `domain/kinematics.js` 는 계산이 되고 단위 테스트로 검증까지 됐는데

아니라 있는 것을 꺼내는 일이라 값이 가장 싸다. 표에는 「본 비율」(coverage)을 함께 낸다 — 낮으면

### 따라가던 사람을 놓치면 모두 회색으로 (2026-09-13)

**정한 것.** 오버레이가 초록(고른 사람)으로 칠하는 것은 **실제로 그 사람을 찾은 프레임뿐**이다.
놓친 프레임에서는 아무도 초록이 되지 않는다. 고른 사람이 애초에 없는 영상(한 명짜리)은 지금처럼 모두 초록.

**왜.** 지금은 「아무도 안 고름」과 「고른 사람을 놓침」이 같은 값(-1)이라 놓친 순간 온 방이 초록이 된다 —
「누구를 재고 있는가」가 거짓말이 되고, 다시 눌러 잡아야 한다는 신호도 사라진다. 실측으로 8초 구간에서

## 미결정 사항

시작하기 전에 답이 필요한 것들이다.

- ~~**intro 행(row 0)을 시간 축에 넣는가.**~~ **넣기로 했다(2026-09-09).** 좌표식이 intro 를 음수 카운트로 분기 없이 처리하고, 재생 헤드도 거기 그대로 선다.
- ~~**자세 모델을 어디에 두는가.**~~ **2026-09-11 에 정했다: 브라우저가 계산하고, 파일은 사용자가 설정에서
  정한 폴더에 받아 둔다.** `@mediapipe/tasks-vision@1.0.1` 의 `vision_bundle.mjs` 는 진짜 ES 모듈이라 번들러도
  npm 도 없이 브라우저가 그대로 읽고, `server.py` 는 파일을 받아 두고 `/models/<이름>` 으로 내주기만 한다 —
  **파이썬 패키지가 하나도 늘지 않는다.** 없으면 `/api/health` 의 `pose:false` 로 알리고 그 기능만 꺼지는
  ffmpeg 과 같은 모양이다. 기본 위치는 저장소 밖의 캐시 폴더이고(2026-09-13 이전에는 저장소의 `models/`) `⚙ 설정` 이나 `--models` 로 바꾼다.
  받는 양은 크기에 따라 17.2MB(lite) · 20.6MB(full) · 41.9MB(heavy)다. 버전은 못 박았다 — 모델이 조용히
  바뀌면 어제 잰 각도와 오늘 잰 각도를 나란히 놓을 수 없다.
- ~~**버전마다 영상이 다른가.**~~ **2026-09-12 에 절반이 정해졌다: 한 안무에 영상이 여러 개 달리고, 박자와 마커는 영상마다 따로 산다**(`media` 가 `{activeId, clips[]}` 가 됐다). 아직 **버전** 개념과는 잇지 않았다 — 지금은 "한 안무표에 테이크 여럿"이고, 안무표 자체의 판본(E1)은 여전히 파일을 나누는 수밖에 없다.
- **루틴 편집 보드에도 카운트 ↔ 시간을 적용하는가.** 루틴은 자체 격자라 별도 템포가 필요할 수 있고, "루틴은 시간 매핑 없음"으로 못 박는 편이 단순하다.
- ~~**로컬 영상 파일을 어디까지 지원하는가.**~~ 2026-09-09 에 두 단으로 정했다. 기본은 **파일명만** 남기고(`{kind:'file', name}`) 다시 열면 같은 파일을 다시 고르라고 안내한다. 설정에서 보관 폴더를 지정하면 File System Access API 로 그 폴더에 복사하고 상대 경로(`path`)까지 남긴다 — 핸들은 IndexedDB 에 두고, 크롬 계열에서만 된다.
- **엔진 상태를 프로젝트 파일에 넣는가.** 넣으면 프로젝트 JSON이 커지고 localStorage 용량을 때린다. 크기 상한을 두고 초과 시 어떻게 할지 정해야 한다.

## 하지 않기로 한 것

- **프레임워크 도입.** 상태 전파는 저장소 하나와 갱신 기술자 하나로 충분하다는 것이 이번 재구성의 결론이다.
